# 使用 DSH 插件的 Codex 订阅额度

> DSH 是独立、默认未连接的数据源。需要安装附带的 DSH companion 插件并明确选择实例、账户和会话。暂停是向所选运行会话发送一次协作式“暂停”消息，不是硬中断，也不会在重置后自动继续。不要将“已接收”理解成“已经停止”。

## 连接与启用

1. 保持 DSH 的 `dsh-codex-subscription` 插件启用。本次适配依据 3.2.3 的公开接口；不修改其 OAuth 登录或安装文件。
2. 从同一个 overlay 发布版本下载 `dsh-codex-usage-overlay-bridge-0.1.0.tgz`。在目标 DSH 的插件管理器添加这个本机 tarball，按界面提示重启。不要在正在工作的 DSH 会话中强行重启或修改活动 profile。
3. 打开 overlay 设置，在「来源设置」中选择 **DSH**。发现桥接实例后，核对地址、实例标识及可选标签，明确选择一个再连接；不会自动连接第一个实例。
4. 明确选择订阅账户，再刷新会话并勾选需要保护的普通会话。不会自动选账户或全选会话，不控制子代理。切换 DSH 中的当前账户后，重新核对 overlay 的账户选择。
5. 检查读数、采样时间和连接状态正确后，再开启“额度不足时暂停”。DSH 的 5 小时/每周阈值独立于本机 Codex，默认均为 **0%**，即任一窗口耗尽时触发。

桥启动后只监听随机的 `127.0.0.1` 端口。发现记录保存在 `%LOCALAPPDATA%\CodexUsageOverlay\dsh-bridges\`；其中包含桥专用配对密钥，**不要复制到聊天、截图、终端、提交或日志**。overlay 只在 native 内存中使用密钥，不把它传入前端或设置文件。Windows 目录与文件 ACL 必须限定为当前用户和 SYSTEM，否则桥拒绝发布。

每次 DSH 插件重启都会生成新实例和密钥，需要重新选择实例与账户/会话。overlay 重启后也需要重新连接，不会把保存的地址当成有效授权。断开只清理 overlay 绑定，不退出订阅账户。

## 确认读数来自哪里

- DSH 读数仅来自所选 DSH 实例的 `codex-subscription/usage/accounts`，不调用本机 Codex `account/rateLimits/read`，失败也不回退到本机 Codex。
- 原来的 Codex 与 Claude 来源保持不变。切换来源、DSH 实例或账户时，旧采样与待发动作被撤销，旧请求的迟到结果不能成为新来源读数。
- DSH 的用量、消耗速率、额度周期、读取历史按 **来源 + 实例 + 账户** 单独存储。设置、读数事件携带来源标识与 generation，前端拒绝不匹配的迟到读数。
- 插件 `usedPercent` 转换成剩余百分比，按照窗口时长识别 5 小时与每周窗口，不依赖字段 primary/secondary 的排列。缺失、不合理、过期或身份不一致的读数不能触发暂停。
- 只列出账户不代表该账户正在用于所选会话。必须同时满足选中账户等于插件当前活动账户、额度快照有效、会话仍运行、模型路由属于订阅插件，才提交。

## 暂停行为与边界

- 只向明确绑定且仍在运行的普通 DSH 会话发送固定文本 `Pause` / `暂停` / `暫停`，请求模式为 `steer`。没有绑定时不会发送，也不会广播到其他会话或本机 Codex。
- 每个实例/账户/会话/额度周期在本次 overlay 进程内最多尝试一次。发送前取消不会消耗次数；一旦进入传输，超时结果未知也不自动重试。切换来源或勾选目标不会清除此记录。新周期、显式重新配对或重启 overlay 会重新允许尝试。
- 暂停默认关闭；关闭开关、读取失败、取消刷新、切源或绑定改变会撤销尚未提交的动作。已经提交的消息仍可能被 DSH 接受或执行。
- DSH 的会话列表与发送不是原子事务；会话在查询后刚好完成仍存在竞态。账户前后复核也无法证明期间从未瞬间切换。普通 steer 可能唤醒刚完成的会话，所以不承诺硬停止或无竞态。
- DSH 不提供本版本可验证的停止回执，也不支持本功能的自动恢复。额度真正耗尽后模型可能无法再处理暂停文本。要在请求边界强制拒绝后续 LLM 请求，仍需另外适配 DSH Host 的请求钩子，本版本没有安装这种拦截器。

## 可选 Web 手工连接

如果另一套 DSH Web 提供带有 `?token=…` 的合法连接链接，可在高级入口粘贴到密码输入框。仅接受明确的 loopback HTTP/HTTPS 地址、严格的端口/路径/查询格式；native 交换认证 Cookie，凭据只存内存。Desktop 当前没有这个公开链接入口，应优先使用 companion。不要从本机配置、签名密钥或浏览器 Cookie 猜测/生成 Host 凭据。

## 验证范围

自动化使用离线伪 DSH/loopback HTTP 服务，覆盖 RPC envelope、身份与过期检查、Origin/Host/鉴权、Windows ACL、来源隔离、取消和 UI 选择流程。自动化没有安装插件、没有改当前 DSH profile，也没有向真实会话发暂停。首次实际安装后，先核对只读额度，再由使用者明确选择测试会话做一次暂停验收。

协议与开发安装详见 [companion 说明](../integrations/dsh-bridge/README.md)。适配依据见 [DSH 公开接口核验](handoff/2026-11-02-dsh-supported-api-audit.md)。
