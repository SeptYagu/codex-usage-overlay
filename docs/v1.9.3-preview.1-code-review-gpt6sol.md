# v1.9.3-preview.1 重写版代码审查

- 审查日期：2026-11-15
- 比较范围：`v1.9.2` → `v1.9.3-preview.1`（审查时 `main` 为 `4e7cd69`）
- 审查性质：源码对照与有限自动化验证；下文的运行风险由代码路径推导，尚未做交互式桌面复现。

## 总体判断

重写版在共享 bridge 代码、按 provider 组织状态、复用连接 UI 和减少空闲状态轮询方面有明确的结构收益。当前还不能把它视为对旧版行为的无损替换：配置容错、关闭保护后的手动恢复入口出现回归；CI 没有运行新增 workspace crate 的单元测试；旧版部分恢复计划的跨重启持久化能力也被移除。建议先处理前两项用户可见问题，再补 CI 覆盖，最后明确跨重启恢复的产品预期。

## 值得保留的优化

| 变化 | 对比旧版的收益 | 证据与边界 |
| --- | --- | --- |

## 发现与修复建议

### 1. [P2] 单个 provider 配置字段类型错误可使整份配置回退默认值

**代码路径。** 新版 `ProviderPreference` 使用派生 `Deserialize`，`monitorEnabled`、`protectionEnabled` 等字段是严格类型（[`config.rs:77-108`](../src-tauri/src/config.rs#L77-L108)）。`OverlaySettings::from_json_migrated` 先对整份 JSON 做 `serde_json::from_value`，失败即返回错误，迁移逻辑还未运行（[`config.rs:402-409`](../src-tauri/src/config.rs#L402-L409)）；`load_settings` 接到错误后静默返回默认配置（[`config.rs:715-728`](../src-tauri/src/config.rs#L715-L728)）。

**旧版对照。** `v1.9.2` 的 `ProviderPreference` 有自定义 `Deserialize`，逐字段尝试解析；某个字段解析失败时，其他合法字段仍可保留（[旧版 `config.rs`](https://github.com/SeptYagu/codex-usage-overlay/blob/v1.9.2/src-tauri/src/config.rs) 中的 `impl Deserialize for ProviderPreference`）。新版只对部分字段提供专门的容错反序列化，布尔字段等仍会中断整份配置解析。

**触发与影响。** 例如保存的 JSON 中 `providerPreferences.codex.protectionEnabled` 为字符串 `"oops"`，同时语言、阈值等其他字段有效：启动时仍会把整份配置读成默认值；若之后保存设置，默认值可能覆盖原文件。手改配置、旧版本异常写入或局部损坏时会遇到；格式完全正确的文件不受此路径影响。现有测试覆盖了错误的声音模式和刷新间隔，未覆盖严格布尔字段失败后保留其他字段的情形（[`config.rs:1260-1286`](../src-tauri/src/config.rs#L1260-L1286)）。

**建议与验收。** 恢复 provider 偏好的逐字段容错，或在整体反序列化前仅清理无效字段，并记录可诊断的加载错误。用一个含错误 `protectionEnabled`、有效语言和有效其他 provider 设置的持久化文件测试 `load_settings`：仅坏字段采用默认值，其余值保持；保存后不丢失有效值。

### 2. [P2] 关闭保护后，仍被记录的暂停会话失去手动恢复入口

**代码路径。** 控制器记录了暂停会话，关闭保护本身不会清掉列表（[`pause_control/mod.rs:198-255`](../src-tauri/src/pause_control/mod.rs#L198-L255)）。但状态快照把 `monitor_enabled && protection_enabled` 作为 `enabled`（[`status.rs:200-213`](../src-tauri/src/pause_control/status.rs#L200-L213)）；`enabled == false` 时输出空的 `paused_threads`（[`status.rs:102-139`](../src-tauri/src/pause_control/status.rs#L102-L139)）。前端只根据 `status.pausedThreads` 绘制恢复与清除按钮（[`ProtectionStatus.tsx:84-96`](../src/components/ProtectionStatus.tsx#L84-L96)）。

**旧版对照。** `v1.9.2` 的状态快照从持久化 `ResumeManager` 读取 `resume_plans`，没有因 `enabled == false` 而清空它们（[旧版 `status.rs`](https://github.com/SeptYagu/codex-usage-overlay/blob/v1.9.2/src-tauri/src/pause_control/status.rs)）。旧版仅对满足条件的计划提供入口，覆盖的暂停类型比新版少。

**触发与影响。** Codex 保护成功暂停一个会话后，用户关闭保护开关；该会话仍在内存列表中，但界面看不到恢复或清除按钮。新版 `resume_chat` 路径会刷新用量并执行额度门控，未直接以保护开关拒绝恢复（[`commands/providers.rs:330-389`](../src-tauri/src/commands/providers.rs#L330-L389)），因此问题首先是入口消失；监控也关闭时，刷新是否可用还需交互验证。

**建议与验收。** Codex 状态应在保护关闭时继续展示已有暂停会话，或提供独立的“待恢复会话”视图；保留现有额度安全门控。测试“暂停成功 → 关闭保护 → 列表仍可见 → 额度允许时恢复或清除”，并检查切换 provider 后不会串出 Codex 会话。

### 3. [P2，验证覆盖] CI 未执行新增 crate 的自有测试，且移除了估算器校验夹具

**代码路径。** 新版 workspace 含根包与 `crates/agent-bridge`（[`Cargo.toml:1-20`](../src-tauri/Cargo.toml#L1-L20)），但 CI 仍运行不带 `--workspace` 的 `cargo test --manifest-path src-tauri/Cargo.toml --locked`（[`ci.yml:57-59`](../.github/workflows/ci.yml#L57-L59)）。从根包 manifest 运行时，该命令测试根包，`agent-bridge` 作为依赖会编译，但它自己的单元测试不会由此执行。发布说明记录了单独的本地 `--workspace` 测试通过（[`发布说明`](releases/v1.9.3-preview.1.md)），不能替代每次提交的 CI 覆盖。

同一版本还移除了旧 CI 的 `node scripts/affine-parity-fixture.mjs --check`、脚本本身和 `affine-parity.csv`，以及若干 burn-rate replay/evidence 脚本与数据。Weighted、Personalized 输出仍保留在新版路径中（[`burn_rate.rs`](../src-tauri/src/codex/burn_rate.rs)）。这属于回归检测能力下降，不能由此推断当前估算结果已经错误。

**建议与验收。** 将 CI Rust 命令改为 `cargo test --manifest-path src-tauri/Cargo.toml --workspace --locked`，确认 CI 输出包含 `agent_bridge` 的测试运行。为仍提供的估算模式保留一个精简、确定性的 parity/replay 校验，并在 CI 中执行；不必恢复整套历史分析资产。

### 4. [P3，产品取舍] 手动恢复列表不再跨应用重启

旧版 `ResumeManager::load` 会从 `pause-resume-state.json` 读取符合条件的恢复计划；它有明确的 eligibility、过期和账号等校验（[旧版 `resume.rs`](https://github.com/SeptYagu/codex-usage-overlay/blob/v1.9.2/src-tauri/src/pause_control/resume.rs)）。新版只在 `AutoPauseController::new` 里初始化内存 `paused_threads: Vec::new()`（[`pause_control/mod.rs:198-205`](../src-tauri/src/pause_control/mod.rs#L198-L205)），没有对应的落盘和启动加载路径。新版同次运行中可记录的已接受暂停范围更宽，但重启后列表会消失。旧版跨重启能力也只覆盖满足其计划条件的暂停，不能把两版列表视为完全等价。

建议先确定产品预期：若用户需要重启后找回暂停会话，保存最小化的会话 ID、账号、来源和时间，并在加载时做有效期与账号校验；若刻意只保留会话期列表，应在说明和界面中明确告知。验收应覆盖重启、账号切换、过期与重复记录。

## 修复顺序与验证范围

1. 先修配置读取容错，阻断有效设置因局部坏值而丢失。
2. 再修保护关闭后的恢复入口，并通过 UI 与命令路径共同验证。
3. 更新 CI 的 workspace 测试命令并恢复最小估算器夹具。
4. 最后决定跨重启恢复是否为预览版必须保留的能力。

本次审查已运行 `npm test`（14 文件、190 用例通过）和 `npm run build`（通过，83 模块）。本机尝试 `cargo test --manifest-path src-tauri/Cargo.toml --workspace --locked --lib` 时，因缺少 MSVC `link.exe` 未能完成链接与测试；发布说明报告标签前在其环境中通过了 workspace Rust 测试，但本次未独立复核。未做交互式 Windows GUI、真实 bridge/额度链路、安装包或更新器验收。上述代码路径和风险判断不应等同于这些场景的运行实测结果。
