# 用量历史折线图改为显示额度余量

**状态：已在 v1.10.1-preview.2 实施（2026-11-26）。** 本方案只调整用量历史窗口中“用量走势”的显示含义，覆盖[原用量历史方案](usage-history-plan.md)里时间折线显示“已用百分比”的设计。每日消耗和额度窗口统计继续表示消耗或已用量。

## 问题与目标

当前时间折线显示已用百分比：使用额度时曲线上升，重置后回落。这与主悬浮窗显示“剩余额度”的读法不一致。将时间折线统一改为**剩余百分比**：使用额度时曲线下降，重置后余量回升。例如历史读数已用 20% 显示为剩余 80%；已用 100% 显示为剩余 0%。

## 最小改动范围

1. 仅在[TimelineChart.tsx](../src/components/history/TimelineChart.tsx)的呈现层，把历史点的已用值 `u` 映射为 `100 − u`，用于折线、孤立点、键盘/鼠标选中点和悬停提示。保持纵轴 **0% 在底部、100% 在顶部**，不要只翻转坐标轴而让标签仍代表已用量。`null` 仍表示无读数，不转换为 100%。
2. 保护阈值虚线也必须落在余量坐标上。现有[usedThresholds](../src/history.ts)会把设置中的剩余阈值转换为已用阈值；绘制虚线时换回 `100 − 已用阈值` 即可。例如剩余 5% 的保护阈值画在 5%，而不是 95%。不改保护行为或设置值。
3. 修改[i18n.ts](../src/i18n.ts)中四种语言的时间折线标题或说明，使其明确表示“剩余额度百分比”；悬停数值也遵循同一含义。保留现有重置竖线、缺口阴影、颜色、时间范围和键盘交互。
4. **不改** Rust 历史记录、JSONL 文件、`get_usage_history` 返回值、前端 `HistoryPoint` 契约和统计计算。[DailyBars.tsx](../src/components/history/DailyBars.tsx)仍显示每天实际消耗，可超过 100%；[WindowTable.tsx](../src/components/history/WindowTable.tsx)仍显示已用峰值、触顶与重置时未用额度。无需迁移旧数据，也不增加设置开关。

## 实施步骤

1. 在时间折线组件集中使用一个局部转换 `remaining(u) = 100 − u`，让所有绘图位置和提示数值调用同一规则。阈值采用相同坐标，避免折线与虚线含义相反。
2. 更新四种语言的折线标题/说明；不要改“每日消耗”和“额度窗口”的文案含义。
3. 更新[HistoryView.test.tsx](../src/components/HistoryView.test.tsx)的现有图表用例：已用 20% 的提示应为剩余 80%，已用 50% 应为剩余 50%；断言曲线随已用量增加而下降、重置后回升、保护阈值在正确余量位置。保留空值、缺口和跨段断线检查。
4. 运行前端测试与构建，人工查看浅色和深色主题下的折线及提示。按仓库规则提交、推送并等待 Windows CI；这份方案本身不实施或发布代码。

## 验收标准

- 5 小时、每周及 Antigravity Argon 的时间折线在同一窗口内随使用而下降；重置后的新窗口从较高余量开始。断线仍断线，不把重置或缺口连接成连续消耗。
- 纵轴、折线、点、提示和保护阈值表达同一“剩余百分比”，其中 100% 在顶部、0% 在底部；无读数仍显示为缺失。
- 每日消耗柱状图、额度窗口统计及已有 90 天历史数据的含义和数值不变。
