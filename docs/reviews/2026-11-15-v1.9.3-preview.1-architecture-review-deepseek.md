# Codex Usage Overlay v1.9.3-preview.1 架构重写审查（DeepSeek）

> 审查对象：`4e7cd69`（PR #1 `refactor/de-overengineering`，v1.9.3-preview.1）
> 对照基线：`853e146`（v1.9.2）
> 审查范围：后端 Rust（`src-tauri/`）、前端 TS/TSX（`src/`）、CI 与文档；不含安装包实机验收
> 结论：**方向正确、收益真实；2 项 P2 未清零，按零缺陷标准不能作为 stable 发布**（preview 可用）
> 本文所有 `file:line` 均指 `4e7cd69`；旧版引用显式标注 `853e146:` 前缀

---

## English summary

The rewrite is a net simplification, not a rewrite for its own sake: provider runtime ownership moved to `ProviderRegistry`/`AppServices`, the frontend collapsed onto a single `monitor_updated` stream, the unconditional 1-second status loop became `status_wake` + a 15-second fallback, and ~4.3k lines of a burn-rate learner that was fed but never displayed were removed.

Two P2 items block a stable release: the 96-origin affine parity fixture and its CI gate were deleted together with the golden CSV (the only cross-implementation numeric guard for the `Personalized` estimator), and the manual-resume thread list is now memory-only, so a restart silently drops every one-click resume affordance. Six P3 items (shim self-heal, dead doc links, no-op snapshot publishing, `synchronize` serialization churn, release-note accounting, rollback semantics) are recorded below with fix suggestions.

## 2. 结论

这次重写的核心判断是对的：**删掉"喂了但从不显示"的并行学习器、把三套状态所有权收成一套、把两个上帝文件拆开**。它没有引入新的抽象层，反而删掉了两套 mock-only trait 与中间枚举（旧版 8 处 `#[allow(dead_code)]`，现仅剩 1 处 `cfg(test)` 用途）。

但它同时也删掉了两类"看起来像负担、实际是保险"的东西：**估算器的金标回归**与**恢复状态的持久化**。这两项不影响首次运行，只在下一次改算法、或用户重启之后才暴露——属于典型的"测试全绿但实现有缺口"。

## 3. 优化点（有证据）

| # | 优化 | 证据与量化 |
| --- | --- | --- |
| 1 | **状态流收拢，IPC 事件量降约 93%** | 旧 `lib.rs` 每 1 秒无条件 `registry.publish()`，每次为 4 个 provider 各发一条 `monitor_updated` ≈ **34.6 万条/天**；新 `status_wake` + 15 秒兜底 ≈ **2.3 万条/天**（`lib.rs:271-289`）。唤醒点覆盖 usage 事件、暂停状态、设置提交、桥接探测、手动恢复，`Notify` 的 permit 语义保证不丢唤醒 |
| 2 | **前端单一数据源** | 删除 `usage_updated` 事件、`get_last_usage` 命令与 `usageSource.ts`（68 行 + 56 行测试）。主窗、托盘、轮播统一消费 `monitor_updated`；`mergeMonitorSnapshot` 以 `sourceKey`/`sourceGeneration`/`revision`/`presentationRevision` 四重条件拒绝乱序与旧源（`useProviderMonitors.ts:19-27`），比旧的 buffer + `takeMatchingUsage` 机制更严格且更短 |
| 3 | **删除从不显示的并行学习器** | `personal.rs` 829 + `shadow.rs` 478 + `replay*` 1,825 行（`replay` 仅有 `mod replay;` 声明，纯死码）+ 其测试 1,202 行。`Personalized` 仍由 `weighted × affine.rate()` 供给（`burn_rate.rs:344-373`），旧 `burn-rate-state.json` 仍无损加载（多余子树被 serde 忽略，`shadow_tests.rs` 覆盖 v1/v2 迁移） |
| 4 | **消除跨 provider 串味** | 旧 `synchronize` 用 `auto_pause_on_low_quota` 镜像做比较，非当前 provider 的 runtime 实际看到的是**别的 provider** 的开关；新版直接比较 `preference(provider)`（`monitor.rs:122-139`） |
| 5 | **桥接实现去重** | Claude/Antigravity 各有一份 `run_chained`/`git_bash`/原子写/本地化 → 合并为 `crates/agent-bridge` 一份。注意：**几乎不省行数**（2,160 → 2,134，仅 −26），收益是单一实现与单一缺陷面；三种语言的拦截文案逐字未变（模板参数化 provider label） |
| 6 | **大文件拆分** | `commands.rs` 4,142 行 → `commands/{mod,providers,settings,usage,updater}.rs`（最大 1,916）；`pause_control` 目录 4,396 → 3,511 行（`resume.rs` 816 行删除）。拆分本身**不省行数**（commands 总量 4,290，+148），收益是职责边界 |
| 7 | **保留关键竞态修复** | `RefreshCompletion` 丢弃被取消的刷新（`usage.rs:318-331`）、`source_commit` 串行化源切换、`live_poll.rs` 以 `Deref` 复用节流而保留 Claude 的 `take_renewal` 退避（`claude/live.rs:36-70`）——都不是新写的能力，但没有在搬运中丢失 |

## 4. 不如的地方

### R1（P2）个性化估算失去唯一的数值金标

- **证据**：`src-tauri/tests/fixtures/affine-parity.csv`（97 行）、`scripts/affine-parity-fixture.mjs`（25 行）与 `.github/workflows/ci.yml` 中的 `node scripts/affine-parity-fixture.mjs --check` 步骤一并删除。旧测试 `853e146:src-tauri/src/codex/burn_rate/affine.rs:82-96` 用该 CSV 对 **96 条合成轨迹**做跨实现比对（独立 JavaScript 实现，容差 `1e-9`）。
- **触发条件**：任何对 `affine.rs::rate` / `learn` 的改动，包括未来调参、clamp 边界调整、衰减系数变更。
- **影响**：`Personalized` 是设置页可选、主浮窗直接显示的 5H 燃烧速率。现有单测只验证"单调、有界、衰减"这类自洽性质，没有任何独立实现或历史数据对照；算法漂移会静默通过全部测试。
- **建议**：恢复最小金标——保留生成脚本并提交 20–50 行 CSV，或直接把 8–16 条固定轨迹向量内联进 `#[test]`；CI 保留 `--check`。成本约 30 行，收益是这条算法唯一的回归网。

### R2（P2）手动恢复列表不再持久化

- **证据**：`pause_control/mod.rs:10-11` 明确注释"只在内存、从不落盘"；列表在 `:239-256` 维护；`status.rs:96-98` 输出。旧版有 `853e146:src-tauri/src/commands.rs:63,129`（`ResumeManager::load`）与 `pause_control/resume.rs:104`，状态写入 `pause-resume-state.json`，重启后可恢复。
- **触发条件**：暂停会话后重启或升级 overlay；以及提交结果未知（`mod.rs:909-921`，`Ok(false)` + `started=true`）时该会话根本不会进入 `paused_threads`。
- **影响**：重启后一键「继续」入口全部消失，用户需自己回到对应会话手动输入；旧版的 `submissionUnknown`/`needsReview` 还有「需要人工检查」的提示文案，新版只剩 targets 列表里的一行 `protectionPhases.unknown`，没有任何操作引导。这是"最需要人工介入的状态，反而没有按钮"。
- **建议**：至少把 `paused_threads` 连同一份 `observed_at` 落盘并设 TTL（例如 24 小时），或在 UI 明示"重启后需手动继续"；unknown 提交也纳入列表，标注"结果未知，未重发"。

### R3（P3）Antigravity `.cmd` 垫片不再自愈

- **证据**：`repair_if_needed` 现在只在启动（`lib.rs:44-52`）与 `antigravity_connect` 中调用（`antigravity/install.rs:119-139`）；`status()`（`:53-93`）只读 CLI settings 与 hooks 文档，不检查注册命令指向的 `antigravity-usage-bridge.cmd` 是否存在。旧版每次 `antigravity_connection_status` 都会 `repair_if_needed`（`853e146:src-tauri/src/commands.rs:1786-1792`）。
- **触发条件**：overlay 位于含空格且无 8.3 短名的路径（此时才产生垫片），覆盖安装/移动目录/杀软隔离导致垫片丢失，且会话未重启。
- **影响**：`PreInvocation` hook 指向不存在的 `.cmd` → 低额度保护静默失效，而设置页仍显示「已连接」（`status_line`/`hooks` 只看配置内容）。
- **建议**：`status()` 增加"注册命令指向垫片且垫片缺失"的判断并报 `bridgeMissing`；修复改为"缺失或内容不符才写盘"，既恢复自愈，也不再有旧版每次轮询重写文件的写盘开销。

### R4（P3）删除目录后留下死链

- **证据**：`docs/handoff/` 整目录删除（77 个文件 / 12,816 行），但 `STATUS.md` 仍有 **21 处** `docs/handoff/*` 引用，`integrations/dsh-bridge/README.md:147` 也指向 `../../docs/handoff/2026-11-02-dsh-supported-api-audit.md`。
- **影响**：`STATUS.md` 是当前状态文档，读者点进去全部 404；`docs/releases/*` 里的历史链接指向 tag 内的旧路径，仍然有效，不受影响。
- **建议**：把 `STATUS.md` 的链接改指对应 `docs/releases/*`，或删掉链接只保留结论；integrations README 那一处改为仓库内现存文档。

### R5（P3）15 秒循环仍在全量重发

- **证据**：`lib.rs:271-289` 每轮调用 `monitors.publish()`，`monitor.rs:303-307` 对每个 provider 无条件 `publish_snapshot`；每次构建都在 `monitor.rs:386` 递增 revision，前端 `useProviderMonitors.ts:23` 的 `next.revision <= old.revision` 因此永远放行。
- **影响**：约 2.3 万条无内容变化的 `monitor_updated`/天，每条都会触发一次 `setState` 与重渲染；轮播与托盘常驻时是持续唤醒。
- **建议**：`build_snapshot_locked` 之外做内容比较（除 `revision` 外的结构哈希），未变则不 emit；或让 `publish` 只在 runtime 的 dirty 标记置位时执行。

### R6（P3）`synchronize` 的全量序列化比较

- **证据**：`monitor.rs:125-136` 对 4 个 provider 各做 2 次 `serde_json::to_value` 全量比较，只为判断"全局字段是否变化"。
- **影响**：每次设置 patch（含滑杆 debounce）产生 8 次全量序列化 + 4 次 `source_commit` 获取。用户触发、非热点，但属于可以避免的固定开销。
- **建议**：用 `settings_revision` 或字段级 `dirty` 位短路；只有 `providerPreferences[provider]` 或已知全局字段变化时才进入比较。

### R7（P3）发布说明的规模口径与真实 diff 不一致

- **证据**：`docs/releases/v1.9.3-preview.1.md:3` 写 "`165` files changed … `-19,802` net lines"；实际 `git diff --shortstat v1.9.2..4e7cd69` = **171 files / +10,456 / −30,178（净 −19,722）**。
- **建议**：改成实测数字，避免以后用发布说明回溯变更规模时对不上。

### R8（P3）回滚到 v1.9.2 时镜像字段缺失

- **证据**：新文件写 `schemaVersion = 5`，旧版 `migrate` 对 `> 4` 直接 return（旧 `config.rs:374`），而旧版 UI 与 `display.rs` 轮播新鲜度仍读顶层镜像字段（`refreshIntervalSeconds` 等），这些字段已不再落盘。
- **影响**：回滚后设置页与轮播节奏显示为默认值；运行时因为 `for_provider()` 会按 `providerPreferences` 重算，保护本身仍正确，首次保存后自愈。
- **建议**：在 preview 发布说明中写明回滚方式（删除 `settings.json` 中 `schemaVersion` 或整份重置），或短期保留只写不读的兼容镜像。

## 5. 已排除的怀疑（反证记录）

审查中一度怀疑、经代码推导后**不成立**的项，记录在此避免下一轮重复怀疑：

| 怀疑 | 反证 |
| --- | --- |
| Claude/Antigravity guard 的激活条件被改成"不再随当前显示 provider 解除" | 旧版 `write_guard_config` 收到的是 `settings.for_provider(...)`，而 `for_provider` 会把 `auto_pause_on_low_quota` 重算为**该 provider 自己的** `monitor_enabled && protection_enabled`（旧 `config.rs` `for_provider` 尾部）。新旧语义一致 |
| `deliver_batch` 里 `delivery_cursor % targets.len()` 可能除零 | `handshake` 对空列表返回 `Handshake::NoActiveSession`（`transport.rs:690-694`），`Targets` 必非空；该取模在旧版同样存在（`853e146` 第 1699 行） |
| 设置迁移在单个旧字段类型异常时会整体丢失 | 新实现确实用 `LegacyTopLevelFields::unwrap_or_default()`（`config.rs:424`），但旧实现遇到同样情况是**整个 `settings.json` 解析失败并回落默认值**；新版至少保住 `providerPreferences`，属于更宽容而非退步 |
| i18n 里留下 `autoResumeAfterQuotaReset` / `resumePhases` 等死键 | 三语 `src/i18n.ts` 中这些键已随之删除（grep 计数为 0），没有残留 |
| 删除 `get_last_usage` 会打断前端 | 前端唯一引用在 `App.test.tsx` 的"不得调用"断言里；`monitor_updated` + `get_monitor_snapshots` 已覆盖启动水合 |
| `Snapshot.usage` 换了类型会破坏线上结构 | `SnapshotUsage` 与旧 `UsageEnvelope` 字段、`serde(flatten)` 顺序完全一致，前端 `types.ts` 同步更新，190 条前端用例通过 |

## 7. 建议的处理顺序

1. **R1** 补回 affine 金标 fixture 与 CI 校验（最便宜、保护最关键的一块算法）。
2. **R2** 决定 `pausedThreads` 落盘，或至少在 UI 明示"重启后需手动继续"，并把 unknown 提交纳入列表。
3. **R3** 垫片改成"缺失/内容不符才写"，恢复自愈且去掉旧版每次轮询重写的开销。
4. **R4 / R7** 清死链、修正发布说明数字。
5. **R5 / R6** 可选：`publish` 变更检测、`synchronize` dirty 短路。
6. **R8** 在 preview 说明里写清回滚方式。
