# Codex Usage Overlay v1.5.0

This release adds Claude subscription limits as a second usage source, with an optional live reading for the Claude desktop app, provider logos and an optional preview update channel. Codex stays the default source, and existing settings and history carry over.

## Claude usage limits

- In Settings, set **Usage source** to **Claude** to show the Claude 5-hour and weekly windows instead of Codex. Only one source is active at a time.
- **Connect Claude Code** registers the bundled `claude-usage-bridge.exe` as Claude Code's statusline command and adds `UserPromptSubmit` / `PreToolUse` hooks to `~/.claude/settings.json` (honoring `CLAUDE_CONFIG_DIR`). The original file is backed up once as `settings.json.codex-overlay.bak`, your existing statusline keeps rendering through the helper, and **Disconnect** removes only the overlay's entries.
- The statusline delivers limits only while the **terminal `claude` CLI** is in use (Claude Code 2.1.80 or later, Pro or Max plan). In that mode the overlay reads no credentials and makes no network requests.
- **Read limits live with your Claude login** (off by default) also covers the desktop app and IDE extensions. At most once a minute, the overlay asks the usage endpoint behind Claude Code's `/usage`, with the login the terminal CLI stores in `~/.claude/.credentials.json`. The token is read for each request and never stored, logged or sent anywhere else. The endpoint is undocumented and may change.
  - Sign in once with `claude` → `/login`; the desktop app does not share its own login.
  - CLI logins expire after a few hours. The overlay then runs `claude auth status` (at most every ten minutes), so Claude Code renews its own login without using quota. The overlay never writes the credentials.
  - While a live read fails or the endpoint asks to wait, the overlay keeps the last stored reading with its age, and Settings shows the reason.
- Burn rate, reset notifications, the tray and the docked bars work for Claude, with separate `claude-` state files. Credits are not shown for Claude.
- With protection on, the hooks refuse new Claude Code prompts and tool calls while either window is at or below its threshold, with a localized reason. Codex Smart Pause is not used for Claude. Requests go through whenever the quota is uncertain.

## Overlay and tray

- The capsule starts with the active provider's logo (OpenAI for Codex, Claude for Claude). **Show provider logo** hides it. Marks come from Simple Icons (Claude, CC0) and LobeHub Icons (OpenAI, MIT) and are trademarks of their owners.
- The tray icon stays visible on a dark taskbar before the first reading and after a failed read. If Windows loses the icon, the next update registers it again.

## Updates

- **Include preview releases** (off by default) also offers preview builds. Previews now carry numbered versions (for example `1.6.0-preview.1`), so each preview is offered the next preview and then the stable release.
- The 1.5.0 previews (`v1.5.0-preview`, `v1.5.0-preview.2`) report version 1.5.0, so the updater does not offer them this release. Install it manually once.

## Before you upgrade or uninstall

- Disconnect Claude Code before uninstalling the overlay; otherwise Claude Code keeps calling the removed helper. Hook changes apply to new Claude Code sessions.
- A portable copy updated in place from 1.4.x does not receive `claude-usage-bridge.exe`, because older updaters only replace the main program and updater helper. Download the portable ZIP again to use Claude Code connection; later portable updates replace the helper too.

## Validation

- 393 Rust tests, 125 frontend tests, seven packaging checks and the production build passed locally. Local NSIS and MSI builds install the bridge once next to the app.
- Live Claude reading was confirmed against the endpoint with a terminal login, including renewal of an expired login through `claude auth status`.
- Not manually smoke-tested for this release: the tray icon re-registration and dark-taskbar visibility on a real taskbar, and an end-to-end in-app update. The release workflow builds and signs the published packages.
