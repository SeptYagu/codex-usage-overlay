# Codex Usage Overlay v1.10.1-preview.3

Fix preview: the Usage history window handles an early weekly reset that flickers through 0%.

## Fixed

- **A window that flickers to 0% is not a reset.** Around an early Antigravity weekly reset, agy reported the weekly window at 91%, then 0% with no reset time, then 91% with the old reset time again, then 0% before the new window started. The History window drew two weekly resets, listed a two-minute weekly window and counted 91% of weekly use for that day. Now, when a window comes back with the same reset time and no less usage, the 0% readings in between count as part of that window. The chart holds the window's value through the flicker, and the reset is drawn once.
- **Early resets end the window.** A window that was reset well before its reported reset time now ends at that reset in the window table, with its unused share, instead of showing as in progress until the old reset time.

Existing history files are read with the same rules, so the affected day displays correctly without clearing history.

## Verification and limits

- Checked against real history recorded on this machine. Antigravity now shows one weekly reset (02:13) instead of two, and that day's weekly use is 7.85% instead of 99.19%. The old weekly window ends at the early reset with 8.17% unused. Over the same seven days, the Claude and Codex views are unchanged.
- A new test covers the flicker and the early reset. The full frontend and Rust test suites pass locally.
- Includes everything from `v1.10.1-preview.1` and `v1.10.1-preview.2`: the Windows ARM64 packages and the remaining-quota timeline. The ARM64 packages have still not been installed or run on an ARM64 PC, and the remaining-quota timeline has not been checked in an installed package.

## 中文说明

本预览版修复“用量历史”窗口对提前重置且读数在 0% 间跳动的处理。

- **跳到 0% 的窗口不算重置。** Antigravity 每周额度提前重置时，agy 先报告每周窗口 91%，随后为 0% 且没有重置时间，接着又以旧的重置时间报告 91%，再回到 0%，之后新窗口才开始。此前历史窗口会画出两次每周重置，列出一个两分钟的每周窗口，并把当天的每周用量算成 91%。现在若窗口以相同的重置时间、不更低的用量重新出现，其间 0% 的读数视为同一窗口，图表保持该窗口的数值，重置只画一次。
- **提前重置的窗口在重置时结束。** 远早于报告时间就被重置的窗口，在窗口表格中以实际重置时间结束并显示未用额度，不再显示为“进行中”直到原重置时间。

已有历史文件按同样规则读取，无需清除。已用本机真实历史验证：Antigravity 只显示一次每周重置（02:13），当天每周用量为 7.85%（此前为 99.19%）；同期 Claude 和 Codex 的显示不变。前端与 Rust 测试均在本机通过。包含 `v1.10.1-preview.1` 和 `v1.10.1-preview.2` 的全部内容（Windows ARM64 安装包和剩余额度折线；ARM64 安装包仍未在 ARM64 电脑上实测）。
