# Codex Usage Overlay v1.9.6-preview.1

Fix preview for five-hour quota reset notifications.

## Fixed

- The first message after an idle period no longer sounds or displays a false five-hour reset alert when it starts a new quota window.
- A fresh reading that explicitly shows a previously used window has recovered can alert once. Notification state records observed usage, sample time and account identity, and older timestamp-only state starts without a retroactive alert.
- Claude's expired snapshot can still display recovered quota, but that local projection cannot trigger a notification. Codex, Claude and DSH each use their original quota observations for the five-hour decision.

## Limits

- DSH currently supplies only windows with a future reset time, so its first-message false alert is suppressed; a distinct upstream recovery signal is still needed to send a confirmed idle-recovery alert.
- Antigravity's five-hour path retains its existing behavior until real pool samples establish its reset semantics.
- Installed Windows toast and sound behavior has not been verified in a live quota cycle. Synthetic regressions and the Windows CI workflow provide the source validation gate.
