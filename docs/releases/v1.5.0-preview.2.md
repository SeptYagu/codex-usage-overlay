# Codex Usage Overlay v1.5.0-preview.2

This preview makes Claude limits work with the Claude desktop app and adds provider logos. App/package version: 1.5.0.

## Live Claude reading (opt-in)

- `v1.5.0-preview` only received Claude limits from the statusline of the terminal `claude` CLI. The desktop app and IDE extensions never run a statusline, so the overlay showed "Failed to read Claude usage" there.
- **Read limits live with your Claude login** (in the Claude card, off by default) asks the usage endpoint behind Claude Code's `/usage` at most once a minute. It uses the login the terminal CLI stores in `~/.claude/.credentials.json`. The token is read for each request and never stored, logged, refreshed or sent anywhere else. The endpoint is undocumented and may change.
- Live readings are also written to the local snapshot, so the Claude guard hooks work in the desktop app too.
- The desktop app keeps its login to itself. If the overlay reports **No terminal login found**, run `claude` in a terminal and sign in with `/login` once. CLI logins expire; using the CLI renews them, and the overlay never does.
- A missing Claude sample now reads "No Claude limits yet" instead of "Claude Code is not connected". Settings explains which source applies.

## Provider logo

- The capsule starts with the active provider's logo (OpenAI for Codex, Claude for Claude) instead of the "Claude" text label. **Show provider logo** in Settings hides it.
- Marks come from Simple Icons 16.36.0 (Claude, CC0) and LobeHub Icons 1.101.0 (OpenAI, MIT) and are trademarks of their owners.

## Updating from v1.5.0-preview

This preview keeps app version 1.5.0, the same as `v1.5.0-preview`, so the in-app updater does not offer it to that build. Install it from this release page instead.

## Validation

- 124 frontend tests, the Rust suite across all targets, the production build and six packaging fixtures passed locally. Live-reading request mapping, token handling and failure messages are covered by unit tests.
- A request with this machine's credentials confirmed the file holds no terminal login (empty tokens), and that the overlay reports it as a sign-in requirement. **A successful live read against the endpoint has not been performed yet.**
- Both logos were checked in the rendered capsule. Installed-package smoke tests are still outstanding.
