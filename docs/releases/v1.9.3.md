# Codex Usage Overlay v1.9.3

Stable release after `v1.9.2`. It collects the three `v1.9.3` previews and one more Antigravity fix: a large internal simplification with no intended change to what the overlay shows or protects, plus fixes for console windows on Windows, settings recovery and Antigravity pool selection.

## Fixed

- **No more console windows from the overlay's background work on Windows.** About every 15 minutes, the `agy` CLI's self-updater escaped the overlay's hidden-window setting and opened a visible console (often a Windows Terminal window). Antigravity quota polls now run `agy` with its auto-update turned off; interactive `agy` sessions keep updating normally. The portable updater, `CodexUsageUpdater.exe`, is now a windowless program as well. ([#4](https://github.com/SeptYagu/codex-usage-overlay/issues/4))
- **Antigravity Auto pool picks the right quota for the Neon orchestrator.** With Gemini 4 Neon, agy offers "Orchestrator (Argon)" and "Orchestrator (Neon)". The Neon orchestrator counts against the main Gemini quota, but Auto sent it to the Argon pool, so protection and the main readings followed the wrong limit. Only models whose name includes Argon use the Argon pool now. The Argon weekly (WTU) reading itself is unchanged.
- **Stuck Antigravity polls end completely.** A quota poll that times out or is cancelled now stops every process it started, including `agy.exe` behind an `agy.cmd` shim.
- **A bad value in `providerPreferences` no longer resets all settings.** A wrong-typed value in a hand-edited `settings.json` falls back for that one field instead of loading the whole file as defaults.
- **Upgrading an old `settings.json` keeps an explicit per-provider `protectionEnabled`.** The legacy top-level `autoPauseOnLowQuota` no longer overwrites it.
- **Stale readings show on time** instead of up to 15 seconds late.

## Changed

- Internals were consolidated: the Claude and Antigravity bridges share one `agent-bridge` crate, monitor state reaches the window through a single update stream, and large backend modules were split up. The 1-second background status loop was replaced by on-demand wake-ups, with a 15-second check while Codex protection is on.
- Unused burn-rate telemetry and replay code was removed, along with the "auto-resume after quota reset" option, which was always disabled. The `Legacy`, `Weighted` and `Personalized` 5H burn-rate forecasts, both DSH pairing paths and manual thread resume are unchanged. Saved settings and burn-rate history from `v1.9.2` load without loss.

## Upgrade note

- This release rewrites `settings.json` to schema v5. `v1.9.2` can still read the file but refuses to save changes to it. To go back to `v1.9.2`, restore or delete `settings.json`.

## 中文说明

`v1.9.2` 之后的正式版，汇总三个 `v1.9.3` 预览版并新增一项 Antigravity 修复：大规模内部精简（不改变浮窗显示与保护行为），以及 Windows 控制台窗口、设置恢复和 Antigravity 配额池选择方面的修复。

### 修复

- **后台任务不再在 Windows 上弹出控制台窗口。** `agy` CLI 的自动更新程序约每 15 分钟会绕过悬浮窗的隐藏窗口设置，弹出可见的控制台（常见为 Windows Terminal 窗口）。现在 Antigravity 额度轮询运行 `agy` 时关闭其自动更新；交互式 `agy` 会话仍正常更新。便携版更新程序 `CodexUsageUpdater.exe` 也改为无窗口程序。（[#4](https://github.com/SeptYagu/codex-usage-overlay/issues/4)）
- **Antigravity“自动”配额池为 Neon 编排模型选择正确额度。** Gemini 4 Neon 上线后，agy 提供 “Orchestrator (Argon)” 与 “Orchestrator (Neon)”。Neon 编排模型计入 Gemini 主额度，但“自动”会把它归入 Argon 配额池，导致保护与主读数跟随错误的额度。现在只有名称包含 Argon 的模型使用 Argon 配额池；Argon 每周（WTU）读数本身不变。
- **卡住的 Antigravity 轮询会被完整结束。** 轮询超时或被取消时，会结束其启动的所有进程，包括经 `agy.cmd` 启动的 `agy.exe`。
- **`providerPreferences` 中的错误值不再重置全部设置。** 手工编辑的 `settings.json` 中类型错误的字段只让该字段回退，不再整份按默认值加载。
- **升级旧版 `settings.json` 时保留显式设置的来源级 `protectionEnabled`。** 旧版顶层 `autoPauseOnLowQuota` 不再覆盖它。
- **过期读数按时显示**，不再最多延迟 15 秒。

### 变更

- 内部整合：Claude 与 Antigravity 桥接程序共用 `agent-bridge` crate，监控状态通过单一更新流送达窗口，并拆分了大型后端模块。后端 1 秒状态轮询改为按需唤醒，开启 Codex 保护时每 15 秒兜底检查。
- 移除未使用的消耗速率遥测与回放代码，以及始终处于禁用状态的“额度重置后自动恢复”选项。`Legacy`、`Weighted`、`Personalized` 三档 5H 消耗速率预测、DSH 双配对通路与手动恢复对话保持不变；`v1.9.2` 的设置与消耗速率历史可无损加载。

### 升级提示

- 本版本会把 `settings.json` 改写为 schema v5。`v1.9.2` 仍可读取该文件，但会拒绝保存修改。如需退回 `v1.9.2`，请还原或删除 `settings.json`。
