# Codex Usage Overlay v1.9.6

Stable release combining `v1.9.5-preview.1`, `v1.9.5-preview.2`, and `v1.9.6-preview.1`. It includes all fixes below on top of `v1.9.4`.

## Fixed

- **Alt+F4 cannot destroy the overlay.** A close request on the overlay is ignored; Hide and Exit remain available from the tray and overlay menus.
- **WebView2 failures recover.** A crashed or unresponsive page renderer reloads in place, at most once per window every 30 seconds. If the WebView2 browser process exits after the app has been running for a minute, the app restarts and recreates its windows from saved state.
- **A floating overlay stays inside the screen.** Display, resolution, scaling and taskbar changes reposition it within the selected work area. If its saved display disappears, it moves to another display and returns when the original display is available. A docked pill is repositioned too. Content growth near the right or bottom edge no longer clips the overlay; shrinking returns it to its saved position.
- **Five-hour reset notifications require evidence of recovery.** The first message after an idle period can open a new quota window without a false alert or sound. A fresh reading that explicitly confirms recovery of a previously used window can alert once. Claude's display-only expiry projection is excluded, and old notification state or an account change establishes a silent baseline.

## Known limits and verification

- A recovery restart loses state held only in memory, including pending paused-chat resume entries. An update prepared for installation on exit is not installed by that recovery restart; automatic update checks prepare it again after relaunch.
- A WebView2 browser-process exit during the first minute after launch does not trigger a restart, to avoid a restart loop when the runtime is broken.
- DSH's current upstream quota response only exposes windows with future reset times. The false first-message alert is suppressed, but a confirmed idle-recovery alert requires a distinct upstream signal. Antigravity retains its existing five-hour notification behavior pending real quota-pool samples.
- The Windows CI and Release workflows test and package the tagged source. Interactive installed-app checks remain unperformed: Alt+F4 and WebView2 recovery, display changes and edge growth, live five-hour notification and sound, signed installer upgrades, and the in-app updater. The five existing ignored hardware/live/GUI tests have not been run.

## 中文说明

`v1.9.6` 正式版整合 `v1.9.5-preview.1`、`v1.9.5-preview.2` 和 `v1.9.6-preview.1`，包含从 `v1.9.4` 以来的全部修复。

### 修复

- 悬浮窗收到 Alt+F4 等关闭请求时不再被销毁；隐藏和退出仍由托盘及悬浮窗菜单控制。
- WebView2 页面渲染进程崩溃或无响应时原地重载；应用运行满一分钟后若 WebView2 浏览器进程退出，则自动重启并从已保存状态重建窗口。
- 增减显示器、更改分辨率或缩放、移动任务栏后，自由悬浮窗会落回工作区；原显示器重新接入时回到保存位置。内容在屏幕右侧或下方变宽、变高时不再被裁切，缩小时回到保存位置；停靠胶囊也会重新落位。
- 五小时额度通知只在新鲜读数明确证实已用窗口恢复时提醒一次。闲置后首条消息新建窗口不再误弹通知或播放声音；Claude 的过期显示投影不参与判定，旧状态和账号切换会静默建立基线。

### 已知限制与验收范围

- 恢复性重启会丢失仅在内存中的状态，例如待恢复的已暂停对话；它不会安装已准备的更新，开启自动检查后会重新准备。启动后第一分钟内的 WebView2 浏览器进程退出不会触发自动重启，以免形成重启循环。
- DSH 当前上游只有带未来截止时间的窗口，能消除首条消息误报，但无法在没有独立恢复信号时提醒真实空闲恢复。Antigravity 的五小时通知仍待真实配额池样本确认。
- Windows CI 和 Release 工作流验证标签源码及打包；安装版交互尚未实测，包括 Alt+F4 与 WebView2 恢复、显示器变化和边缘伸缩、真实五小时通知与提示音、签名安装包升级和内置更新。五项已有的硬件／实时／GUI 忽略测试也未运行。

正式版使用标准更新通道，无需开启“包含预览版更新”。
