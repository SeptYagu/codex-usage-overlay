# Codex Usage Overlay v1.10.1

Stable release on top of `v1.10.0`. It adds Windows ARM64 packages and a Remaining / Used switch for the usage history timeline, and fixes how usage history reads resets. Includes everything from `v1.10.1-preview.1` through `v1.10.1-preview.3`.

## Added

- **Remaining / Used switch on the timeline.** The Usage history timeline shows remaining quota by default: lines fall as quota is used and rise after a reset (`v1.10.1-preview.2`). A **Remaining / Used** switch beside the timeline title brings back the used-percent view, with the matching title, hover values and protection threshold lines. The choice is remembered. Daily consumption and the window table always show usage.
- **Windows ARM64 packages.** Each release now ships the NSIS installer, MSI and portable ZIP built natively for ARM64 (`arm64` in the file name), next to the x64 ones (`v1.10.1-preview.1`). An installed or portable copy updates only from packages of its own architecture, so an x64 copy running under emulation on an ARM64 PC keeps updating to x64. To switch to the native build, install the ARM64 package; settings and history are kept.

## Fixed

- **Resets drawn once.** After an Antigravity reset, agy can report an unused 0% window and then no window at all; that drop was drawn as a second reset. Any window at 0% now counts as not in use, for every provider (`v1.10.1-preview.1`).
- **A window that flickers to 0% is not a reset.** Around an early weekly reset, agy read 91%, 0%, 91% with the old reset time, then 0%. The History window drew two resets, listed a two-minute window and counted 91% of weekly use for the day. The 0% readings inside a window that comes back with the same reset time now belong to that window (`v1.10.1-preview.3`).
- **Early resets end the window.** A window reset well before its reported time now ends at that reset in the window table, with its unused share, instead of showing as in progress until the old reset time (`v1.10.1-preview.3`).

Existing history files are read with the same rules, so no history needs clearing.

## Known limits and verification

- The full frontend, Rust, DSH companion, packaging and Claude process-tree checks pass locally on Windows x64, and CI runs the tests on both x64 and ARM64.
- The history fixes were checked against real Claude, Codex and Antigravity history recorded on this machine. The Remaining / Used switch was checked in a browser preview with that history, in light and dark themes; it has not been tried in an installed copy.
- The ARM64 packages are built and signed by the release workflow but have not been installed or run on an ARM64 PC.

## 中文说明

`v1.10.1` 正式版基于 `v1.10.0`，新增 Windows ARM64 安装包和用量历史折线的“剩余 / 已用”切换，并修复用量历史对重置的判断。包含 `v1.10.1-preview.1` 至 `v1.10.1-preview.3` 的全部内容。

### 新增

- **折线“剩余 / 已用”切换。** 用量历史折线默认显示剩余额度：使用额度时下降，重置后回升。折线标题旁新增“剩余 / 已用”切换，可恢复显示已用百分比，标题、悬停数值和保护阈值线随之切换，选择会被记住。每日消耗和额度窗口表格始终显示用量。
- **Windows ARM64 安装包。** 每次发布同时提供原生 ARM64 版本的 NSIS 安装包、MSI 和便携 ZIP（文件名含 `arm64`）。应用只从与自身架构相同的安装包更新；在 ARM64 电脑上以模拟方式运行的 x64 版本会继续更新到 x64。如需改用原生版本，请安装 ARM64 安装包，设置和历史都会保留。

### 修复

- **重置只画一次。** Antigravity 重置后可能先返回一个 0% 的未使用窗口、之后不再返回窗口，此前会被画成第二次重置。现在所有来源中 0% 的窗口都视为未使用。
- **跳到 0% 的窗口不算重置。** 每周额度提前重置时，agy 依次报告 91%、0%、以旧重置时间报告 91%、再到 0%。此前历史会画两次重置、列出一个两分钟的窗口，并把当天每周用量算成 91%。现在以相同重置时间重新出现的窗口，其间 0% 的读数视为同一窗口。
- **提前重置的窗口在重置时结束。** 远早于报告时间就被重置的窗口，在窗口表格中以实际重置时间结束并显示未用额度。

已有历史文件按同样规则读取，无需清除。

### 已知限制与验证

- 前端、Rust、DSH 配套组件、打包和 Claude 进程树检查均在本机 Windows x64 通过；CI 在 x64 和 ARM64 上运行测试。
- 历史修复已用本机真实的 Claude、Codex 和 Antigravity 历史验证。“剩余 / 已用”切换已在浏览器预览中用真实历史、浅色与深色主题检查，尚未在安装版中实测。
- ARM64 安装包由发布流程构建和签名，尚未在 ARM64 电脑上安装或运行。
