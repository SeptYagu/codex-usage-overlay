# Codex Usage Overlay v1.5.0-preview

This preview adds Claude subscription limits as a second usage source and an opt-in preview update channel. App/package version: 1.5.0.

## Claude usage limits

- In Settings, set **Usage source** to **Claude** to show the Claude 5-hour and weekly windows instead of Codex. Codex remains the default, and only one source is active at a time.
- **Connect Claude Code** registers the bundled `claude-usage-bridge.exe` as Claude Code's statusline command and adds `UserPromptSubmit` / `PreToolUse` hooks to `~/.claude/settings.json` (honoring `CLAUDE_CONFIG_DIR`). The original file is backed up once as `settings.json.codex-overlay.bak`. Your existing statusline keeps rendering through the helper. **Disconnect** restores it and removes only the overlay's entries.
- Limits come from the `rate_limits` data Claude Code passes to its statusline, so they need Claude Code 2.1.80 or later signed in with a Pro or Max plan. The overlay reads no Claude credentials and makes no network requests for Claude. **Values update only while Claude Code is in use.**
- Burn rate, reset notifications, the tray and the docked bars work for Claude. Learner and reset state are stored in separate `claude-` files. Credits are not shown for Claude.
- With protection on, the Claude hooks refuse new prompts and tool calls while either window is at or below its threshold, and show a localized reason. Codex Smart Pause is never used for Claude. The guard lets requests through whenever the quota is uncertain: no sample, an unreadable sample, a passed reset, or protection turned off.

## Preview update channel

- **Include preview releases** (off by default) makes update checks read the manifest of the highest-versioned published release, preview or stable, found through the GitHub releases API. Updates are still signature-verified. Turning the option off stops offering previews but does not downgrade an installed preview.

## Limits and migration

- Disconnect Claude Code before uninstalling the overlay. Otherwise Claude Code keeps calling the removed helper.
- Hook changes apply to new Claude Code sessions.
- A portable copy updated from an earlier version does not receive `claude-usage-bridge.exe`, because older updaters only extract the main program and updater helper. Download the portable ZIP again to use Claude support; later portable updates replace the helper automatically.
- This preview keeps app version 1.5.0, so the later stable 1.5.0 is not offered as an update to this preview.

## Validation

- Rust tests, frontend tests, the production build, the locked all-target check and six packaging fixtures passed locally. The bridge was exercised with recorded statusline input, both hooks, statusline chaining through Git Bash and argument errors. Local NSIS and MSI builds confirmed that both installers install the bridge once next to the app and remove it on uninstall.
- **Not yet performed:** a live Claude Code session against the installed package, installed-package and portable smoke tests, and an end-to-end preview-channel update. The release workflow builds and signs the published packages; check its result separately.
