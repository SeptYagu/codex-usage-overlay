# Codex Usage Overlay v1.9.5-preview.1

Fix preview on top of `v1.9.4`. It closes two ways the overlay could disappear and stay gone until the app was restarted.

## Fixed

- **Alt+F4 no longer destroys the overlay.** The overlay has no close button, but it takes keyboard focus whenever the tray shows it. A close request at that moment (Alt+F4, or `taskkill` without `/F`) destroyed the overlay window for good: the app kept running in the tray, but tray clicks did nothing until it was restarted. Close requests on the overlay are now ignored; Hide and Exit stay in the tray and overlay menus.
- **A dead WebView2 no longer leaves the overlay blank.** The overlay is a transparent window, so when its WebView2 content died it stayed "visible" and on top while drawing nothing. Each window now watches its WebView2. A crashed or hung page renderer is reloaded in place, at most once every 30 seconds per window. If the WebView2 browser process exits, which takes the overlay, the settings window and the tray menu with it, the app restarts itself and rebuilds them from the saved state.

## Known limits

- A recovery restart loses what lives only in memory, such as the list of paused Codex chats waiting to be resumed, the same as restarting the app by hand.
- A WebView2 browser-process exit within a minute of launch does not trigger a restart, so a broken WebView2 runtime cannot cause a restart loop. The overlay then stays blank until the app is restarted.
- A recovery restart does not install an update that was prepared for exit. With automatic update checks on, the relaunched app prepares it again.

## Diagnostics

- `scripts/diagnose-overlay-visibility.py` in the repository (not shipped in the packages) tells which kind of "missing" the overlay is: hidden, destroyed, blank WebView2, minimized, cloaked, off-screen, covered, or no longer topmost. It reads physical-pixel coordinates. See `docs/overlay-visibility-diagnosis.md`.

## 中文说明

基于 `v1.9.4` 的修复预览版：堵上两条会让悬浮窗消失、而且只能重启才能恢复的路径。

### 修复

- **Alt+F4 不再销毁悬浮窗。** 悬浮窗没有关闭按钮，但每次从托盘显示时都会获得键盘焦点。此时的关闭请求（Alt+F4，或不带 `/F` 的 `taskkill`）会永久销毁悬浮窗：应用仍在托盘运行，但托盘怎么点都没有反应，直到重启。现在悬浮窗忽略关闭请求，隐藏和退出仍在托盘与悬浮窗菜单中。
- **WebView2 进程退出后悬浮窗不再空白。** 悬浮窗是透明窗口，WebView2 内容失效后它仍"可见"且置顶，却什么也不画。现在每个窗口都会监视自己的 WebView2：页面渲染进程崩溃或无响应时原地重新加载，每个窗口 30 秒内最多一次；WebView2 浏览器进程退出时（悬浮窗、设置窗口和托盘菜单会一起失效），应用自动重启，从已保存的状态重建所有窗口。

### 已知限制

- 恢复性重启会丢失只保存在内存中的状态，例如等待恢复的已暂停 Codex 对话列表，与手动重启相同。
- 启动不到一分钟就发生的 WebView2 浏览器进程退出不会触发重启，以免 WebView2 运行时损坏时反复重启；这种情况下悬浮窗保持空白，需要手动重启。
- 恢复性重启不会安装已准备在退出时安装的更新；开启自动检查更新时，重启后的应用会重新准备。

### 诊断工具

- 仓库中的 `scripts/diagnose-overlay-visibility.py`（不随安装包发布）可以判定悬浮窗"看不见"属于哪一类：隐藏、被销毁、WebView2 空白、最小化、被 cloak、越界、被遮挡或失去置顶，坐标为物理像素。详见 `docs/overlay-visibility-diagnosis.md`。
