# Codex Usage Overlay v1.10.0-preview.3

Fix preview: the Usage history window places window resets at the time the provider reset them.

## Fixed

- **One reset, at the right time.** Just after a reset, Claude and Antigravity report one reading with no reset time before the next window starts. The History window drew that reset twice: once at the old window's reset time and again at the next window's first use. It is now one reset, at the old window's reset time, or when it was seen if the provider reset early.
- **Whole-minute Claude reset times.** Claude's reset times read back a second early on some polls (21:09:59 instead of 21:10:00), so the window table could show 21:09 for a 21:10 reset, and each flip wrote a history line. They are now recorded as the whole minute, and a reset time that moves by under a minute is not a change.
- **Unused Codex windows.** While a Codex window is unused, Codex reports its reset a full window after every read, so the reset moved forward on each poll and a line was written every minute. An unused window is now recorded without a reset time, so an idle stretch only writes the 30-minute heartbeat.
- A reading that loses its reset time while the window is still in use no longer counts as a reset.

Existing history files are read with the same rules, so history recorded by the earlier previews displays correctly without clearing it.

## Verification and limits

- The new rules were run against real Claude, Codex and Antigravity history from an installed `v1.10.0-preview.2`: one 5-hour reset per provider, Claude's at the whole minute, and window start and reset times matching what each provider reported.
- New tests cover a Claude reset through an unused window, an unused Codex window, a reading that loses its reset time and an early Antigravity reset. The full frontend and Rust test suites, the production build and the packaging checks pass locally.
- Not yet checked on the signed installer itself. The History window still opens centred each time and does not remember its size and position.

## 中文说明

本预览版让“用量历史”窗口把额度窗口的重置标在服务商实际重置的时间。

- Claude 和 Antigravity 在重置后、下一个窗口开始前，会先返回一次没有重置时间的读数。此前这次重置会被画两次：一次在旧窗口的重置时间，一次在下一个窗口首次使用时。现在只画一次，位于旧窗口的重置时间；若服务商提前重置，则位于观察到重置的时间。
- Claude 的重置时间有时会早读一秒（21:09:59 而非 21:10:00），导致窗口表格把 21:10 的重置显示为 21:09，且每次跳动都会写入一行。现在按整分钟记录，相差不到一分钟的重置时间也不再视为变化。
- Codex 窗口未使用时，每次读取都会把重置时间报为一个完整窗口之后，导致重置时间不断后移、每分钟写入一行。现在未使用的窗口不记录重置时间，空闲期间只写入每 30 分钟一次的心跳。
- 窗口仍在使用中、只是读数缺少重置时间时，不再算作重置。

已有历史文件按同样规则读取，无需清除。已用已安装的 `v1.10.0-preview.2` 中真实的 Claude、Codex 和 Antigravity 历史数据验证；前端与 Rust 测试、生产构建和打包检查均在本机通过；尚未在签名安装包上实测。
