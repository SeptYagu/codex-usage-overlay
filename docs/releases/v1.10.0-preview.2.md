# Codex Usage Overlay v1.10.0-preview.2

Fix preview: opening the Usage history window no longer freezes the app.

## Fixed

- **Usage history no longer freezes the overlay.** In `v1.10.0-preview.1`, choosing **Usage History…** from the tray menu or the overlay's right-click menu, or **Open usage history** in Settings, froze the app. On Windows, a window built from a synchronous command or a menu event handler deadlocks, and all three entry points did that. The window is now built on a worker thread, and the history commands run off the main thread.

Everything else is unchanged from `v1.10.0-preview.1`, including the usage history recorder, which keeps recording as before.

## Verification and limits

- Checked by hand on a debug build of this source, run with a separate test data folder: the History window opened from the tray menu and from the overlay's right-click menu without freezing, and live Codex and Antigravity readings were written to the history files.
- The full frontend and Rust test suites, the production build and the packaging checks pass locally.
- Not yet checked on the signed installer itself. The History window still opens centred each time and does not remember its size and position.

## 中文说明

本预览版修复打开“用量历史”窗口时整个应用卡死的问题。

在 `v1.10.0-preview.1` 中，从托盘菜单或浮窗右键菜单选择“用量历史…”，或在设置中点击“打开用量历史”，应用会卡死。原因是在 Windows 上，从同步命令或菜单事件处理中创建窗口会造成死锁，而这三个入口都是如此。现在窗口改在工作线程中创建，用量历史相关命令也不再占用主线程。用量历史的记录功能不受影响。

已在本源码的调试版（使用独立的测试数据目录）上手动确认：从托盘菜单和浮窗右键菜单都能正常打开用量历史窗口，且实时读数正常写入历史文件。前端与 Rust 测试、生产构建和打包检查均在本机通过；尚未在签名安装包上实测。
