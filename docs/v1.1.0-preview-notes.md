# v1.1.0 Preview Notes

This preview adds independent five-hour and weekly reset notifications, custom sound selection and preview, and automatic edge docking with a two-bar quota pill. Existing settings are preserved; new settings use the documented defaults.

## Automated checks

- Frontend: 35 tests pass; production build passes.
- Rust: 30 unit tests pass; `cargo check --locked` passes.
- Audio probe: generated MP3, AAC, M4A, and WAV samples decoded and played; a 13-second WAV stopped at the 10-second limit.
- Dock geometry tests cover all four edges, DPI/scale calculations, negative monitor coordinates, snap thresholds, small work areas, collapse locks, and the post-write-back cursor coverage of the expanded window.
- Windows release build: debug build passed. The single-job optimized build passed and produced both installers:
  - NSIS: `src-tauri/target/release/bundle/nsis/codex-usage-overlay_1.1.0_x64-setup.exe` (3.87 MiB)
  - MSI: `src-tauri/target/release/bundle/msi/codex-usage-overlay_1.1.0_x64_en-US.msi` (5.64 MiB)
- Portable build: `cargo build --manifest-path src-tauri/Cargo.toml --locked --release --bin codex-usage-updater` passed. `output/tauri-release/CodexUsageOverlay-v1.1.0-preview-Windows-x64.zip` was created locally (5.56 MiB); all four entries were checked against their source SHA256 hashes. The archive is unsigned.
- Updater signing did not complete: this environment has no `TAURI_SIGNING_PRIVATE_KEY`, so Tauri exited with an error after creating the installers. No updater signature or published release was produced.

## Known limitations (preview)

- Custom-sound notifications use the raw WinRT toast app id `com.codex.usage.overlay` (`notify.rs` `show_toast`). No AUMID shortcut is registered for portable builds, so a toast may play its sound without showing a banner. The spec's `ensure_aumid_shortcut` step is not implemented.
- The tray menu is shown and focused on every measurement (`tray.rs` `layout_tray_menu`). Because Windows may asynchronously re-layout the popup, an already-dismissed menu can be popped up again. A "closed" flag / reject-show-while-hidden guard is not implemented.
- The expanded window cannot cover the whole pill. The capsule is always shorter than the pill along the free axis (306 physical px vs 211 at 175%), so spec §3.4 defines the contract as covering the *cursor's position*: the hover transition writes a rectangle that contains the entire pill, and the authoritative capsule-size write-back then re-places the window so the cursor stays inside it. Whether WebView2 delivers `mouseleave` when a stationary cursor is left outside by a programmatic shrink is still unverified on a visible desktop.
