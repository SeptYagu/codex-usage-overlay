# v1.1.0 多阶段实施方案：额度重置通知、悬浮窗贴边隐藏与托盘菜单修复

> 实施进度：阶段 1–5 已完成并提交；阶段 6 的版本更新、自动化测试、安装包和便携包本地验证已完成。更新器签名与阶段 0 的原生窗口、通知和多显示器实机验证仍未完成，正式发布保持闸门状态，见[验证记录](stage0-verification.md)和[预览说明](v1.1.0-preview-notes.md)。目标平台：Windows 10/11，沿用现有 Tauri v2、React 和 Rust 架构。
>
> 本文中的尺寸、延迟和默认开关状态是待实机验证的设计建议；截图只用于说明贴边小浮窗的视觉方向，不构成额外功能要求。

## 1. 目标与交付范围

本版本交付两组互相独立的功能及一项现有缺陷修复：

1. 5 小时额度、周额度各自拥有重置通知开关和提示音设置。默认采用 Windows 通知及系统提示音；用户可为任一项改用本地 MP3、AAC 或 WAV 音效，单次最多播放 10 秒。
2. 悬浮窗拖至任一屏幕边缘时可自动贴边收起，仅留下类似参考图的双额度小指示窗；鼠标悬停时恢复完整浮窗。托盘菜单提供“自动贴边隐藏”开关。
3. 修复托盘菜单底部大片空白：菜单窗口按实际内容高度收放，保持靠近托盘图标；语言子菜单、更新状态和新增开关改变内容时同步调整。

现有额度读取方式、完整浮窗的两种布局、绿／黄／红阈值、托盘刷新和更新功能继续可用。新功能需兼容安装版与便携版，以及已有的 `settings.json` 和 `window-position.json`。

## 2. 当前基础与实施约束

| 现状 | 对方案的影响 |
| --- | --- |
| 后端已经提供 `fiveHourResetsAt`、`weekResetsAt` 及两个剩余百分比。 | 复用现有数据源，无须新增 Codex 接口。 |
| 用量由后台定时读取，也可由前端和托盘手动读取。 | 所有成功读取必须汇入同一个重置判断入口，避免重复通知。 |
| Windows 通知插件已接入，当前用于更新提醒。 | 可复用权限与通知能力；额度通知逻辑放在后台，不依赖主窗口可见。 |
| 悬浮窗会随内容及 DPI 缩放改变尺寸；每次移动都会保存位置。 | 收起过程中的程序性移动不能覆盖用户保存的展开位置。 |
| 托盘右键打开的是自定义 `tray-menu` 窗口。 | 新开关应加入该菜单，并与设置快照同步。 |
| 托盘菜单窗口当前固定为 300×500 逻辑像素，定位也按 500 高计算；页面根容器使用 `h-screen`。 | 内容少于 500 时在“退出”下方留下大片空白；加入新开关后也不能继续依赖固定高度。 |
| 当前颜色阈值为剩余 ≥50% 绿色、20%–49% 黄色、<20% 红色。 | 小指示窗直接复用同一阈值，未知值用中性色。 |

主要涉及 `src/types.ts`、`src/components/SettingsView.tsx`、`src/components/TrayMenuView.tsx`、`src/components/OverlayView.tsx`、`src/index.css`、`src/i18n.ts`，以及 `src-tauri/src/config.rs`、`commands.rs`、`lib.rs`、`tray.rs`。新增的通知调度、音频播放和贴边状态建议各自独立成模块，避免继续扩大现有入口文件。

## 3. 产品行为约定

### 3.1 通知

- 两个开关彼此独立。建议新安装默认开启，旧设置缺少字段时使用同一默认值。关闭某项时，该项不弹通知、不播放音频；重新开启不补发过去的重置。
- 每项的提示音下拉框为“Windows 默认”和“自定义音效”。两种模式都显示包含额度类型及重置已完成信息的 Windows 通知；自定义模式让系统通知静音，再播放用户音频，避免双重提示音。
- 自定义模式提供文件选择、当前路径展示、清除和试听。扩展名不区分大小写；选择时检查文件存在、格式和可解码性，触发时再次检查。音频文件保持原位，只保存路径，不复制文件内容。
- 试听及正式播放均在 10 秒处停止；文件不足 10 秒自然结束。无效路径、解码失败或播放设备不可用时显示可理解的错误，保留设置以供用户重新选择，不进入反复播放循环。
- 若两个额度同一时刻重置，分别生成两条通知；自定义音效顺序播放，避免同时混响。Windows 拒绝通知权限时不反复弹权限请求，设置中应提示权限状态。

### 3.2 贴边小浮窗

- 托盘开关建议默认关闭，避免升级后改变用户原有摆放方式。启用后，仅在用户拖动完整浮窗并松手时判断吸附；建议吸附距离为距离当前显示器**可用区域**边缘 16 逻辑像素，可在实机检查后调整。
- 左右边缘使用竖向小窗：左条代表 5 小时额度，右条代表周额度；条的长度表示剩余比例，颜色沿用现有阈值。手绘参考图只表达双条布局与贴边方向；实际小窗为规则圆角矩形，底色、边框、透明度、缩放和红黄绿配色与当前完整悬浮窗共用同一套样式，暗色主题保持同等可读性。浅色／深色样张见[技术规格 §3.4](v1.1.0-technical-spec.md#34-四边小浮窗几何与旋转)。
- 上下边缘将整个竖向小窗顺时针旋转 90°，并按旋转后的外接尺寸定位，避免条形被窗口裁切。未知额度显示中性色；0% 显示空量程，不伪装成仍有剩余额度。
- 鼠标进入可见的小窗即展开完整窗口；离开后建议延迟 400 毫秒收起。拖动、右键菜单打开及鼠标仍在展开窗口内时取消收起。关闭托盘开关后立即恢复完整窗口。
- 托盘原有“显示／隐藏悬浮窗”仍控制整个窗口可见性；用户主动隐藏时，小窗也不应留在屏幕边缘。

### 3.3 托盘菜单空白修复

- 托盘菜单窗口高度由实际可见菜单内容决定；底部只保留与顶部接近的正常内边距，不出现大片空白。菜单宽度维持现有布局所需尺寸，文字换行时高度随之增加。
- 打开／收起语言列表、显示更新检查结果或安装进度、安装版与便携版显示不同条目，以及切换界面语言后，都重新测量并调整窗口高度；新增“自动贴边隐藏”项也纳入测量。
- 每次调整高度后，依据托盘图标所在显示器的可用工作区重新定位，使菜单紧贴任务栏一侧且不会跑出屏幕。若内容超过可用高度，限制窗口高度并允许菜单内部滚动；避免首次打开时先显示固定高度再明显跳动。

## 4. 分阶段实施

### 阶段 0：确认交互与技术可行性

**工作**：用当前版本实测主窗口拖动、窗口移动事件、DPI 变化、四边工作区位置；验证选定的 Windows 音频播放方案能解码 MP3、AAC、WAV 并可靠停止于 10 秒。绘制四边的展开／收起状态图，确定通知权限被拒时的界面提示。

**交付**：一页交互规格和技术选型记录；明确文件选择器、音频解码与停止控制的实现途径。

**完成条件**：三种格式各有一个可播放样本；四边可见区域和鼠标命中区域的定位方案经过 Windows 实机验证。若某方案不能可靠处理 AAC，应在编码前更换方案。

### 阶段 1：设置模型与界面

**工作**：前后端同时加入 `fiveHourResetNotification`、`weeklyResetNotification`、各自的音效模式和音频路径，以及 `autoEdgeHide`。设置页将两种额度做成独立配置区；路径仅在自定义模式下可编辑。托盘菜单加入带勾选状态的“自动贴边隐藏”，同时修复固定 500 像素高度造成的底部空白，改为按可见内容调整高度和位置。补齐简体中文、繁体中文、英文文案。

**交付**：可读写、可跨窗口同步的新设置；旧设置文件迁移测试；设置界面与托盘开关；无大片空白的自适应托盘菜单。

**完成条件**：旧设置加载后原有偏好不变；两个通知设置互不覆盖；托盘和设置页修改能立即同步，重启后保持一致。对连续快速修改须防止旧的异步保存结果覆盖较新的设置。托盘菜单在折叠与展开语言列表、更新状态变化及不同语言下均贴合内容，屏幕边缘不裁切。

### 阶段 2：重置判断和一次性通知

**工作**：抽出统一的用量成功处理流程，让后台轮询、主窗口手动刷新和托盘刷新共用。为每个额度保存上次已观察的 `resetsAt` 和上次已处理的周期标识，单独持久化到本地运行状态文件。到达预计时间后安排一次读取；只有读到有效的新周期，才触发通知。首次看到某个周期只建立基线，不误报历史重置。

**交付**：独立通知调度模块、周期状态持久化、Windows 通知内容和权限处理。

**完成条件**：每项每周期最多处理一次；手动刷新与后台读取同时完成、应用重启、系统睡眠后恢复都不会重复通知。缺失重置时间、读取失败或电脑时钟变化不会产生虚假的“已重置”通知。

### 阶段 3：自定义音效

**工作**：接入本地文件选择与音频播放；选择和运行时进行格式及可解码性检查；正式通知与试听共用 10 秒上限和停止清理逻辑。连续重置事件按顺序播放，退出程序时停止并释放音频资源。

**交付**：两项独立音效路径、试听按钮、错误提示和播放队列。

**完成条件**：MP3、AAC、WAV 都通过真实文件验证；短音频正常结束，长音频 10 秒内停止；路径失效不会阻止另一个额度的通知，也不会造成循环报错。

### 阶段 4：贴边状态与窗口定位

**工作**：建立“自由展开、贴边收起、悬停展开、手动隐藏”状态及左／右／上／下方向。依据当前显示器工作区、窗口实际尺寸和 DPI 计算位置。分别维护用户拖动锚点和程序动画位置；程序移动不写入用户位置文件。对窗口缩放、余额显示切换、屏幕布局变化重新计算贴边坐标。

**交付**：四边吸附和恢复行为、可靠的位置保存、多显示器与任务栏避让。

**完成条件**：四边可吸附且不被裁切；收起后可见部分始终能被鼠标指到；重启可恢复原边缘和锚点；关闭自动贴边隐藏时回到正确的展开位置。

### 阶段 5：小浮窗视觉和交互

**工作**：实现双条指示窗、比例填充、三色规则、未知状态、顺时针旋转和浅／深色主题。加入悬停展开、离开延迟收起与拖动／菜单期间的状态锁。检查与两种完整布局、100%–250% 缩放和背景透明度的组合。

**交付**：与参考图方向一致的四边小浮窗及流畅交互。

**完成条件**：5 小时与周额度不会混淆；红黄绿在四边和两种主题下可辨；悬停不闪烁，鼠标可以从小窗顺畅移入完整窗口；完整窗口仍可拖动和打开右键菜单。

### 阶段 6：回归、预览版与发布

**工作**：更新中英文 README、设置说明和版本号。运行前端测试、构建、Rust 测试，并按 `RELEASING.md` 完成 Windows 实机检查及安装版、便携版预览包验证。先发预览版，重点观察通知可靠性、音频兼容性和多显示器位置问题；修正后再发布正式版。

**交付**：测试记录、预览版发布说明、最终 v1.1.0 安装包与便携包。

**完成条件**：下方验收矩阵通过；签名、更新元数据、安装与便携启动检查符合现有发布流程。

## 6. 主要风险和处理

1. **音频格式兼容**：文件扩展名不能证明能解码。阶段 0 用真实 AAC、MP3、WAV 样本验证所选播放实现；阶段 3 在选择时与播放时均检查。
2. **通知重复或漏报**：多个刷新入口和睡眠唤醒会造成竞态。统一后端处理入口，并以持久化的周期标识去重；通知失败也记录本周期处理结果，避免无限重试，并允许下一周期再次尝试。
3. **窗口坐标漂移**：现有窗口移动监听会记录程序性移动。阶段 4 明确区分用户拖动与程序定位，持久化展开锚点，不持久化动画中间位置。
4. **Windows 提示限制**：系统可能因通知权限、勿扰模式或声音设备状态抑制提示。设置页展示可操作的状态或错误；不声称应用能绕过系统策略。
5. **托盘菜单尺寸与定位不同步**：菜单内容、语言和 DPI 会改变真实高度。阶段 1 用内容测量驱动尺寸，尺寸确定后按托盘图标与工作区定位；内容变化时重复计算，超高时限定高度并滚动。

## 7. 开发顺序与版本闸门

阶段 0 是技术闸门；阶段 1 完成后，阶段 2 与阶段 4 可分别推进；阶段 3 依赖阶段 2，阶段 5 依赖阶段 4；阶段 6 汇总验收。每个阶段完成时检查改动、运行相称测试并形成独立提交。预览版通过真实 Windows 环境的四边贴边与音频检查后，才进入正式发布。

预计实施量为 **6–10 个工作日**，取决于阶段 0 的音频兼容性和多显示器验证结果；此数字用于排期，不替代验收条件。
