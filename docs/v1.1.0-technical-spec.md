## 2. 核心难点一：音频播放与控制（阶段 0 验证 / 阶段 3 落地）

### 2.1 选型论证

**候选方案对比：**

| 方案 | MP3 | AAC | WAV | 停止控制 | 体积/复杂度 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| rodio 0.22.2 + symphonia（纯 Rust） | ✅ symphonia-mp3 | 阶段 0 验证 symphonia-aac + isomp4 | ✅ symphonia-wav + pcm | `Player::stop()` 与 `Source::take_duration`，主动队列控制 | 单一依赖树，MPL-2.0（symphonia） | **有条件选用** |
| rodio + minimp3/hound 默认后端 | ✅ | ❌（AAC 默认禁用，仅 symphonia 支持） | ✅ | 同上 | — | 否决（计划文档明确要求 AAC 可靠） |
| Windows Media Foundation（`windows` crate COM） | ✅ | ✅ | ✅ | 可控但需 IMFMediaSession 状态机 | COM/STA、回调线程、错误处理复杂；便携版依赖系统编解码器 | 否决（复杂度不成比例） |
| 前端 HTMLAudioElement | 依赖 WebView2 编解码 | ✅（WebView2 一般支持） | ✅ | 简单 | 主窗口隐藏/销毁时行为不可控；透明置顶窗口的 webview 音频生命周期难管理 | 否决（后台通知播放不依赖窗口可见是硬需求） |

### 2.2 `audio.rs` 模块设计

为使播放不受主窗口可见性和异步命令生命周期影响，使用**专职播放线程 + 命令通道**。此隔离是生命周期设计，不预设 `Player` 的 `Send` 属性；阶段 0 验证所需跨线程类型和设备恢复行为：

```rust
// src-tauri/src/audio.rs
use std::path::PathBuf;
use std::time::Duration;

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "camelCase")]
pub enum QuotaKind { FiveHour, Week }

#[derive(Debug)]
pub enum AudioError {
    PathMissing,          // 文件不存在
    Undecodable(String),  // 扩展名合法但解码失败
    DeviceUnavailable,    // 无音频输出设备
    Busy,                 // （试听专用）通道关闭等内部错误
}

/// 可解码性预检结果（阶段 3 选择文件时与触发播放前各调用一次）
pub struct ProbeInfo { pub container: &'static str }  // "mp3" | "aac-adts" | "m4a" | "wav"

/// 打开文件并流式解码前若干帧；不整读文件进内存（BufReader 流式）。
pub fn probe_audio(path: &PathBuf) -> Result<ProbeInfo, AudioError>;

enum AudioCommand {
    /// 正式通知播放：加入工作线程的高优先级队列，10s 上限。
    Enqueue { path: PathBuf, kind: QuotaKind },
    /// 试听排在正式通知之后，不清空另一额度的待播通知。
    Preview { path: PathBuf, reply: mpsc::Sender<Result<(), AudioError>> },
    StopPreview,
    Shutdown,
}

#[derive(Clone)]
pub struct AudioHandle { tx: std::sync::mpsc::Sender<AudioCommand> }

impl AudioHandle {
    pub fn enqueue_notification(&self, path: PathBuf, kind: QuotaKind);
    pub fn preview(&self, path: PathBuf) -> Result<(), AudioError>;
    pub fn stop_preview(&self);
    pub fn shutdown(&self);  // exit_app 前调用
}

/// 在 setup 阶段启动工作线程并挂到 AppState（OnceLock<AudioHandle>）。
pub fn spawn_worker() -> AudioHandle;
```

**工作线程内部结构（单线程拥有全部音频资源）：**保留一个 `VecDeque<AudioJob>` 和一个当前播放项；正式通知按到达次序排列，试听排在已收到的通知之后。线程用有界接收等待结合播放完成检测推进队列。`StopPreview` 只取消尚未开始的试听，或停止当前试听后创建新 `Player`，不得清空正式通知。设备打开失败时当前项报错，下一项可重新尝试打开设备。

```rust
// 伪代码：启动时不强制打开设备；处理每个 AudioJob 时按需打开/恢复设备。
// 仅当前播放项调用 player.append(load_limited_source(path)?);
// player.empty() 后取下一项；需要取消当前试听时 player.stop() 并重新建 Player。
// Shutdown 停止当前项，清空内部队列并让设备/Player 随线程退出释放。

/// 统一的「10 秒上限」包装点：试听与正式播放共用。
fn load_limited_source(path: &PathBuf) -> Result<impl rodio::Source + Send + 'static, AudioError> {
    if !path.is_file() { return Err(AudioError::PathMissing); }
    let file = std::fs::File::open(path).map_err(|_| AudioError::PathMissing)?;
    let src = rodio::Decoder::try_from(file)
        .map_err(|e| AudioError::Undecodable(e.to_string()))?;
    Ok(src.take_duration(Duration::from_secs(10)))
}
```

设计要点：

1. **10 秒截断的唯一实现点**是 `load_limited_source` 里的 `take_duration`。文件不足 10 秒自然结束（`take_duration` 在源耗尽时提前结束）。不依赖 `Source::total_duration()`（rodio issue #190：该函数对非 WAV 源不一定可靠），因此**不需要**预知时长。
2. **防混响/顺序队列**：工作线程只播放一个当前项；5 小时额度与周额度同刻重置时，`notify.rs` 依固定顺序（先 fiveHour 后 week）各 `Enqueue` 一次，绝不并发出声。
3. **试听与正式通知独立管理**：试听排在正式通知之后，不清除另一额度的待播音效；`StopPreview` 只影响试听。`Player::clear()` 会使播放器暂停，不用于这一流程。试听命令通过回复通道返回路径、解码或设备错误。
4. **退出释放**：`exit_app` 命令（commands.rs:216-218）改为先 `audio.shutdown()` 再 `app.exit(0)`；后台线程停止当前项并释放播放器与设备。窗口关闭和其他退出路径也须共用清理逻辑。
5. **播放设备不可用**：打开设备失败时仅当前项报错，不 panic；下一项可尝试恢复设备。错误由工作线程转成 `sound_playback_error` 事件，设置页展示后用户可重新选择。
6. **路径失效不影响另一额度**：`Enqueue` 失败只上报该 `kind` 的错误，队列继续。

### 2.3 文件选择与格式校验（`pick_sound_file`）

```rust
// commands.rs
#[tauri::command]
pub async fn pick_sound_file(kind: QuotaKind, app: AppHandle) -> Result<Option<String>, String> {
    use tauri_plugin_dialog::DialogExt;
    let picked = tokio::task::spawn_blocking(move || {
        app.dialog().file()
            .add_filter("音频文件 (MP3/AAC/WAV)", &["mp3", "aac", "m4a", "wav"])
            .blocking_pick_file()
    }).await.map_err(|e| e.to_string())?;           // 阻塞选择器不占用异步执行线程
    let Some(p) = picked else { return Ok(None) };   // 用户取消 → None，前端不动当前值
    let path = p.into_path().map_err(|e| e.to_string())?; // Windows 文件路径，不把 URI 当路径

    // 校验链：扩展名（不区分大小写）→ 文件存在 → 可解码预检
    let ext = path.extension().and_then(|e| e.to_str()).map(|e| e.to_ascii_lowercase());
    match ext.as_deref() {
        Some("mp3" | "aac" | "m4a" | "wav") => {}
        _ => return Err("unsupported_format".into()),
    }
    audio::probe_audio(&path).map_err(|e| e.to_string())?;   // Undecodable → 前端报「无法解码」

    Ok(Some(path.to_string_lossy().into_owned()))    // 音频文件保持原位，只存路径
}
```

- 选择时预检（本命令）+ **触发时再次校验**：`load_limited_source` 内部 `path.is_file()` + 解码即运行时复检（§2.2）。
- 扩展名只做粗筛，**可解码性以 `Decoder` 实测为准**（扩展名不能证明能解码，计划风险 #1）。
- 音频文件保持原位，仅保存绝对路径字符串到 `settings.json`，不做复制（符合计划 §3.1）。

### 3.1 状态机定义

```rust
    Free,            // 自由展开（未贴边，或贴边功能关闭）

pub struct DockRuntime {
    pub state: DockState,
    pub expanded: bool,          // 仅 Docked 状态有意义：true=悬停展开的完整浮窗
    pub dragging: bool,          // 拖动锁
    pub menu_open: bool,         // 右键菜单锁

}
```

### 3.2 Work Area 与多显示器、DPI 几何

复用 F7 已使用的 Tauri API（物理像素语义；Windows 工作区结果仍须由阶段 0 实机确认）：

```rust
// dock.rs 内部工具：取「窗口中心点所在显示器」的物理工作区
fn work_area(window: &tauri::WebviewWindow) -> Option<(i32, i32, u32, u32)> {
    // 先按窗口中心点判定目标显示器；再退化到 current_monitor()。
    let monitor = (|| {
        let pos = window.outer_position().ok()?;
        let size = window.outer_size().ok()?;
        let cx = pos.x + size.width as i32 / 2;
        let cy = pos.y + size.height as i32 / 2;
        window.monitor_from_point(cx as f64, cy as f64).ok().flatten()
    })().or_else(|| window.current_monitor().ok().flatten())?;
    let wa = monitor.work_area();   // 物理像素（tray.rs:107 已用）
    Some((wa.position.x, wa.position.y, wa.size.width, wa.size.height))
}
```

- **DPI 处理原则：所有几何判定与落位都在物理像素域完成**（`outer_position`/`outer_size`/`work_area` 全是物理值）。逻辑像素只出现在两处：吸附阈值（§3.3）与小浮窗 CSS 尺寸（§3.5），两者经 `monitor.scale_factor()`（100%→1.0，175%→1.75，250%→2.5）换算。
- 跨 DPI 多显示器：窗口移动到另一台显示器时 Tauri 会发 `ScaleFactorChanged`；`dock.rs` 在监听器里对 `Docked` 状态重算一次落位（阶段 4 交付项「屏幕布局变化重新计算」）。

### 3.3 16 逻辑像素吸附判定

```rust
pub const SNAP_MARGIN_LOGICAL: f64 = 16.0;

/// 拖动结束时调用：返回命中的边（多边同时命中取物理距离最小者）。
pub fn detect_edge(
    win: (i32, i32, u32, u32),   // 窗口物理 rect（outer_position/outer_size）
    wa:   (i32, i32, u32, u32),  // 工作区物理 rect
    scale_factor: f64,
) -> Option<Edge> {
    let t = (SNAP_MARGIN_LOGICAL * scale_factor).round() as i32;  // 16 逻辑 px → 物理
    let (x, y, w, h) = win;
    let (wx, wy, ww, wh) = (wa.0, wa.1, wa.2 as i32, wa.3 as i32);
    let d_left   = x - wx;
    let d_right  = (wx + ww) - (x + w as i32);
    let d_top    = y - wy;
    let d_bottom = (wy + wh) - (y + h as i32);
    let cands = [
        (d_left, Edge::Left), (d_right, Edge::Right),
        (d_top, Edge::Top), (d_bottom, Edge::Bottom),
    ];
    cands.into_iter()
        .filter(|(d, _)| d.abs() <= t)   // 允许轻微越界；远离边缘的负数不得命中
        .min_by_key(|(d, _)| d.abs())     // 多边同时命中时取绝对距离最小者
        .map(|(_, e)| e)
}
```

吸附判定只发生一次：**拖动松手时**（计划 §3.2「仅在用户拖动完整浮窗并松手时判断吸附」）。挂接点见 §3.6。

### 3.4 四边小浮窗几何与旋转

**常量（100% 缩放时的逻辑像素，阶段 0 可调）：**

```rust
pub const PILL_W: f64 = 46.0;   // 左右边缘：竖向小窗宽（左右条 + 间距 + 内边距）
pub const PILL_H: f64 = 100.0;  // 竖向小窗高
pub const BAR_WIDTH: f64 = 9.0; // 单条宽度
pub const BAR_GAP: f64 = 6.0;   // 双条间距
pub const PILL_PADDING_X: f64 = 11.0; // 46 = 11 + 9 + 6 + 9 + 11
pub const PILL_PADDING_Y: f64 = 14.0; // 100 = 14 + 72（量程）+ 14
pub const EDGE_INSET: f64 = 2.0; // 逻辑像素；计算物理位置时乘 scale_factor
```

**定位公式（物理像素；`sf = monitor.scale_factor()`，`s = settings.scalePercent / 100`，`I = round(EDGE_INSET·sf)`，`(wx, wy, ww, wh)` 为工作区）：**

设窗口松手锚点中心为 `(ax, ay)`（拖动结束时窗口物理中心）：

| Edge | 小浮窗物理尺寸 `(W×H)` | 落位 `x` | 落位 `y` |
| --- | --- | --- | --- |
| Left | `round(PILL_W·sf·s) × round(PILL_H·sf·s)` | `wx + I` | `clamp(ay − H/2, wy, wy + wh − H)` |
| Right | 同上 | `wx + ww − W − I` | 同 Left 的 y |
| Top | `round(PILL_H·sf·s) × round(PILL_W·sf·s)`（**外接尺寸互换**） | `clamp(ax − W/2, wx, wx + ww − W)` | `wy + I` |
| Bottom | 同 Top | 同 Top 的 x | `wy + wh − H − I` |

**旋转的实现分工：**

- **窗口系统层不做任何旋转**（Windows 无窗口级旋转 API；DWM 旋转层不可靠）。窗口始终是轴对齐矩形。
- 旋转完全由**前端 CSS** 完成：`OverlayView` 收到 `dock_state_changed` 后渲染小浮窗分支，Top/Bottom 时对内层元素施加 `transform: rotate(90deg)`（顺时针），并明确旋转原点及外接尺寸。Rust 按上表将窗口宽高互换；阶段 5 实测边框不裁切。
- 左边缘竖窗内部：左条 = 5h、右条 = 周额度（`flex-direction: row`）；Top/Bottom 旋转后视觉上成为横向双条。
- 小窗跟随现有 `scalePercent` 与 `dprComp` 补偿，Rust 的目标物理尺寸与前端绘制后的外接尺寸必须一致；缩放或跨 DPI 显示器后重新计算尺寸和落位。工作区比缩放后小窗还小时，先限制尺寸再夹紧位置，避免 `clamp` 的上下界倒置。

| --- | --- | --- |
| 浅色 | ![浅色左右贴边小窗示意](assets/edge-pill-vertical.svg) | ![浅色上下贴边小窗示意](assets/edge-pill-horizontal.svg) |
| 深色 | ![深色左右贴边小窗示意](assets/edge-pill-vertical-dark.svg) | ![深色上下贴边小窗示意](assets/edge-pill-horizontal-dark.svg) |

实际小窗在 React/CSS 中绘制双条。实现时把目前作用在 `.overlay-capsule` 的主题变量提取到完整窗与小窗共用的容器／类，两者共用 `--overlay-surface`、`--overlay-border`、`--overlay-rule`、`--overlay-healthy`、`--overlay-warning`、`--overlay-low`；背景仍用 `rgba(var(--overlay-surface), var(--overlay-alpha))`，透明度、浅/深主题和缩放均继承现有设置。不要单独写一套小窗颜色或使用样张 SVG 作运行时背景。填充长度按各自剩余百分比变化，颜色沿用 ≥50% 绿、20%–49% 黄、<20% 红阈值，未知值用中性色，0% 为空量程。左右边缘复用竖向组件，上下边缘顺时针旋转同一个组件。小窗只省略文字与倒计时；悬停后恢复当前完整浮窗布局和字体，收起／展开过渡保留相同边框观感。

**展开恢复与两阶段覆盖契约**：展开以 `window-position.json` 锚点 `(left, top)`（物理 px，与 v1.0.1 存储格式一致）为基准，不仅在显示器拔出时才夹紧。`mouse_enter` 在临时改尺寸**之前**记下进入小浮窗那一刻的鼠标点 `entered_cursor = window.cursor_position()` 与 `anchor_center`（= 松手时窗口物理中心），二者构成这次展开会话的**会话锚点**，本次会话全程复用、不再变更。

随后是两阶段覆盖契约（`W×H` = 当前窗口物理尺寸，`(wx, wy, ww, wh)` = 工作区）：

1. **过渡期（临时尺寸）**：`set_full_size` 写入的临时尺寸不小于当前小浮窗（两轴各取 `max(估算值, 当前窗口尺寸)`），`transition_rect` 让贴边轴紧贴工作区边缘（`Left → wx`、`Right → wx+ww−W`、`Top → wy`、`Bottom → wy+wh−H`），自由轴以 `anchor_center` 居中并夹紧工作区。故该矩形**恒包含整个小浮窗**。
2. **真实尺寸回写后**：胶囊在自由轴上恒比小浮窗短（左/右小浮窗高 `PILL_H`=100 逻辑 px ≈ 内容未变换盒 69 CSS px 的 1.45 倍；175% 下即 306 对 211 物理 px），**任何尺寸的展开窗都无法覆盖整个小浮窗**。故本阶段的契约是**会话级锚定**：`docked_expanded_final_rect` 让贴边轴仍紧贴边缘，自由轴先以 `anchor_center` 居中，再以**会话进入点 `entered_cursor`**（进入小浮窗那一刻记录、会话内恒定）为目标把该轴位置夹紧到 `[entered_cursor − 尺寸 + 1, entered_cursor − 1]`（留 1 物理 px 安全边距），最后整体夹紧工作区（进入点位于工作区内且窗口不超过工作区时，覆盖位置必然存在）。系统未在进入时提供鼠标坐标（`entered_cursor = None`）时退化为纯 `anchor_center` 居中夹紧。

展开态的**所有**程序性落位——前端 `fitCapsuleSize` 回写触发的 `window_resized`，与用量刷新/设置变更触发的 `keep_docked_in_work_area`——都走同一函数，且该函数**只以会话进入点 `entered_cursor` 为鼠标输入、绝不重新读取实时鼠标坐标**：`Hover` 在进入时记录一次并在整个会话内保持不变，会话结束（收起或会话重置）时清空。因此落位是**会话级锚定且完全幂等**的——对同一 (边, 尺寸, 锚点, 进入点) 恒得**同一矩形**，两条路径不会互相拉扯，后台重排既不会按当前鼠标位置搬动已展开窗口，也不会把仍在窗口内的鼠标甩出窗口。注意不得改用「鼠标是否仍在小浮窗命中区内」之类的实时开关：展开胶囊（175% 下 871 物理 px 宽）远宽于小浮窗命中区（141），任何此类开关都会在会话内被反复跨越，使落位重新依赖实时鼠标而失去幂等性。此外 `mouse_enter` 会置一个有界的 `awaiting_resize` 让位标志（1.5 s 租约；`window_resized` 到达即释放，即使该回写丢失也会自行到期），期间 `keep_docked_in_work_area` 直接早退。前端恢复完整胶囊渲染后由 `fitCapsuleSize` 接管尺寸。

### 3.5 展开与收起的程序性移动（尺寸先变、位置后定）

```rust
impl DockManager {
    /// 收起：按 §3.4 公式落位。锚点仅由显式用户拖动结束路径写入。
    pub fn collapse(&self, window: &WebviewWindow, edge: Edge, anchor_center: (i32, i32)) -> Result<()> {
        let sf = window.current_monitor()?.map(|m| m.scale_factor()).unwrap_or(1.0);
```

### 3.6 用户锚点解耦：程序性移动绝不写入 `window-position.json`

现状问题：lib.rs:122-133 的 `Moved` 监听器把一切移动都持久化（F6）。**不再按每次 `Moved` 写入锚点**，也不靠固定 500ms 抑制窗口猜测事件来源。只在确认用户拖动结束的路径读取 `outer_position()` 并保存一次；程序性收起、展开和显示器夹紧不走此路径。`Moved` 事件保留给显示器归属更新等无需落盘的逻辑。

1. **把拖动入口接通**：当前 `data-tauri-drag-region` 触发的是 Tauri 内建行为，自定义 `commands::start_dragging` 不会被调用。阶段 4 将完整浮窗的拖动区域改为显式 `onMouseDown`（主键、非双击时 `invoke('start_dragging')`），并移除同一区域的 `data-tauri-drag-region`，防止重复启动拖动。保留原有右键菜单与双击保护。
2. **确认松手语义再保存**：命令设置 `dragging=true`，调用 `window.start_dragging()`，在阶段 0 验证其 Windows 返回时机；若返回即松手，读取最终 `outer_position()`，无论正负坐标都保存，随后检测吸附。若实测提前返回，使用 Windows 原生拖动结束事件（如 `WM_EXITSIZEMOVE`）完成同样的保存与检测；不能以 150ms `Moved` 静默代替真正的松手，因为慢速拖动会被误判。
3. **程序移动不落盘**：T1 命中吸附时先保存用户松手坐标，再收起。悬停展开、贴边收起和显示器变化重定位只修改实际窗口位置，不改 `window-position.json`。
4. **负坐标可保存**：左侧或上方副屏的坐标可能同时为负数，删除现有 `pos.x > 0 || pos.y > 0` 守卫；初始化恢复与用户拖动通过明确的状态区分。手动隐藏不写锚点。

### 3.7 悬停延迟与状态锁的定时器归属

- **定时器全部在 Rust 侧**：webview 定时器在后台节流不可靠，且锁状态（dragging/menu_open）由 Rust 统一管理。每次进入或离开都更新鼠标状态并取消旧定时器；新定时器期满后重新读取状态，不能只依赖一个不会变化的 `wait_unlocked()` future。
- 前端仅上报两个原子事件：`mouseenter → invoke('dock_mouse_enter')`、`mouseleave → invoke('dock_mouse_leave')`。`OverlayView` 根容器 `onMouseEnter/onMouseLeave`（docked 模式下整个窗口即小浮窗，无命中歧义）。
- `tokio::select!` 结构：

### 3.9 与托盘/右键菜单的交互约束

- 托盘「显示/隐藏悬浮窗」（`toggle_main_window`，tray.rs:135-146）语义不变，但隐藏时置 `ManualHidden`、显示时走 T9，避免「小窗残留在屏幕边缘」（计划 §3.2）。

- 关闭 `auto_edge_hide`（T7）由 `patch_settings` 统一驱动，成功落盘后立即恢复完整窗口到锚点；各窗口经 `settings_updated` + `dock_state_changed` 同步。

### 4.3 防竞态：`patch_settings` 字段级合并

现状隐患：SettingsView 与 TrayMenuView 都发**全量快照**（F10）。用户在托盘快速切换语言的同时设置页保存缩放，两个全量写按到达顺序互相覆盖（后写者持旧快照）。新入口须保留现有 `save_settings` 的托盘 tooltip/icon、设置窗口标题和“刚开启自动更新时立即检查”等副作用，并为 `autoEdgeHide` 增加状态转换副作用。

```rust
// commands.rs 新增
#[tauri::command]
pub async fn patch_settings(
    patch: serde_json::Value,
    state: State<'_, Arc<AppState>>,
    app: AppHandle,
) -> Result<OverlaySettings, String> {
    let changes = validate_whitelisted_patch(&patch)?; // 先验证整个补丁，不能边改边验证
    let (merged, revision) = {
        let mut settings = state.settings.lock().await;
        let mut next = settings.clone();
        apply_changes(&mut next, &changes);
        state.config_manager.save_settings_checked(&next)?; // 写入失败返回错误，不发布假成功快照
        *settings = next.clone();
        let revision = state.next_settings_revision();
        (next, revision)
    };
    apply_settings_effects(&app, &state, &merged, &changes).await;
    let _ = app.emit("settings_updated", SettingsEnvelope { revision, settings: merged.clone() });
    Ok(merged)
}
```

- **事务性**：`validate_whitelisted_patch` 在取得锁前校验每个已提供字段的类型和取值范围；未知键返回错误。只对 `next` 副本应用，持锁写入成功后才替换内存设置。`ConfigManager` 的保存接口需返回错误，不能继续静默吞掉写入失败。
- **顺序**：字段级补丁在同一 `settings` Mutex 内合并、落盘并递增 revision。`settings_updated` 改为带 revision 的完整快照；前端丢弃比已应用 revision 更旧的事件，防止释放锁后的异步副作用使广播乱序。`get_settings` 的初次读取也返回同一 revision 语义。
- **副作用**：`apply_settings_effects` 复用原 `save_settings` 的 tooltip/icon、标题和自动更新处理；阶段 4 加入 `autoEdgeHide` 改变时的展开/收起状态转换。若副作用可能失败，应有可见错误或回滚方案，不把已保存设置与窗口状态长期留在不一致状态。
- **防抖**：只对缩放、透明度等高频滑块做 250ms 合并；通知开关、音效模式/路径、语言和托盘开关立即提交。设置窗口关闭或卸载时冲刷待提交滑块补丁。各视图提交本次变化字段，不再发送旧全量快照。
- **收敛写入口**：旧 `save_settings` 不再接受前端全量快照；`set_autostart` 等内部更新也走同一合并和广播逻辑。

### 4.6 托盘菜单底部空白修复（阶段 1）

**定位**：F16 中的 500 逻辑像素同时用于创建窗口和计算弹出位置；`TrayMenuView` 的 `h-screen` 把背景铺满该窗口。截图中“Exit Overlay”以下的区域属于窗口本身，并非多出的菜单项。新增“自动贴边隐藏”只会增加一行，不能根治固定高度造成的空白。

**尺寸来源**：菜单宽度先保持 300 逻辑像素；高度由真实菜单 DOM（含外层上下内边距）的渲染尺寸决定，不设固定 500 高。根容器移除 `h-screen`，内容容器加 `ref` 和 `ResizeObserver`；首次完成渲染及字体就绪后测量非零高度。语言列表展开／收起、切换语言、异步 `isInstalled` 结果、更新提示与安装进度，以及本次新增的开关都会触发重新测量。不要靠菜单项数量乘固定行高，因为翻译换行和 Windows 文本缩放会改变实际高度。

**窗口调整流程**：前端将测得的 CSS 像素高度与本次打开序号发给 Rust；按现有完整浮窗的 `dprComp = devicePixelRatio / window.scaleFactor()` 思路换算为 Tauri 逻辑尺寸，再换算为物理尺寸。`tray.rs` 在同一条调整流程内先限制目标高度不超过托盘图标所在显示器的 `work_area`（留出边距），再设置窗口高度、根据**新高度**重算靠近图标的位置，最后显示或更新已显示窗口。首次打开要等有效测量后再显示，避免先出现 500 高窗口再跳动；重新打开隐藏窗口也重新测量，旧序号的迟到结果不得覆盖新尺寸。保留尺寸变更后的 `clamp`，支持负坐标副屏和四侧任务栏。

**内容过高**：超过工作区上限时只让菜单内容区 `overflow-y: auto`；窗口自身不越界，底部“退出”项可滚动到。宽度与滚动条导致文字换行时，测量与调整需收敛，避免 `ResizeObserver` 与窗口调整互相反复触发。最小高度只容纳实际条目与正常内边距，不额外保留空白。

**验收**：默认菜单底部留白与顶部内边距接近；展开语言列表和更新状态变化后窗口立即贴合内容；简中／繁中／英文、安装／便携、100%／175%／250% DPI、任务栏四边及副屏都不裁切。内容高于工作区时才出现内部滚动条。可将测量值与最终窗口 `inner_size()` 记录在阶段 1 的实机检查中，防止 CSS 高度与 Tauri 逻辑像素换算不一致。

### 5.1 统一用量成功处理入口

把 F2 的两份重复成功处理合并为一个函数，`notify` 的去重判断挂在其尾部：

```rust
pub async fn process_usage_success(app: &AppHandle, state: &Arc<AppState>, usage: &CodexUsage) {
```

### 5.2 周期状态持久化：`reset-state.json`

`ConfigManager` 新增 `reset_state_path()` → `%LOCALAPPDATA%\CodexUsageOverlay\reset-state.json`：

```json
{
  "fiveHour": { "lastSeenResetsAt": 1790536584, "lastHandledBoundary": null },
  "weekly":   { "lastSeenResetsAt": null,       "lastHandledBoundary": null }
}
```

- `lastSeenResetsAt`：上次有效读取所报告的**下一次**重置时间，是待跨越的周期边界。
- `lastHandledBoundary`：已经处理过的**旧** `resetsAt` 边界；无论通知开关关闭或发送失败都记账，避免重新开启后补发旧事件。字段名不用 `notified`，因为它不保证系统实际显示了通知。
- 写入走 `.tmp + rename` 并返回错误；进程内持有 `Mutex<ResetStateFile>` 缓存。先可靠保存“已处理”，再尝试发通知；若状态写入失败则不发送，避免重启后重复。系统通知的显示结果仍受 Windows 控制，不能承诺绝对送达。

### 5.3 去重判断核心（伪代码级）

```rust
async fn maybe_notify_cycle(app, state, kind, new_resets_at: Option<i64>,
                            enabled: bool, mode: SoundMode, sound_path: Option<String>) -> Result<(), NotifyError> {
    let Some(new_resets_at) = new_resets_at else { return Ok(()) };
    let now = unix_now();
    let mut st = state.reset_state.lock().await;
    let mut next = st.clone(); // 磁盘写入失败时保持内存旧状态，下次读取可重试
    let cyc = next.slot_mut(kind);
    let old = cyc.last_seen_resets_at;

    // 首次有效读取只建立基线，但仍须安排该时间到期后的主动补读。
    if old.is_none() {
        cyc.last_seen_resets_at = Some(new_resets_at);
        save_checked(&next)?;
        *st = next;
        drop(st);
        schedule_post_reset_fetch(app, kind, new_resets_at);
        return Ok(());
    }
    let old = old.unwrap();
    if new_resets_at == old {
        drop(st);
        schedule_post_reset_fetch(app, kind, new_resets_at); // 重启后重建未来定时器
        return Ok(());
    }

    // 旧边界已到期 + 服务端返回更晚的下一次重置时间，才确认跨周期。
    let crossed = old <= now && new_resets_at > old;
    let already_handled = cyc.last_handled_boundary == Some(old);
    cyc.last_seen_resets_at = Some(new_resets_at);
    if crossed { cyc.last_handled_boundary = Some(old); }
    save_checked(&next)?;  // 先持久化，再提交内存并发通知；保存失败不发
    *st = next;
    drop(st);

    if crossed && !already_handled && enabled {
        emit_quota_reset(app, kind, mode, sound_path); // 成败不影响另一额度
    }
    schedule_post_reset_fetch(app, kind, new_resets_at);
    Ok(())
}
```

**规则 4 —— 到期后主动补读**：`schedule_post_reset_fetch` 从首次有效基线开始，在未来 `resets_at + 30s`（宽限，吸收服务端时钟偏差）安排一次 `fetch_usage_background`：

- 每个额度同时至多一个挂起定时器（`JoinHandle` 存入 `AppState`）；仅对未来时间安排，时间戳未变且已有同目标定时器时不重复安排，重启后的首次读取要恢复定时器；时间戳变化时取消旧任务并按新时间安排。若到期补读仍返回旧时间，不再对过去时间紧密重排，由常规轮询重试。
- 睡眠唤醒场景：唤醒后主动检查当前时间与待跨越边界，触发补读；不假设所有 Windows 休眠情况下 Tokio 计时器都会以同样方式立即到期。
- 若补读前常规轮询先拿到了新周期，规则 2/3 的持久化标记使补读成为空操作。

判断依据是「旧 `resetsAt` 已到期」及「服务端返回更晚的下一次 `resetsAt`」；仍需要本机时钟做到期比较，因此不能宣称完全不受系统时钟跳变影响。阶段 2 测试需覆盖时间前拨/回拨，并以服务端周期前进为主要确认条件。

```rust
    let audio = if silent { r#"<audio silent="true"/>"# } else { r#"<audio/>"# };
    let xml = format!(r#"<toast><visual><binding template="ToastGeneric">
        <text>{}</text><text>{}</text></binding></visual>{}</toast>"#, title, body, audio);
    let doc = XmlDocument::new()?;
    doc.LoadXml(&windows::core::HSTRING::from(xml))?;
    Ok(doc) // title/body 为固定内置文案；若将来引入外部文本，须做 XML 转义
}

pub fn show_toast(silent: bool, title: &str, body: &str) -> Result<(), NotifyError> {
    let doc = toast_xml(title, body, silent)?;
    let notifier = ToastNotificationManager::CreateToastNotifierWithId(&AUMID.into())?;
    notifier.Show(&ToastNotification::CreateToastNotification(&doc)?)?;
    Ok(())
}

pub fn notification_status() -> NotificationStatus {   // 设置页权限状态展示
    // ToastNotifier.Setting() → Enabled / DisabledForApplication / DisabledForUser / ...
}
```

要点：

- **静音即 XML 层 `<audio silent="true"/>`**（WinRT 官方语义），随后 `AudioHandle::enqueue_notification` 播放自定义音效 —— 精确实现「系统通知静音 + 用户音频」，杜绝双声。
- **权限被拒不反复弹请求**：WinRT toast 无「请求权限」交互；`Setting()` 返回 `DisabledForApplication/DisabledForUser` 时，通知跳过、错误状态写入 `reset-state.json` 的 `lastNotifyError` 字段，设置页经 `quota_reset`/设置加载时展示 §4.5 的 `notifyPermissionDenied` 文案。
- **AUMID 快捷方式兜底（便携版重点）**：WinRT toast 需要与 AUMID 匹配的开始菜单快捷方式。阶段 0 分别验证 NSIS、MSI、便携版。便携版若必须创建快捷方式，设置页应告知用户；`ensure_aumid_shortcut()` 只维护本应用创建的快捷方式，并处理便携程序移动、卸载或用户关闭通知后的清理/更新。创建失败时显示原因；自定义模式可仅播音频，默认模式则报告无法显示通知。

**PluginDefault 路径（windows 模式）**：沿用现有插件（Rust 侧 `app.notification().builder().title(..).body(..).show()`），系统默认提示音由 Windows 决定，行为与现有更新提醒一致（F11）。

### 5.5 音效接线

```
maybe_notify_cycle（enabled && mode==Custom）
  ├─ show_toast(silent=true,  …)          // 静音通知
  └─ audio_handle.enqueue_notification(path, kind)   // 顺序队列（§2.2），同刻双额度自动依次播放
maybe_notify_cycle（enabled && mode==Windows）
  └─ show_toast(silent=false, …)          // 系统默认提示音
```

任一环节失败（toast 失败 / 音效路径失效）都**不阻断另一额度的通知**，错误只落 `lastNotifyError` / `sound_playback_error`（计划阶段 3 完成条件）。
