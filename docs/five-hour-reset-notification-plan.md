# 五小时额度重置通知修复方案

Codex Usage Overlay 应在确认已消耗的五小时额度恢复时提醒一次。首条消息产生新的五小时截止时间时，静默记录新窗口，并从该窗口实际产生用量后开始跟踪恢复。此规则适用于安装后首次读数，以及闲置、睡眠或重启后重新开始使用的场景。

## 现象和影响范围

`advance_cycle` 在旧截止时间已过、新截止时间更晚时产生重置事件。调用方只传入时间戳，遇到空值便提前返回。因此，即使浮窗在空闲期已经显示额度恢复，通知状态也可能一直保留旧截止时间，等下一次发送消息才触发弹窗和提示音。使用现有 Rust 判定和本机时间关系回放，已复现 Codex 和 Claude 的触发过程。 [通知实现](../src-tauri/src/notify.rs)

| 来源 | 已知行为 |
| --- | --- |
| Codex | 上一窗口结束后，首条消息启动新的五小时窗口。本机记录显示通知状态在新窗口启动时才处理旧截止时间。 [OpenAI 用量说明](https://help.openai.com/en/articles/20001516-managing-usage-with-gpt-6-astra-in-work-and-codex) |
| Claude | 同样由首条消息启动窗口。本机记录显示旧窗口到期数小时后，Overlay 在新窗口启动时才处理旧截止时间。桥接层可把过期快照显示为用量 `0%`、截止时间为空，这个显示结果由本地时间投影得出。 [Anthropic 用量说明](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work) · [Claude 读数映射](../src-tauri/src/claude/source.rs) |
| DSH | 桥接的是选定账号的 Codex 额度。本机记录出现了相同的延迟处理。现有 DSH 解析器要求返回的截止时间晚于样本采集时间，恢复判定需要检查桥接上游实际能提供的字段。 [DSH 额度解析](../src-tauri/src/dsh/parser.rs) |
| Antigravity | 共用通知逻辑。Google 确认部分套餐每五小时刷新额度，首条消息是否启动计时仍待验证。需采集真实配额池的到期前、到期后空闲、再次使用三个阶段的样本。 [Google 套餐说明](https://antigravity.google/docs/plans) · [Antigravity 读数映射](../src-tauri/src/antigravity/source.rs) |

## 通知判定

五小时判定使用同一账号和配额窗口的新鲜读数。输入包含原始已用百分比、截止时间、样本采集时间，以及来源能可靠识别的空闲或恢复信号。显示层可以继续按当前时间投影过期快照。重复读取旧快照、缺字段、网络失败或只有定时器到点时，等待可信读数。

| 观察到的变化 | 行为 |
| --- | --- |
| 首次读到窗口，或更换账号、配额池后首次读到窗口 | 建立基线，静默。 |
| 同一窗口内观察到正用量，或新窗口的首份样本已有用量 | 记录该窗口有过消耗，为它将来的恢复建立依据。 |
| 已有消耗的窗口到期，新鲜读数确认额度恢复 | 把旧截止时间记为已处理。提醒开启时发出一次重置事件。 |
| 直接读到新窗口，期间缺少明确的恢复证据 | 静默建立新基线。即使首份读数是 `0%`，也可能是用量取整后的新窗口。 |
| 样本时间回退、重复或缺少可信的恢复信号 | 跳过通知，保留可用的当前窗口依据。 |

确认恢复的具体输入以来源数据为准。例如，供应方的新鲜读数明确表示无活动窗口且额度已经恢复时，可以确认旧窗口恢复。对到期后返回新截止时间、用量归零的来源，先验证这种形态能否与首条消息开窗区分。两者无法区分时接受少报一次真实恢复，避免用户在开始使用时收到错误提醒。主动付费或活动重置只在有明确恢复证据时记为恢复，截止时间变化本身不足以识别这种事件。

## 实现步骤

1. 在 `refresh_usage` 成功路径为五小时通知提供原始窗口数据及采集时间。Claude 的实时、缓存及 statusline 路径要区分原始字段与 `WindowSnapshot::at` 合成的显示值。Codex 复用读取时效判断，DSH 复用账号和 `fetchedAt` 校验。先接入 Codex、Claude 和 DSH。Antigravity 的五小时路径等真实样本明确其刷新方式后再接入。 [刷新入口](../src-tauri/src/commands/usage.rs) · [过期快照投影](../src-tauri/crates/agent-bridge/src/lib.rs)
2. 在 `notify.rs` 为五小时窗口保存已观察到的用量证据，并沿用现有的截止时间和去重记录。旧 `reset-state.json` 中只有时间戳的记录从未知用量建立基线。沿用按来源的状态文件和刷新提交锁。已知账号或配额池切换时重新建立基线并取消旧窗口定时器。持久化成功后再提交弹窗和声音。
3. 沿用到期后 30 秒补读。补读通过正常监控入口取得证据，失败时交给现有轮询重试。在五小时判定中保持每个来源的通知开关和提示音行为。周额度继续走既有判定，尤其要验收 Claude 固定的每周重置时间。 [Claude 周额度规则](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work)

## 验收

- 用合成时间回放 Codex、Claude 和 DSH 的「旧窗口到期 → 空闲 → 首条消息开窗」。新窗口首份样本分别覆盖 `0%` 和正用量，弹窗、声音和重置事件均为零。
- 对已用窗口注入新鲜、明确的恢复样本。通知开启时只产生一次事件，随后开窗、重复轮询及重启均不重复提醒。关闭开关再打开时也不补发。
- 覆盖旧状态文件迁移、账号切换、电脑睡眠跨到期点、超时及陈旧缓存。确认旧读数既不会触发通知，也不会覆盖当前窗口或改错补读定时器。验证五小时和周额度同时到期时各自按设置处理。
- 用实际 Windows 安装版确认 Codex、Claude 和 DSH 的首条消息没有弹窗或提示音，并验证能够确认恢复的路径确实提醒。Antigravity 按配额池验证真实输入，再增加对应的回归用例。发布前以 Windows CI 和安装版烟测记录为准。 [发布流程](../RELEASING.md)
