## 二、审查发现与缺陷清单

### D6（P2）D1 未完全闭环：展开过渡期「临时矩形」仍不覆盖小浮窗命中区，右边缘贴边时 100% 不覆盖

- **文件与行号**
  - `src-tauri/src/dock.rs:661-683`（`set_full_size`：临时尺寸 = `max(硬编码估算 220/160×scale, 当前窗口尺寸)`，并 emit `overlay_size_invalidated`）
  - `src-tauri/src/dock.rs:692-728`（`place_full_at_anchor`：位置取 `window-position.json` 的松手锚点 `(left, top)`，仅夹紧到该锚点所属工作区；**不做任何「与当前小浮窗矩形取并集」的修正**）
  - `src-tauri/src/dock.rs:454-473`（`mouse_enter`：先 `set_full_size`，再 `place_full_at_anchor`，最后才 `emit_state`）
  - `src-tauri/src/dock.rs:637-653`（`apply_pill`）与 `:319-370`（`pill_geometry`：左/右边缘小浮窗 `x` 固定为 `wx+I` / `wx+ww−W−I`，上/下边缘 `y` 固定为 `wy+I` / `wy+wh−H−I`；仅另一轴按 `anchor_center` 居中）
  - `src/components/OverlayView.tsx:95-114`（`fitCapsuleSize` 的 `if (collapsed) return;` 守卫 → 过渡期内前端无法、也不应回写内容尺寸；内容尺寸要等 `dock_state_changed` 到达后才回写）
  - 对照契约：`docs/v1.1.0-technical-spec.md:407`（§3.4「展开后的矩形须覆盖鼠标当前所在的小窗命中区域，避免刚展开就收到 `mouseleave`」）与上轮 D1 的「修复后验收标准」（第 1 轮 handoff 第 36-37 行）
- **触发条件**：`auto_edge_hide=true`、窗口已贴边收起为小浮窗，鼠标悬停展开。右边缘为 100% 必现（与松手偏移无关），下边缘约 38%–58% 面积不覆盖，左边缘 16%–30%，上边缘 0%–17%（见下表）。所有落在吸附阈值内的正常松手位置均在触发范围内。
- **实际行为与期望行为**
  - 期望（§3.4/上轮验收）：`mouse_enter` 那一刻写入窗口的矩形必须覆盖鼠标当前所在的小浮窗命中区，使展开过程中鼠标始终位于窗口内。
  - 实际：`set_full_size` 只保证「不小于当前窗口尺寸」，**不修正位置**；`place_full_at_anchor` 把窗口放到松手锚点 `(left, top)`。由于小浮窗被 `pill_geometry` 钉在工作区边缘、而展开矩形落在松手锚点，两者在「贴边轴」上相差最多一个吸附阈值；又因为估算宽度（220 逻辑 px）恒约为真实胶囊（284.31 逻辑 px，v1.0.1 实测未变换盒）的 77%，夹紧计算无法把窗口推到贴边侧，于是**右边缘贴边时临时矩形整体落在小浮窗之外**（相差 871−674＝197 px）。
- **根因**：修复只处理了尺寸轴（`max(est, current)`），未处理位置轴。上轮 D1 的根因本就是「Rust 用硬编码近似尺寸代替真实内容尺寸」；本轮把近似值从「写死不纠正」改成「先写近似值、再由前端纠正」，但**过渡期**仍以上述近似矩形参与定位与命中，`place_full_at_anchor` 的入参语义（恢复用户锚点）与 §3.4 要求的入参语义（覆盖当前命中区）不是同一件事。
- **影响范围**
  - 展开过渡期（自 `place_full_at_anchor` 到前端内容尺寸回写完成，至少一个 IPC 往返 + 一次 React 渲染）内鼠标可能位于窗口之外：右边缘贴边时**必然**如此；此时 WebView 收不到该位置上的鼠标消息，若系统投递 leave 事件即触发 `mouse_leave` → 400 ms 后 `collapse_if_current`（`pointer_inside=false`）收起 → 表现为「悬停展开一闪即回」；由于收起时小浮窗按 `anchor_center` 重新落位、再次悬停会重复同一过渡，右边缘可形成 ~450 ms 周期抖动。
  - 即使未投递 leave，仍有一次可见跳变（窗口先跳到离鼠标 197 px 处、再膨回覆盖小浮窗）。
  - 无数据损坏：`window-position.json` 只在松手路径写入，本缺陷不触碰它。有规避方案：展开后把鼠标移回胶囊内即可取消待收起定时器（`enter_pill()` 置 `pointer_inside=true` 并递增 `timer_generation`，旧代次定时器失效）。
  - 结构性上限：小浮窗高 100 逻辑 px 恒为内容胶囊（未变换 69 CSS px）的 1.45 倍，故即便过渡期修正到完全覆盖，内容尺寸回写后仍会有约 31% 的小浮窗面积（上下各约 15%）落在最终矩形之外——建议在规格层同时记录该已知几何，或把「覆盖」目标明确为「覆盖鼠标当前位置」而非「覆盖整个小浮窗」。
- **复现方法与验证证据**（按源码公式定值演算；参数：`sf=1.75`、`scalePercent=175`、`show_credits=true`、工作区 2560×1440、内容实测未变换盒 284.31×69 CSS → 内容窗口 871×211 物理、估算 674×153、吸附阈值 `round(16×1.75)=28` px、小浮窗 141×306（左/右）或 306×141（上/下）；`pill_geometry` 的数值已由仓库自带单测 `pill_geometry_swaps_dimensions_for_top_and_bottom_and_scales` 交叉印证）

  右边缘举例（`off=0`）：小浮窗 `x∈[2415,2556]`；松手锚点 `x=1689`（=2560−871，是「右边缘吸附」的合法松手位，`|(1689+871)−2560|=0 ≤ 28`）；过渡期矩形 `[1689,2363]×[400,706]`，其右边界 2363 < 小浮窗左边界 2415 ⇒ 交叠面积为 0；只有当 871 宽的内容尺寸回写后矩形才变为 `[1689,2560]` 并覆盖小浮窗。
  - 现有测试未覆盖：`OverlayView.test.tsx` 只断言折叠→展开后 `setSize` 被重新调用（尺寸侧）、`dock.rs` 单测只覆盖 `pill_geometry`/`detect_edge`/`select_work_area`/`clamp_position` 的纯函数，**没有任何用例断言「展开过渡期矩形 ⊇ 小浮窗矩形」**，也没有这条契约的实机证据。
  - **未验证环节（如实声明）**：本机自动化会话无可交互 Tauri 桌面窗口，无法实测「窗口在静止鼠标下移开后 Windows/WebView2 是否投递 leave」。因此上表中「覆盖比例」是确定结论（纯几何），而「是否表现为刚展开即收起」依赖该 leave 语义；即便如此，§3.4 明文要求的覆盖契约已被确定性违反，右边缘 100% 不覆盖。
- **修复建议**（审查轮不落码，仅供参考）
  1. 过渡期矩形取「夹紧后的锚点矩形」与「当前小浮窗矩形」的并集（或按贴边轴取 `min(saved, pill)`：左/上取更小坐标、右/下取更小坐标方向一致），保证 `mouse_enter` 写下的矩形覆盖小浮窗命中区；
  2. 或把 `place_full_at_anchor` 的入参语义拆开：恢复用户锚点（自由态）与「展开过渡落位」（贴边态）分别实现，后者以「覆盖当前圆角矩形」为目标，内容尺寸回写后再按锚点二次夹紧（§3.4 已要求「尺寸变化完成后再夹紧一次」）；
  3. 前端侧无法、也不应绕过 `collapsed` 守卫，故不应把该契约的实现责任留给前端。
- **修复后验收标准**
  1. 新增 Rust 单测（纯几何、可离线跑）：对四边 × 吸附阈值内若干松手偏移，断言 `mouse_enter` 过渡期矩形包含小浮窗矩形（允许按「覆盖鼠标位置」的替代目标，但必须显式断言并更新 §3.4 文案）；
  2. 实机（可见桌面，四边各一次）：小浮窗悬停展开后鼠标不动，右边缘等 500 ms 内不收起、无可见跳变；
  3. 记录 `window.inner_size()` 与胶囊 `getBoundingClientRect` 换算值（±1 px）与本次过渡矩形实测值。
