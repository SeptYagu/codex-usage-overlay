# Codex Usage Overlay v1.3.1 — Display Controls Plan

Date: 2026-10-03  
Baseline: `7b335d7` (`docs: finalize v1.3.0 changelog`)  
Scope: plan only; no production implementation in this commit.

## 1. Goal

v1.3.1 adds two independent presentation preferences:

1. `showBurnRate` — show/hide the `x%/h` Burn Rate text introduced in v1.3.0.
2. `showFiveHourQuota` — show/hide all user-visible 5-hour quota presentation.

The second control is needed because some account/subscription configurations may not use a meaningful 5-hour quota. The application must therefore be able to present Weekly usage without forcing an irrelevant 5H module.

This is intentionally a presentation release. It must not change the v1.3.0 sampling, estimator, reset-detection, persistence, or refresh-pipeline semantics.

## 2. Product decisions

Both new settings default to `true`.

That preserves v1.3.0 behavior for every existing installation after upgrade. Users opt out only when the extra information is not useful.

`showBurnRate` controls Burn Rate text only. It does not stop BurnRateTracker collection or persistence.

`showFiveHourQuota` controls presentation only. It does not stop fetching 5H data, storing it, estimating its burn rate, or processing reset state.

The two controls are independent:

| showFiveHourQuota | showBurnRate | Expanded overlay |
| --- | --- | --- |
| true | true | 5H + WK; both show countdown and Burn Rate |
| true | false | 5H + WK; countdown only |
| false | true | WK only; WK countdown + Burn Rate |
| false | false | WK only; countdown only |

`showCredits` remains independent from both.

No automatic subscription-tier detection is required in v1.3.1. The user explicitly selects the presentation appropriate to the account.

## 3. Settings model

Add to TypeScript `OverlaySettings`:

```ts
showFiveHourQuota: boolean;
showBurnRate: boolean;
```

Add matching Rust fields to `OverlaySettings`:

```rust
#[serde(default = "default_true")]
pub show_five_hour_quota: bool,

#[serde(default = "default_true")]
pub show_burn_rate: bool,
```

Add both keys to the closed `validate_settings_patch()` boolean allowlist.

Add both to `DEFAULT_SETTINGS` and Rust `Default`.

Backward compatibility is mandatory: settings files written by v1.3.0 or earlier contain neither key and must deserialize to `true` for both fields without resetting any existing preference.
## 4. Settings UI

Place the new controls in the left-hand overlay/display column, adjacent to the existing Credit visibility control.

Recommended order:

1. Show 5-hour quota
2. Show Credit Balance
3. Show Burn Rate (%/h)
4. Auto hide at screen edge
5. Show Percentage Grid
6. Mouse click-through

Recommended i18n copy:

| Key | English | 简体中文 | 繁體中文 |
| --- | --- | --- | --- |
| `showFiveHourQuota` | Show 5-hour quota | 显示 5 小时额度 | 顯示 5 小時額度 |
| `showBurnRate` | Show Burn Rate (%/h) | 显示消耗速度（%/h） | 顯示消耗速度（%/h） |

Do not label Burn Rate as model speed, token speed, or inference speed. The value remains account quota consumption rate.

Do not disable `showBurnRate` when `showFiveHourQuota=false`, because Weekly Burn Rate is still useful.

## 5. Expanded overlay behavior

Build the visible quota list from settings instead of always rendering both quota blocks.

When `showFiveHourQuota=true`:
- render 5H first;
- render WK second.

When `showFiveHourQuota=false`:
- omit the 5H quota block and its divider entirely;
- render WK as the first/only quota block;
- retain normal grouped/stacks behavior.
Burn Rate rendering is conditional inside each visible quota block:

- `showBurnRate=true`: metadata row contains countdown + Burn Rate.
- `showBurnRate=false`: metadata row contains countdown only.

When Burn Rate is hidden, do not leave an empty rate span, placeholder dash, or reserved horizontal gap.

The final overlay width remains content-driven through the existing ResizeObserver path.

Credits behavior is unchanged except that divider placement must still be correct when 5H is absent.

Examples:

```text
5H ON, Rate ON, Credit ON:
5H 90% | WK 80% | CR $...
2h 34m 16.8%/h   4d 02h 0.6%/h

5H OFF, Rate ON, Credit ON:
WK 80% | CR $...
4d 02h 0.6%/h

5H OFF, Rate OFF, Credit OFF:
WK 80%
4d 02h
```

## 6. Collapsed edge pill

`showFiveHourQuota=false` must also remove the 5H bar from the collapsed edge pill.

Current pill rendering always iterates both quotas. v1.3.1 should reuse the same visible-quota list or equivalent visibility helper so expanded and collapsed modes cannot drift.

One-bar pill behavior must be intentional:

- render only the Weekly track;
- center the remaining track within the existing pill host;
- preserve percentage-grid behavior on the Weekly track;
- preserve top/bottom rotation behavior;
- do not leave an invisible/empty 5H track occupying width;
- update accessible labels so a hidden 5H quota is not still announced by the pill.

The pill host dimensions and docking hit target should remain unchanged unless real-layout verification proves a change is required.

`showBurnRate` has no collapsed-pill effect because Burn Rate text is not rendered there today.

## 7. Tray tooltip and tray icon

The current tray tooltip mirrors `showCredits`; 5H visibility should follow the same presentation principle.

When `showFiveHourQuota=true`:
- tooltip keeps `5H … | WK …` plus optional Credit.

When `showFiveHourQuota=false`:
- tooltip contains `WK …` plus optional Credit;
- do not render `5H --%` or any other placeholder.

The tray icon currently encodes 5H as the outer ring and Weekly as the inner ring.

When 5H is hidden:
- do not draw the 5H outer ring or its inactive track;
- keep Weekly on its existing inner-ring semantic position;
- do not silently remap Weekly to the outer ring in v1.3.1.

This requires the tray-icon renderer to receive presentation visibility explicitly rather than treating `None` as “hidden”, because `None` currently means “quota unavailable” and still draws an inactive ring.
The same tray presentation helper must be used by normal usage refreshes and by settings-change refreshes so the icon/tooltip cannot disagree after toggling a setting.

## 8. Data, estimator, and notification independence

Display settings must not mutate underlying quota data.

Turning off either display switch must NOT:
- clear BurnRateTracker history;
- stop Burn Rate persistence;
- skip 5H parsing;
- change polling cadence;
- change `last_usage`;
- alter reset-cycle detection;
- alter account-switch isolation;
- fabricate `None` values in the usage DTO;
- trigger a network refresh merely because a display switch changed.

5-hour reset notification preferences remain independent.

Specifically, `showFiveHourQuota=false` must not implicitly disable `fiveHourResetNotification`. A user may hide the quota while still wanting a reset alert.

Likewise, turning the display back on should immediately reuse current cached data/history rather than needing a new estimator warm-up period.

## 9. Dock geometry

v1.3.0 widened the provisional expanded width because Burn Rate is always visible.

v1.3.1 makes width conditional again.

The backend geometry invalidation condition in `apply_settings_patch()` must include:
- `showFiveHourQuota`;
- `showBurnRate`;
- existing `showCredits`, layout, scale, and language dependencies.

The provisional sizing function must account for the visible composition rather than accepting only `show_credits`.
Recommended direction:

```text
provisional_expanded_base_size(
  show_five_hour_quota,
  show_credits,
  show_burn_rate,
  layout
)
```

Exact constants should be derived from existing verified v1.3.0 widths plus real rendering, not guessed independently.

The authoritative final size remains frontend-content measured. Provisional sizes only need to avoid clipping/hover loss during dock expansion.

Required geometry cases:
- 5H on/off;
- Burn Rate on/off;
- Credits on/off;
- grouped/stacks;
- scale 100% and 250%;
- docked expansion from every edge;
- English / Simplified Chinese / Traditional Chinese;
- mixed/high DPI.

## 10. Implementation seams

Prefer small reusable presentation helpers rather than scattering conditionals.

Frontend candidate:
- derive `visibleQuotas` once from `settings.showFiveHourQuota`;
- derive metadata rendering from `settings.showBurnRate`;
- reuse `visibleQuotas` in expanded and collapsed rendering.

Backend candidate:
- centralize tray presentation from `usage + settings`;
- pass explicit visibility to tray icon generation;
- centralize provisional-size inputs.

Do not alter the raw usage model merely to implement visibility.

## 14. Acceptance criteria

v1.3.1 is complete when:

- two persisted switches exist: 5H visibility and Burn Rate visibility;
- both default true for fresh and upgraded installations;
- disabling Burn Rate removes rate text without stopping estimator collection;
- disabling 5H removes every visible 5H representation from expanded overlay, collapsed pill, tray tooltip, and tray icon;
- Weekly remains fully usable when 5H is hidden;
- Credit remains independent;
- 5H notifications remain independent;
- toggling visibility does not clear history or require Burn Rate re-warm-up;
- no orphan dividers, empty gaps, clipping, or hover-loss regressions occur;
- dock geometry responds immediately to either display change;
- all frontend/Rust/build/check gates pass;
- supported languages, layouts, scales, and DPI combinations pass real-machine verification.

## 15. Out of scope

Do not add in v1.3.1:
- automatic subscription-tier detection;
- automatic hiding based on missing quota data;
- a switch that disables BurnRateTracker computation;
- a switch that disables 5H network parsing;
- changes to Burn Rate math;
- token/s or inference-speed metrics;
- new quota types;
- persistent app-server work;
- analytics/history UI.

## 16. Version rationale

This is appropriately a `1.3.1` patch release: it exposes presentation controls around features already shipped in 1.3.0 and adapts the UI to accounts where one quota surface is not useful, without changing the underlying usage or estimator contract.
