# 多 Agent 额度自动轮播实施方案

- 日期：2026-11-06，America/Indianapolis。
- 状态：**方案阶段；尚未实现、发布或安装。**
- 基线：仓库 `a960c04`，应用源码版本 `v1.6.0`。
- 范围：现有 Codex、Claude、DSH 在已启用监控且有可用读数时，浮窗自动轮换显示额度。不是账号轮换、请求路由或多个同类 profile 并行运行。

## 1. 可行性和推荐体验

可以实现。当前已有独立来源 runtime、后台采样、`MonitorSnapshot` 缓存、来源图标手动切换及跟随显示来源的托盘。轮播应增加显示调度，不改变采样和保护模型。

推荐默认行为：

| 项目 | 规则 |
| --- | --- |
| 开关 | 默认关闭；用户主动开启 |
| 轮播间隔 | 默认 8 秒，可选 5／8／10／15／30 秒；与额度读取间隔无关 |
| 顺序 | Codex → Claude → DSH，循环跳过不符合条件的来源 |
| 来源数量 | 至少两个可轮播来源才定时切换；一个或零个时待机，保留开关意图 |
| 手动切换 | 立即显示目标，从此刻暂停自动切换 30 秒；连续操作重置停留期限 |
| 交互 | 鼠标停留、键盘焦点在浮窗控件内、拖动、浮窗／托盘菜单打开时暂停 |
| 不可见状态 | 主动隐藏、最小化或贴边收起时暂停；恢复可见后重新开始完整停留周期 |
| 显示身份 | 每屏明确标明当前来源；不让不同来源的百分比在无标识情况下变化 |
| 执行边界 | 只读取已有缓存，不强制刷新、不改保护、不创建继续任务、不改变连接或账号 |

与[独立设置栏方案](2026-11-06-independent-provider-settings-columns-plan.md)配合：公共设置放“额度自动轮播”和间隔；各来源栏放“参与轮播”，并显示当前是否可参与及原因。关闭参与只影响展示，不关闭监控、提醒或保护。

## 2. 候选来源与连接状态

“已连接”不能仅由监控开关或 `has_reading` 推断。当前 `Registry::next()` 只检查监控及曾有读数，适合现有宽松手动切换，但不应直接作为自动轮播策略。

自动候选需同时满足：

1. 用户开启该来源监控，并允许它参与轮播。
2. runtime 仍为 Registry 中当前实例，`sourceKey/sourceGeneration` 与样本相符。
3. 已有至少一项可展示的额度／余额数据，且不是从旧来源身份留下的缓存。
4. 样本时间未超过该来源有效窗口；沿用现有监控判断的 `max(120 秒, 正常刷新间隔 × 2)`。独立刷新方案实施后读取该来源间隔，不能再取全局镜像。
5. 无明确的未连接／认证失效／账户绑定失效／需要设置状态。来源专属连接适配器应输出明确可展示状态，不用解析错误文案猜测认证结果。候选判断只读已有的连接状态和结构化错误，不主动发起连接探测、认证或额度请求。

短暂读数失败或正在刷新时，可在上述时间窗内保留上次成功读数，并显示旧样本／重试标记；不会因一次网络错误立即反复加入和移除。超过有效窗口就从自动候选中移除，后续有效成功样本再加入。手动查看陈旧读数仍按原规则允许，并明确显示状态。

Claude 桥接模式没有新终端样本时可能暂时退出轮播，这是数据新鲜度限制；不能为凑齐轮播来源擅自开启实时读取。DSH 未配置、未认证或身份不匹配时不参与，轮播不替用户连接或绑定会话。

候选变化只影响展示列表：

- 当前来源仍合格时，不因另一个来源加入／退出而立即换页，等当前停留结束。
- 当前来源不合格、只剩一个可用来源时，允许一次切到该来源后待机，不持续循环。
- 没有可用来源时保留当前页并展示已有的错误／无读数状态，不闪回任意来源。
- 鼠标／拖动／菜单等交互暂停期间不强行换页；退出交互后先重新核对候选和状态，再安排切换。

## 3. 设置与显示状态分离

### 3.1 配置字段

新增应用级字段：

| JSON 字段 | 类型 | 默认 |
| --- | --- | --- |
| `quotaCarouselEnabled` | boolean | false |
| `quotaCarouselIntervalSeconds` | 5／8／10／15／30 | 8 |

在 `ProviderPreference` 增加 `carouselIncluded: boolean`，默认 true。监控、保护和参与轮播是独立设置。零个或一个来源被勾选时不报保存失败，显示待机原因即可。

与独立设置栏共同实施时使用其 schema 3 迁移，仅为缺失的新字段补默认，不清空旧值、不再次复制其他偏好。未知类型／非法枚举的磁盘值仅恢复相应字段，实时 patch 严格拒绝；更高 schema 和失败保存继续遵守版本保护及原子提交。

### 3.2 为什么不能直接调用现有手动切换

现有 `cycle_display_provider` 调用 `apply_settings_patch({"cycleProvider":true})`，最终写入 `settings.provider`、保存磁盘并同步 Registry。若每 8 秒调用一次，会产生持续写配置和设置广播，还可能牵动兼容镜像与窗口尺寸。

保留根 `settings.provider` 作为**最近手动选中的来源**，另建应用唯一的运行时 `DisplayState`：

```text
DisplayState
  manualProvider          最近成功保存的手动来源
  effectiveProvider       浮窗当前实际显示来源
  revision                应用内单调递增显示版本
  carouselEnabled         已保存开关
  candidates              当前合格来源及其身份
  pauseReasons            交互／隐藏／候选不足等原因集合
  manualHoldUntil         单调时钟的手动停留期限
  nextDeadline            单调时钟的下一次切换期限
```

自动 tick 只改变 `effectiveProvider` 和显示版本，不调用设置 patch、不写 `settings.json`、不调用 `Registry::synchronize`、不修改 runtime settings revision／source generation。设置中的兼容镜像继续对应手动保存来源，真正显示／托盘使用 effective 来源的 runtime 投影，不能误把镜像当作当前轮播配置。

重启后先显示保存的手动来源；轮播开关和间隔恢复，运行时倒计时重新开始，不恢复上次进程的瞬时页码。用户关闭轮播时，冻结当前 effective 来源，并在同一设置事务中把它保存为手动来源一次，避免关开关后页面跳回很久之前的选择。

## 4. 单一显示选择入口

新增后端显示协调模块，例如 `src-tauri/src/display.rs`，由应用 owner 持有一个控制器和一个调度 worker。不可在每个 WebView、每栏组件或每个来源 runtime 中各自创建轮播计时器。

统一入口可设计为 `select_display_provider(provider, origin)`，origin 区分：

- `Manual`：浮窗图标、来源栏“在浮窗显示”、现有设置／托盘手动选择。保存手动偏好成功后立即提交显示选择，并开始 30 秒停留；失败不留下未保存的显示假象。
- `Carousel`：调度器推进，只更新运行时显示；不写设置。
- `Fallback`：当前来源失去资格时的一次展示回退；同样不写设置，受交互暂停约束。

现有手动“下一个”必须以当前 `effectiveProvider` 为起点，不能以最近手动偏好为起点；候选仍可沿用较宽松的手动可展示规则。手动操作、自动 tick、关闭轮播与候选变更在同一个短提交门中串行，避免快速点击重复跳页。门内不做磁盘／网络 I/O；手动持久化和提交通过版本校验接线，旧 tick 不得覆盖刚提交的手动选择。

`AppState::is_displayed`、`AppServices.displayed_provider`、托盘更新、手动刷新目标、保护状态摘要、浮窗来源 scope 和尺寸布局均改为读取同一 effective 来源。后台提醒继续依来源 runtime 执行，不能跟着轮播改变。

特别注意：Settings 的各来源设置保存目标是固定来源，不是 effective 来源。已有顶层兼容 patch 的归属仍按独立设置栏方案取已保存的手动来源，不能在自动换页后悄悄改写别的来源。

## 5. 事件、缓存和来源一致性

增加 `get_display_state` 查询与 `display_updated` 事件，承载 `revision`、effective 来源、期望 `sourceKey/sourceGeneration`、候选、暂停原因和必要的剩余时间。单调时钟内部值不直接持久化，也不作为跨进程时间戳传递；对 UI 输出可展示的剩余毫秒。

前端先监听再恢复初始状态，以 `DisplayState.revision` 拒绝迟到选择。收到切换后，使用 `useProviderMonitors` 已有的对应来源缓存；核对来源身份、代次及可选算法方案的显示版本，绝不暂用上一来源数字配上新图标。缺少匹配缓存时短暂显示该来源的加载／无数据状态，不能跨来源借值。

以下入口必须一并迁移：

- `App.tsx` 浮窗渲染、数据 scope 和手动 Refresh。
- `OverlayView.tsx` 当前图标、下一来源提示及交互状态。
- 托盘额度环、tooltip、保护摘要、菜单中的当前来源。
- `get_last_usage/fetch_usage` 选择显示目标的逻辑；请求开始时绑定目标，结束时若已切页只更新原来源缓存，不改变页面。
- Settings 公共区当前来源摘要及每栏“在浮窗显示”标记。
- dock 对齐／尺寸预算和 `is_displayed()` 判断。

`settings_updated` 不再拥有覆盖实时 effective 来源的权力：只更新保存偏好和轮播参数，由显示协调器决定是否改变页面。不能在前端把 effective 来源偷偷写回 `settings.provider`，导致下一次普通 patch 将自动页码持久化。

## 6. 暂停、计时与显示稳定性

使用 `tokio::time::Instant` 和可唤醒的单 worker。候选、配置、交互或可见性变化时通知 worker 重新计算；不每秒重写设置、不按 tick 发布整份 monitor 数据。

| 状态 | 行为 |
| --- | --- |
| 关闭 | 无轮播 deadline；保留手动显示能力 |
| 开启且合格来源不足两个 | 待机；按第 2 节规则处理一次回退 |
| 正常轮播 | 当前页停留满所选间隔后推进一个来源 |
| 手动停留 | 下一切换不得早于最后手动选择后 30 秒；不再额外叠加一个完整 8 秒周期 |
| 鼠标／焦点／拖动／菜单暂停 | 不换页；所有相关暂停原因消失后，从当前页重新停留完整间隔；若手动停留尚未结束，取较晚期限 |
| 隐藏、最小化、贴边收起 | 不换页；恢复可见后重新停留完整间隔 |
| 休眠或执行阻塞 | 恢复后重新计时，不补发错过的多次 tick |

暂停原因采用集合，菜单关闭不能清除仍存在的 hover／drag 等原因。交互事件由主浮窗及后端菜单／dock 状态汇总，设置窗口的普通编辑不暂停整个轮播。窗口销毁、指针捕获结束和拖动取消须释放所属交互 token，避免永久停住；不能用粗暴超时清除仍在操作的真实暂停。

第一阶段只轮播完整浮窗。贴边收起时两条额度条缺少足够的来源标识，因此维持最后一页；悬停展开后先让用户阅读和手动操作。将来若支持收起条轮播，须先增加清楚的来源标记并单独验证最小尺寸，不能让无标签的百分比悄悄换来源。

开启轮播时，即使用户关闭了来源 logo，也须显示紧凑来源文字作为替代标识；不修改用户保存的 logo 偏好。tooltip 可显示“自动轮播／手动停留／暂停原因”，不默认增加每秒倒计时动画。第一阶段采用直接换页，不增加影响读数辨认的动画。

轮播候选的内容宽度可能不同，尤其 Codex 有 Credit、Claude 没有。开启轮播后按候选所需宽度的最大值预留稳定预算，延续当前缩放与屏幕边界处理；不每次换页重写窗口位置或学习贴边位置。候选变化／全局外观变化时才重算预算，关闭轮播后恢复当前来源正常预算。

## 7. 与监控和保护的关系

自动轮播只控制展示：

- 不要求每 8 秒拉一次额度；各来源继续自己的正常刷新、保护加速、节流和失败退避。
- 不因为来源显示或被跳过而开启／关闭保护、重新绑定会话、清空学习、改变算法或重置通知去重。
- 低额度不会在第一版触发抢占页面、延长停留或改变轮播顺序；使用已有来源保护与重置通知，避免引入第二套注意力调度。
- Codex 的定时继续仍使用服务器重置时间＋120 秒生成指定时刻；轮播不创建任务、不重复发送文案。
- 用量接口失败与显示调度失败分别记录，不能把轮播待机写成额度读取失败。

| 文件／模块 | 计划改动 |
| --- | --- |

| `src-tauri/src/commands.rs`、`monitor.rs` | 区分手动／自动选择、有效候选读回、显示目标缓存命令、取消每 tick 保存路径 |
| `src-tauri/src/lib.rs` | 初始化／停止唯一 worker，注册显示查询和交互命令，应用可见性接线 |
| `src-tauri/src/tray.rs`、`dock.rs` | effective 来源、菜单／dock 暂停信号、稳定尺寸预算 |
| `src/App.tsx`、`src/usageSource.ts` | 运行时显示与持久化设置分离，缓存匹配和版本过滤 |
| `src/hooks/useDisplayState.ts`（新增） | 显示订阅／初始恢复，独立版本水位 |
| `src/components/OverlayView.tsx`、`src/hooks/useProviderMonitors.ts` | 当前来源和缓存渲染、手动 next、交互暂停与状态提示 |
| 三栏方案的公共／来源组件、`src/providerSettings.ts`、`src/i18n.ts` | 轮播开关、间隔、参与选项和三语言状态说明 |
| Rust／React 测试、`scripts/display-controls-qa/` | 虚拟时间、显示来源一致性、窗口与轮播布局验证 |

分阶段实施：

1. **显示状态分离**：先让现有手动切换通过统一显示入口工作；不开轮播，回归显示、托盘、刷新及三栏来源标记。
2. **候选与状态机**：纯候选和虚拟时间测试，覆盖连接、新鲜度、用户停留和暂停组合；没有任何 I/O 副作用。
3. **调度和交互**：接入唯一 worker、运行时事件和菜单／dock 信号；验证每 tick 零配置写入、零强制采样。
4. **UI 与集成**：设置、来源标识、稳定宽度、多窗口与高 DPI；完成自动及 Windows 实机验收后再准备发布。

与三栏／Codex 功能共同实施时，先建立 schema 3 和来源缓存，再做显示状态分离。若显示缓存同时增加算法元数据，两份方案共用同一个缓存与版本契约，不能各建一套互不一致的最后读数。

## 9. 验收矩阵

| 类别 | 必须通过的场景 |
| --- | --- |
| 基本轮播 | 两个／三个候选的固定顺序、完整间隔、零／一个候选待机、从非候选当前页的一次回退 |
| 连接与读数 | 无样本、不完整样本、代次不符、明确未连接、认证失效、短暂失败仍新鲜、到期移除、成功恢复加入 |
| 手动操作 | 当前 effective 的 next、连续快点、来源栏直接选择、30 秒停留、停留期间关闭轮播、保存失败不留下错误手动页 |
| 竞态 | 手动选择与 tick 同时发生、禁用来源与 tick、关闭轮播与迟到 tick、多窗口命令乱序、晚到 display／cache／monitor 事件 |
| 暂停 | hover＋菜单组合、键盘焦点、拖动取消、指针捕获释放、隐藏／最小化、贴边收起、暂停后恢复完整停留 |
| 时间 | 修改系统墙钟不影响 deadline、休眠恢复不追赶多页、改变间隔重新安排、手动停留不会额外叠加一周期 |
| 无副作用 | 多个 tick 后 settings 文件／mtime、配置写次数、runtime 版本、source generation、采样调用数、tracker／通知／保护账本均无额外变化 |
| 来源一致 | 图标／文字、两额度、余额、算法说明、托盘环、tooltip 和手动刷新目标属于同一 effective 来源；旧响应只回原缓存 |
| 布局 | Credit 有无、两个布局、5H 隐藏、logo 关闭时仍有来源文字、多语言、缩放 100%／175%／250%、多屏边界无逐页跳位 |
| 生命周期 | 设置／托盘／主窗口同时存在仍仅一个 worker，重启从手动来源开始，退出回收 worker，不关闭其他进程 |

调度测试使用虚拟时间及有界屏障，不实际等待几十秒。零副作用测试应通过生产入口注入 recording sink／存储写计数，不能仅测纯函数就声称调度没有写配置。语义检查包括：把 tick 错接 `apply_settings_patch`、把 manual 起点错用 settings.provider、让旧显示事件覆盖新 revision 时，相应测试应失败。

基础检查沿用 `npm test`、`npm run build`、`cargo test --manifest-path src-tauri/Cargo.toml --locked` 和 `cargo check --manifest-path src-tauri/Cargo.toml --locked --all-targets`。浏览器 QA 用模拟时钟和固定来源样本验证显示；Windows 另外验证隐藏／贴边／托盘菜单、焦点、拖动及休眠恢复。未运行的实机项目不得计为通过。
