## 二、审查发现与缺陷清单

### P2-1 / CR3-1 最小化后退出（或最小化时被关闭）仍会丢失最小化前的窗口调整：本轮采用“丢弃不可用读数”策略，但全仓不存在“最小化前”的捕获点，Round 2 验收标准 #1/#2 的“恢复”要求未闭环

**文件与行号**

- 本轮新增的早退守卫：`src-tauri/src/lib.rs:300-302`（`if is_minimized { return; }`）
- 本轮新增的零尺寸拒绝：`src-tauri/src/lib.rs:303-306`
- `RunEvent::Exit` 兜底与守卫（本轮加固）：`src-tauri/src/lib.rs:254-273`（守卫 `262-264`；调用 `266-272`）
- `CloseRequested` 落盘（未变）：`src-tauri/src/lib.rs:55-65`（`is_minimized` 实参在 `62`）
- 唯一落盘函数与其调用点：`src-tauri/src/lib.rs:293-318`，调用者仅 `lib.rs:57` 与 `lib.rs:266`；`save_settings_geometry` 定义在 `src-tauri/src/config.rs:232-240`
- 无记录时的恢复兜底：`src-tauri/src/tray.rs:242-250` → `src-tauri/src/tray.rs:274-280`（`center_settings_window` 设 `480×660` 并居中）
- 读取侧对非正尺寸的拒绝：`src-tauri/src/config.rs:207-230`（`width > 0 && height > 0`）
- 窗口属性：`src-tauri/tauri.conf.json:39`（`decorations: true`）、`:41`（`skipTaskbar: false`）、`:43`（`maximizable: false`）；未设置 `minimizable`，取 `tauri-utils-2.10.0/src/config.rs:2421` 的默认值 `true`

**触发条件**

打开设置窗口 → 本会话内**不点击设置窗口的关闭按钮（X）** → 拖动/缩放窗口 → 点标题栏最小化 → 从托盘菜单选“退出悬浮窗”（`commands.rs:547-550` → `app.exit(0)`）或系统关机 → 重启 → 从托盘打开设置。

**实际行为 vs 期望行为**

- 实际：整条链路**没有任何一次落盘**。
  - `RunEvent::Exit` 的守卫（`lib.rs:262-264`）要求 `is_visible && !is_minimized`，最小化窗口（`IsWindowVisible == TRUE`、`IsIconic == TRUE`）在 `-is_minimized` 处被挡下；
  - 即便走到 `persist_settings_geometry`，本会话也从未触发过 `CloseRequested`（用户没点 X），因此没有任何一次“最小化前”的写入；任务栏“关闭窗口”路径同理，`is_minimized == true` 会在 `lib.rs:300-302` 被早退拒绝。
  - 于是磁盘上要么不存在 `settings-window-geometry.json`（首次使用），要么是上一会话的**陈旧**记录。重启后 `tray.rs:247-250` 读到 `None` → 居中 `480×660`；或读到陈旧记录 → 复原到本轮移动**之前**的位置。用户在本会话中的位置/尺寸调整 100% 丢失。
- 期望（Round 2 验收标准 #1、#2 明文要求）：恢复到**最小化前的物理位置与逻辑尺寸**；对最小化的设置窗口执行任务栏“关闭窗口”后重启“同样复原”。

**根因**

1. 本轮修复正确地阻止了 0×0 覆盖，但采取的是“**丢弃**不可用读数”策略。全仓只有两个落盘点（`CloseRequested`、`RunEvent::Exit`），二者在“本会话未关闭过设置窗口 **且** 退出时处于最小化”这一组合下**同时不可用**，而中间不存在任何捕获点：`on_window_event` 仅处理 `CloseRequested` / `tray-menu` 的 `Focused(false)` / `main` 的 `ScaleFactorChanged`（`lib.rs:53-83`），没有设置窗口的 `Moved`/`Resized` 处理。这与 Round 1 的 P3-2（“调整后直接退出”不落盘）同源——根因是缺少移动/缩放时的防抖落盘，Round 1 的兜底只覆盖了“退出时窗口仍可见且非最小化”的情形。
2. Round 2 文档内部存在矛盾：其《修复建议》要求“拒绝最小化/零尺寸读数”（本轮已照做），而《修复后验收标准》#1 要求“恢复到最小化前的几何”。只拒绝读数、不新增捕获点，二者无法同时成立；本轮实现满足了前者，因此后者未达成。
3. 相对 Round 2 代码并非功能回归（Round 2 在该路径写入 0×0 记录后同样无法复原，且会销毁旧记录），但本版本核心交付“几何跨会话记忆”在该路径仍然静默失效。

**影响范围**

设置窗口被最小化后退出（或最小化状态下被任务栏关闭）时，本会话的窗口调整不会被记住，窗口退化为居中 `480×660` 或上一会话的陈旧位置。不崩溃、不产生幽灵窗口、不再损坏既有记录。规避方案：退出前先点 X 关闭设置窗口，或先还原窗口再退出。

**复现方法 / 运行证据**

1. 静态可证（本机执行）：
   - `grep -rn "persist_settings_geometry\|save_settings_geometry" src-tauri/src` → 产品代码仅 `lib.rs:57`、`lib.rs:266` 两个调用点、`config.rs:232` 一处定义；`src/` 前端无任何几何落盘调用。
   - `grep -rn "WindowEvent::" src-tauri/src` → 仅 `CloseRequested`(settings/tray-menu)、`Focused(false)`(tray-menu)、`ScaleFactorChanged`(main)。⟹ 从“移动/缩放”到“最小化”之间不存在任何落盘点，结论与显示器/DPI 无关，与用户操作顺序一一对应。
2. 路径可达性（沿用 Round 2 已验证的原生探针结论 + 源码）：最小化窗口 `IsWindowVisible == TRUE` 而 `GetClientRect == 0×0`；`tauri-utils-2.10.0/config.rs:2421` 默认 `minimizable: true` 且 `tauri.conf.json` 未覆盖、`decorations: true` ⟹ 标题栏最小化按钮在正常 UI 下存在。
3. 空记录/陈旧记录的最终落点：`tray.rs:247-250`（`None → center_settings_window`）、`tray.rs:274-280`（`480×660` + `center()`）；陈旧记录则经 `plan_settings_geometry` 按旧逻辑复原。
4. 本轮新单测的覆盖边界（说明为何 57/57 全绿仍未闭环）：`lib.rs:378-476` 的四个用例**只覆盖 `persist_settings_geometry` 这个纯函数**，不覆盖两个调用点在“最小化 + 本会话无 CloseRequested”组合下的接线，因此该缺陷可以在测试全绿的情况下存在。

**修复建议（择一，建议 A，或 A+B 叠加）**

- **A（推荐，符合计划原意）**：对设置窗口的 `WindowEvent::Moved` / `WindowEvent::Resized` 做约 500 ms 防抖落盘（读值前跳过最小化与零尺寸读数）。`v1.1.3-update-plan.md` 第 2 节的原文即是“在用户移动或缩放后自动持久化落盘”，该改动同时根治 Round 1 的 P3-2 与本项。
- **B（改动面最小）**：在 `AppState` 中缓存“最近一次非最小化且非零的几何”，`CloseRequested` / `RunEvent::Exit` 在实时读数被拒绝时落盘该缓存（`persist_settings_geometry` 保持现有的拒绝逻辑不变，仅在拒绝分支写入缓存值）。
- **不要只放宽退出路径守卫**（例如把 `-is_minimized` 去掉）：那会重新引入 Round 2 的 0×0 覆盖；`CloseRequested` 的最小化路径同样缺失。

**修复后验收标准**

1. 全新用户（无历史记录）：打开设置 → 移动/缩放 → 最小化 → 托盘退出 → 重启 → 打开设置：恢复到**最小化前**的物理位置与逻辑尺寸（而非居中 `480×660`）。
2. 有历史记录时同上，且不得回退为更早的陈旧记录。
3. 最小化的设置窗口经任务栏“关闭窗口”后重启同样复原。
4. 不回归：正常 X 关闭后重启精确复原；未最小化的“调整后直接退出”仍被兜底保存；任何路径都不写入 0 尺寸记录；工作区无 `*.json.tmp` 残留。
5. 新增至少一个可离线运行的纯逻辑单测：模拟“实时读数不可用（最小化/零尺寸）+ 存在历史几何”，断言被拒绝后落盘的是历史几何；把缓存丢弃、或把守卫放到覆盖缓存的位置时，该用例必须失败。
