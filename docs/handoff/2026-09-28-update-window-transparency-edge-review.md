## 1. 更新机制现状

- 当前版本号为 1.1.1（`package.json`、`src-tauri/tauri.conf.json`）。默认 `autoCheckUpdates=true`，启动 15 秒后首次检查，此后每 12 小时检查一次；用户从关闭改为开启时立即检查。`src-tauri/src/lib.rs` 的后台任务和 `src-tauri/src/commands.rs::patch_settings` 负责调度。
- 使用 Tauri updater，从 GitHub 最新稳定版的 `latest.json` 查询，按便携版/NSIS/MSI 选择 target；配置要求签名版本。检查结果存在内存的 `pending_update` / `available_update`，同一运行进程只对同一版本广播一次 `update_available`。见 `src-tauri/tauri.conf.json`、`src-tauri/src/config.rs::updater_target`、`src-tauri/src/commands.rs::check_and_store_update` / `check_and_notify_auto_update`。
- `src/App.tsx` 的主窗口监听广播，请求 Windows 通知权限并尝试发系统通知；托盘菜单监听同一事件，打开菜单时也读取已发现更新。若权限未获批准、主窗口尚未装好监听器或通知 API 失败，当前没有补发/应用内主动弹窗兜底；一次进程内的“已通知版本”标记仍可能被置位。该标记不持久化，重启后可能再次提醒。
- **不会静默自动安装。** 用户须从托盘“检查更新”/发现版本提示里点击“下载并安装”。安装版走 updater 的 `download_and_install`；便携版下载签名更新包，暂存 EXE 后启动同目录的更新助手，退出应用后替换并重启。手动检查只更新托盘内状态，不额外触发系统通知。安装失败时托盘显示通用错误，已取出的 `pending_update` 不会恢复；再次尝试需重新检查。
- 后续改进建议：由后端持久保存“发现版本、通知交付结果/时间”，让前端确认通知成功后再去重；权限关闭时在托盘状态或设置页显示可见提示；安装失败允许对同一已验证版本重试，并给出具体错误。自动安装如需新增，先定义是否需要用户确认、重启时机及便携版失败恢复。

## 2. 窗口大小为何没有持久化

- `src-tauri/src/config.rs` 仅持久化设置、主窗口用户锚点 `window-position.json` 和贴边状态 `dock-state.json`；没有主窗口或设置窗口的宽高字段。主窗口初始 380×90 只是 `tauri.conf.json` 的创建值，启动后 Rust 写临时尺寸，再由 `src/components/OverlayView.tsx::fitCapsuleSize` 按实际内容外接矩形自动调整。布局、语言、余额显隐、字体、缩放、DPI 都会改变最终尺寸；任意记住上次物理宽高可能与下一次内容或显示器不匹配。
- 设置窗口在 `tauri.conf.json` 和 `src-tauri/src/tray.rs::open_settings_window` 固定宽 380、初始高 560，允许高度 350～900。关闭时仅隐藏，所以**同一次进程内**调整高度会暂存于窗口对象；下次启动重新用默认高度，没有落盘。这是功能缺口，不是已实现但读取失败。
- 建议分开处理：主窗口保留内容驱动尺寸，持久化 `scalePercent`（已经实现），不要把自动计算的宽高作为用户偏好；如需“手调尺寸”，先明确是等比例缩放还是可变宽度/换行，再建立独立设置。设置窗口可保存逻辑像素的高度与位置，启动时按当前显示器工作区夹紧；写入带版本的窗口布局记录，损坏/旧版时回默认值。程序性贴边/展开位置继续不覆盖用户锚点。

## 3. 透明度观感核对

- 设置字段为 `backgroundTransparencyPercent`，默认 23、UI 范围 0～80。`OverlayView.tsx` 将其转换为 `--overlay-alpha=(100-value)/100`，`src/index.css` 仅在完整胶囊与贴边小窗的**背景色**上使用 `rgba(..., alpha)`。因此 23% 对应 77% 底板不透明度；数学映射方向正确。
- 边框、文字、倒计时、彩色进度条没有一起调透明。特别是完整窗/小窗的边框使用实色，最多 80% 的范围也意味着底板至少保留 20% 不透明度。在浅色/深色桌面和 Windows 合成下，视觉上可能感觉“调到很高仍然明显”；这是合理的观感反馈，但仅凭静态代码不能判定显示器上的实际合成是否异常。
- 建议先做可重复的实机对照：固定同一桌面背景与主题，截图 0/25/50/80%，分别取底板中心和背景像素，核对合成结果；边框另量，避免把边框不透明误判成底板值失效。若确认用户要“整个悬浮窗透明”，应新增独立的整体不透明度语义；若仍只调底板，则把边框 alpha 与底板协调，并在设置页加即时棋盘格/桌面预览和“仅底板”说明。不要直接改变现有字段语义，以免升级后旧设置呈现突变。

## 4. 贴边现状与 MeowpinPet 对照

| 方面 | 当前悬浮窗 | MeowpinPet 已实现 M6 |
| --- | --- | --- |
| 触发 | 仅拖拽结束，窗口外框距四边之一 ≤16 逻辑像素；四角取最近边 | 拖拽结束或成功的自主路线结束；用**可见内容边界**与工作区距离，深度为短边 10%，限制在 8～32 逻辑像素；两边同时命中则拒绝 |
| 隐藏 | 把窗口缩成屏内 46×100 逻辑像素小窗，离边 2 逻辑像素 | 沿选定边法向移出工作区，仅留下有独立锚点、可点击的探头；只保留探头输入区 |
| 显示 | 鼠标进入小窗即放大为完整胶囊；离开后 400 ms 收回 | 玩家按下探头才跳出；同一次按下可继续拖拽；不会因为悬停或鼠标离开反复收放 |
| 状态/位置 | `Free/Docked/ManualHidden`；保存用户锚点与 docked/edge，重启可恢复贴边 | `visible/hiding/hidden/emerging`；隐藏位置只在进程内，重启从安全可见位置恢复；动画超时与显示变化走安全恢复 |

当前实现入口：`src-tauri/src/dock.rs::detect_edge`、`drag_ended`、`apply_pill`、`mouse_enter`、`mouse_leave`、`restore_startup`；前端小窗在 `src/components/OverlayView.tsx`。MeowpinPet 入口：`src/windowing/edge_hiding_geometry_policy.gd`、`src/edge_hiding/edge_hiding_controller.gd`、`src/app/desktop_pet_interaction_controller.gd`、`assets/edge_hiding/default_edge_hiding_profile.tres`。MeowpinPet 需求文件第 19.15 节计划把边缘圈改为短边 25%、限制在 32～96 逻辑像素并增加启动/设置切换检查点；**现有控制器/资源仍使用 M6 的 10%、8～32，不把 M6.1 规划算作已实现。**

### 推荐的悬浮窗方案

1. **明确触发语义。** “自动贴边隐藏”开启时，只在拖拽结束后的稳定位置检查；以实际可见胶囊边界和当前显示器工作区计算距离。首版用短边约 25%、夹在 24～48 逻辑像素的可调触发带作体验候选，四角双边命中时保持原位，不随机择边。该数值是本项目待实机验证的方案，不直接照搬宠物的 32～96。关闭时停止新贴边并安全展开。
2. **把贴边后的可见物改成稳定的窄标签。** 保留两条额度进度，缩小法向厚度并贴合工作区边界；不直接复制 Godot 的屏外窗口与多边形输入，因为 Tauri/WebView 的透明区域命中行为不同。标签仍保持可点击面积，四角/任务栏/多显示器安全区均要验证。
3. **默认点击展开，展开后保持稳定。** 点击标签才显示完整胶囊，鼠标离开不立刻收回；提供清楚的再次收起操作（标签按钮/托盘菜单或拖回边缘），从展开状态可直接拖走以解除贴边。若保留“悬停预览”，作为独立可选模式且有合理延时，不能与持久展开共用模糊状态。这样借鉴 MeowpinPet 的“按下才跳出”，避免当前 400 ms 离开收起引起频繁闪动。
4. **位置和状态分离。** 保存最后一次用户拖拽后的自由态锚点；贴边标签和临时展开位置只作表现状态。重启时优先安全可见恢复；是否恢复贴边作为独立偏好确认，避免历史 `dock-state.json` 静默改变语义。显示器拔除、DPI/工作区变化、尺寸回写或位置失败时回到可见可点击位置。沿用目前按展开会话固定 `entered_cursor` 的幂等落位，不能退回实时鼠标追随；进一步消除前端 `setSize` 到后端 `dock_window_resized` 的短暂几何空档。
5. **分阶段验收。** 先验证纯几何：四边、四角、负坐标、多显示器、任务栏、100/150/200% DPI、100/175/250% 缩放、小工作区；再做真实 Windows 鼠标测试：贴边、单击展开、拖走、重复点击、设置切换、重启、屏幕拔插，展开后停留至少两次用量刷新不移动/不意外收起。与既有 Rust/前端测试一起运行。交互定稿前用可见构建让用户确认“点击展开 + 明确收起”的手感。

## 5. 全窗口鼠标穿透（本轮已实现）

- 参考 MeowpinPet `src/platform/windows/window_controller.gd::set_full_passthrough` 与 `src/desktop_control/desktop_control_coordinator.gd::set_full_passthrough`：开启前要求托盘恢复入口就绪；设置/托盘均可切换。本项目不复制 Godot 的逐语义输入多边形，当前交付的是**整块主浮窗**鼠标穿透。
- 新字段 `mousePassthrough` 默认 `false`，由 `settings.json` 持久化；旧设置通过 serde 默认值迁移。`src-tauri/src/commands.rs::set_main_mouse_passthrough` 在开启时检查常驻托盘，再调用 Tauri 原生 `set_ignore_cursor_events`。设置补丁由同一互斥锁串行，避免设置页和托盘交错把原生状态改成旧值；持久化或 Tauri 调用返回错误时回滚字段。重启恢复时若托盘或调用返回错误，清除已保存的穿透偏好，保持主浮窗可交互。
- `src/components/SettingsView.tsx` 和 `src/components/TrayMenuView.tsx` 提供同步开关，后者是主窗不可点击时的恢复入口。中/英/繁三种语言及 README 已更新。鼠标穿透时主窗口的拖动、右键菜单和贴边悬停自然收不到鼠标事件；设置窗口和托盘菜单仍可操作。
- 已运行：`npm test -- --run` 39/39；`npm run build` 通过；`cargo test --locked` 41/41；`git diff --check` 通过。`cargo fmt --all -- --check` 因仓库既有的大量 Rust 排版差异未通过，本轮没有为此批量格式化无关代码。Tauri 的 Windows `set_ignore_cursor_events` 以事件循环消息异步应用，返回成功不等于 Godot 示例中的原生状态读回；未在可见 Windows 桌面实测鼠标事件是否落到下方应用、托盘恢复和重启恢复。下一步应在真实桌面验证这些操作，尤其是贴边小窗下开启穿透、托盘关闭后能否重新拖动。

## 6. 设置面板大小与默认位置

- 当前 `src-tauri/tauri.conf.json` 的设置窗口初始为 **380×560 逻辑像素**，固定宽 380、允许高度 350～900；`src-tauri/src/tray.rs::open_settings_window` 的动态创建分支也是 380×560。页面 `src/components/SettingsView.tsx` 使用 20px 内边距、纵向堆叠和滚动条。加入多个通知及音效控件后，单列可见内容有限，“太小、频繁滚动”的反馈与现有布局一致。
- **当前没有显式居中。** 两处创建配置均没有 `center`/`set_position`；Tauri v2 此配置默认 `center=false`。首次打开落点取决于窗口系统，不保证屏幕中心。同一进程内关闭只隐藏，重新打开保留该窗口对象的当前落点；重启没有位置恢复。
- 建议将默认宽增至约 460～500、高 620～700 逻辑像素，并按工作区夹紧；较窄屏幕改为自适应宽度和清晰分组，保留滚动。首次打开显式居中到当前主屏或托盘所在屏幕的工作区；用户移动/调整后保存设置窗口的逻辑位置与高度，下次启动优先恢复并校验仍在可见工作区。不要把主悬浮窗自动计算的尺寸混入该记录。尺寸区间和分组布局需实际打开后以 100/150/200% DPI 做可读性验收。
