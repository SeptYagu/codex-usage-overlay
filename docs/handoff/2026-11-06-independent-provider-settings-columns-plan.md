# Agent 独立设置栏与设置窗口扩展方案

- 日期：2026-11-06，America/Indianapolis。
- 状态：**方案阶段；尚未修改生产代码、用户配置或运行实例。**
- 仓库基线：`701fcc3`；应用源码版本为 `v1.6.0`。
- 用户确认方向：顶部公共设置，下方 Codex、Claude、DSH 各占一栏；无需切换设置对象，能够直接查看和修改每个来源的独立配置。
- 本文的 Agent 指这三个现有用量来源，不新增同一来源下任意多个命名 profile、账号并行监控或多实例管理。

## 1. 目标与基线差距

当前并非所有设置都独立。`providerPreferences` 已分别保存监控开关、保护开关和两项阈值；连接信息及历史也按现有来源边界处理。但刷新间隔、重置提醒开关、音效模式和路径仍来自全局字段。

`SettingsView.tsx` 当前有一个 `configurationProvider`，通过“来源设置”下拉框把同一张表单投影到不同来源。刷新和提醒出现在该区域容易让用户误以为它们已经独立。窗口目前为 960×620、左右两栏，新增 Codex 文案和算法控件后也需要更多可用空间。

本次目标同时包含：

1. 三个来源同时展示，不再切换编辑对象。
2. 每栏明确保存自己的刷新、通知、音效和保护配置，修改一栏不改变另一栏。
3. 公共设置只保留一份；浮窗显示选择与后台运行、正在编辑的栏保持独立。
4. 迁移保留现有偏好、连接和历史，不额外开启保护、实时读取或外部任务。
5. 与[Codex 文案、定时继续与可选算法方案](2026-11-06-codex-custom-pause-continuation-estimator-plan.md)共同实施时有明确的配置和 UI 落点。

## 2. 布局与交互

### 2.1 窗口结构

默认窗口调整为约 **1320×800 逻辑像素**。保留可调整大小和几何位置记忆；不在每次打开时强制重置用户保存的尺寸。

| 位置 | 内容 |
| --- | --- |
| 窗口标题区 | 应用设置、版本号、当前显示来源摘要 |
| 公共设置区 | 一份可折叠的公共设置，折叠后仍显示入口和简短摘要 |
| 主区域 | 固定顺序 Codex → Claude → DSH，各来源独立设置栏 |
| 底部 | 保存失败摘要、必要的应用级提示和关闭操作；栏内错误同时保留定位入口 |

公共区包含：浮窗布局、缩放、透明度、5H／消耗速率／Credit／来源图标显隐、贴边和穿透、语言、开机启动、更新。Credit 仅在支持的来源显示，但显隐偏好继续是全局偏好。系统通知权限和音频设备可用状态也只显示一份，不能伪装成三个独立的 Windows 权限开关。

每栏头部显示来源名、监控开关、连接／健康状态、上次样本时间，以及“在浮窗显示”按钮；当前显示栏用明确标记。监控关闭或尚无可显示读数时，该按钮禁用并解释原因，保留现有可用来源切换规则。读取失败但保留有效历史读数时，允许显示该来源，并标记旧样本／错误。

### 2.2 各栏内容

| Codex | Claude | DSH |
| --- | --- | --- |
| 本机 Codex 连接和读取状态 | Claude 连接、断开和实时读取授权 | Desktop 连接、实例、账户与明确选择的暂停会话 |
| 独立正常刷新间隔 | 独立正常刷新间隔，注明实时读取最低一分钟 | 独立正常刷新间隔 |
| 5H／Weekly 重置提醒及音效 | 5H／Weekly 重置提醒及音效 | 5H／Weekly 重置提醒及音效 |
| 暂停保护、阈值及结果 | 请求保护、阈值及钩子状态 | 暂停保护、阈值及结果 |
| 自定义暂停文案、定时继续预设、5H 算法选择（按配套方案） | Claude 专属说明 | DSH 专属说明 |

保护与通知可分组；耗时诊断和长结果列表默认折叠。不要给 Claude 或 DSH 放置无实际能力的 Codex 文案／算法占位控件。长文案使用有界高度的 textarea，可调整高度或内部滚动，不把整栏撑成几屏空白。

### 2.3 响应式与可访问性

- 内容宽度足够时三栏等宽，建议窗口宽度约 1180 及以上进入三栏，每栏目标最小宽度约 360。具体断点按生产字体和翻译渲染结果校准。
- 中等宽度两栏并按固定顺序换行；最小窗口可为一栏纵向排列，三个来源始终存在，不退回下拉切换。
- 三栏模式各栏内容独立纵向滚动，栏头保持可见；两栏／一栏模式改为页面纵向滚动与自然高度，避免多层窄滚动区。任何模式都不能横向裁切设置控件。
- 公共设置展开后应保留可用主体空间；高度不足时允许整体滚动。保存错误摘要不能占据大半窗口或遮住输入。
- 控件 id 带来源前缀，例如 `codex-five-hour-threshold`；`label`、描述、错误提示都关联本栏 id。键盘顺序为公共区、Codex、Claude、DSH。
- 旧几何位置合法时继续使用，窗口较窄则自然换行；无历史或历史位置失效时使用新默认值并限制在当前工作区内。小屏和高 DPI 不能被 1320×800 的默认值挤出可操作范围。

公共区折叠状态可先只保留在设置窗口会话内；本轮不为布局偏好额外引入持久化文件。

## 3. 设置归属与 schema 3

### 3.1 数据模型

扩展现有 `ProviderPreference`，不另建第二份并行来源配置表。新增七个字段：

| 字段 | 类型 | 新安装默认 |
| --- | --- | --- |
| `refreshIntervalSeconds` | number | 60 |
| `fiveHourResetNotification` | boolean | true |
| `weeklyResetNotification` | boolean | true |
| `fiveHourSoundMode` | `windows` / `custom` | `windows` |
| `weeklySoundMode` | `windows` / `custom` | `windows` |
| `fiveHourSoundPath` | string / null | null |
| `weeklySoundPath` | string / null | null |

保留已有 `monitorEnabled`、`protectionEnabled`、`fiveHourThresholdPercent`、`weeklyThresholdPercent`。来源配置的权威位置为 `providerPreferences.codex/claude/dsh`。新 schemaVersion 为 **3**。

示例：只修改 Claude 的刷新间隔及 Weekly 提醒：

```json
{
  "providerPreferences": {
    "claude": {
      "refreshIntervalSeconds": 120,
      "weeklyResetNotification": false
    }
  }
}
```

语言、显示和系统集成仍使用根设置。连接参数继续按现有专属字段保存，不在本轮无必要地重命名 DSH／Claude 全部字段。配套方案的三个 Codex 专属字段也保留原 JSON 位置和 Codex 限定语义，通过 Codex 栏编辑；不要为了三栏布局把它们复制到三个来源。

### 3.2 顶层旧字段的兼容规则

原顶层刷新／通知／音效字段只作为旧配置迁移输入及当前显示来源的兼容镜像；schema 3 的新 UI 必须发来源明确的嵌套 patch，后台只读 `for_provider(provider)` 的投影。不得让顶层值继续反向覆盖所有来源。

扩展 `mirror_display_preferences()`，在显示来源改变或对应来源设置保存后同步旧字段；但镜像更新不生成第二次设置事务，不增加学习／通知副作用。扩展 `for_provider()` 将七个字段投影到指定 runtime，使现有轮询、通知与音频执行路径读取正确值。

旧顶层字段若经兼容 API 写入，明确只作用于已提交设置中的当前显示来源；不能以 UI 临时选择、另一个栏或请求结束时的新显示来源推断目标。若同一 patch 同时写显示来源和任意旧来源字段，或同一字段既顶层写又嵌套写，整体拒绝并提示使用明确来源。嵌套 patch 与显示来源切换可同事务提交，因为目标来源已明确。

刷新 API 的后端合法范围保留现有 15–3600 秒，UI 常用选项保留 30／60／120／300 秒。迁移得到的其他合法值应以“自定义：N 秒”显示并保留，不能因下拉框没有选项而静默改成 60 秒。保留现有声音格式、路径长度和缺失文件处理；保存路径不等于复制音频文件。

## 4. 旧配置迁移

实现版本化、幂等的迁移链：先补齐旧的来源监控／保护结构，再将 schema 1／2 迁移至 3。现有 `migrate()` 无条件写 `schema_version = 2`，实施时必须修改，否则会把新配置降回旧版本。

迁移步骤：

1. 读取 raw JSON，保留每个新字段是否真实存在的信息。不要先套 `ProviderPreference::default()` 再推断缺失，否则会分不清“用户关闭提醒”和“字段尚不存在”。
2. 先按现有规则恢复已有的监控、保护、阈值；保留各来源明确保存的合法值。
3. 对每来源新增七字段，已有合法的嵌套值优先；缺失字段从旧顶层对应值复制；旧值也缺失／无效时才采用新安装默认。部分迁移配置不能覆盖已独立的值。
4. 保留保护开关及实时读取授权。监控关闭时保护仍关闭；迁移通知设置不意味着开启未启用的监控，不立即补发旧周期通知。
5. 不修改连接、账户、会话绑定、学习、额度重置去重、窗口状态或历史文件命名。自定义音效只保留原路径。
6. 完成规范化后写入 schema 3，沿用已存在的原子保存机制；失败保留原磁盘文件，给出可恢复错误，不宣称迁移成功。

schema 3 再加载只能修复单个缺失／非法字段，不能重新从全局镜像覆盖已独立的设置。`false`、null 路径及合法零阈值均需按各自字段规则区分。未来更高 schema 不能被当前程序自动降级重写，应报告版本不支持并停止写配置。

首次保存后可再次加载并逐字段比对。回退旧程序只能获得顶层镜像，无法表达三套独立偏好；发布说明必须指出这点，不能承诺旧程序编辑后再升级仍保留全部新字段。

## 5. 前端组件和保存流程

拆分 `SettingsView`，建议新增：

- `CommonSettingsSection.tsx`：公共设置及全局权限／设备状态。
- `ProviderSettingsColumn.tsx`：接收固定 `provider`、本栏 preference、monitor snapshot 和已保存全局设置。
- `ProviderNotifications.tsx`：可复用的独立提醒与音效区域。

Codex、Claude、DSH 专属内容使用现有或新增的子组件；只抽象真正相同的区域，不用大量布尔参数把三种连接流程揉成一个表单。

移除 `configurationProvider`、来源设置下拉框和隐式字段重定向。保存入口改为 `patchProvider(provider, patch)` 与 `patchGlobal(patch)`，前者在构造 patch 时绑定来源。每栏的防抖、草稿及错误也按固定来源绑定，不能在计时器触发时才读取当前浮窗来源。

继续复用 `mergeSettingsPatch/mergePendingPatches` 的来源内深合并，但补齐跨栏并发覆盖测试：短时间分别拖动 Codex 和 Claude 滑块，合并结果必须同时包含两栏 patch；只修改一个嵌套字段不能重置同栏其他字段。

根设置写入仍走现有串行队列和 settings revision。失败仅撤销该次乐观 patch，在最新已保存设置上重放其余待保存项；不能用旧整份快照回滚掉其他栏已成功的保存。显示“正在保存／保存失败”的信息应能定位来源和字段。

“在浮窗显示”只更新 `provider`，不修改任何栏的监控或保护。关闭监控仍关闭该来源保护并取消未发送动作；其他栏的状态、草稿、历史和运行任务不受影响。

## 6. 后台轮询、通知与试听隔离

### 6.1 Runtime 同步与正常刷新间隔

`Registry::synchronize` 继续每来源应用 `for_provider()`。只有实际投影内容改变的 runtime 才递增其设置版本、重算策略或唤醒；扩展 preference 表不应使所有 runtime 因根对象不同而重复工作。

修改一栏正常刷新间隔时，仅重算该来源 polling deadline 并中断它旧的等待，以现有调度器决定下一次读取；不得清空历史、重新创建连接、取消无关来源的读取或强制插入重复样本。耗时的额度请求仍合并，不能因修改间隔产生并行重复读取。

每来源继续独立应用保护加速、失败退避和服务端 Retry-After，正常间隔不是实际间隔的无条件保证。Claude 实时读取仍共享一分钟节流；桥接模式的新样本仍由 Claude Code 产生。栏内同时展示用户正常间隔与适用的实际等待原因，避免把 30 秒选择解释成一定每 30 秒发请求。

修改通知开关或音效只更新配置，不产生额度读取、不使旧样本变新、不重置周期去重、不立即通知。正在运行的通知使用已捕获且有来源身份的执行上下文；下一次真正新周期使用新配置。

### 6.2 Windows 通知与本地状态

继续复用来源独立的 reset state；提醒开关、声音模式和路径改从该来源 runtime 投影读取。后台来源重置也可提醒，不取当前浮窗来源的配置。通知标题或正文带明确来源名。

Windows 通知权限和音频输出设备是全局资源。权限查询与授权由公共入口管理；不能为每栏制造重复授权请求。每来源提醒开关仍保存用户意图，权限不可用时说明原因，不擅自把三个开关全改成关闭。

### 6.3 音效选择和试听

`SoundPicker` 当前只有 `kind`；`preview_sound` 也只接收额度种类，`sound_preview_finished` 无播放身份。直接复制三个组件会把同类错误和结束事件广播给多个栏，这是本轮必须改的接线。

为选择／试听调用及播放事件补齐上下文：`provider`、`kind`、唯一 `playbackId`；状态回执按调用类型关联，必要时带 `sourceGeneration`。后端通过明确来源查找已保存路径，不能通过当前显示来源查找。文案、文件选择和错误提示只更新发起栏。

沿用一个全局音频执行器，不创建三个互相抢设备的播放器。每次试听新请求明确替换旧试听；旧结束／错误回执只清除旧 `playbackId`，不能把新试听标成结束。本栏“停止试听”只停止匹配 ID 的试听；全局停止可以有独立明确入口。真实重置音频继续沿用执行器优先级和限长策略，不能因试听把真实通知标成已播放或重复播放。

组件卸载或窄屏换行不触发再次播放。连接、试听、文件对话框等异步操作完成时还需核对发起上下文，不能把结果写到另一栏。

## 7. 与 Codex 新功能方案的衔接

配套方案继续负责文案、定时继续、算法数学及候选发布；本方案负责三栏结构、共用项拆分、schema 3 和声音事件隔离。共同实施时：

1. 优先完成 schema 3、来源明确的 patch、`for_provider` 投影和三栏组件，再接入 Codex 专属控件。
2. 配套方案中“设置来源选中 Codex 才展示控件”改为“控件固定属于 Codex 栏”；不再有需要切换的编辑来源。
3. 配套方案中“纯新增字段不必提升 schema 2”的前提仅适用于独立实施；共同实施以本方案 schema 3 为准，不能运行两套互相覆盖的迁移。
4. Codex 文案和算法仍只修改 Codex 的功能状态；它们的保存不能触发 Claude／DSH 重新读取。新增根专属字段在其他 runtime 应忽略或按固定值投影，避免全局对象比较引发无意义的版本变更。
5. 定时继续仍由浮窗计算服务器重置时间＋120 秒，发送 `{resume_at}` 对应的完整指定时间；三栏布局不改变时间语义。
6. 算法切换依然只重投影 Codex 缓存；来源刷新间隔分离后，个性化学习状态按 Codex 实际采样间隔判断。

两份方案都不授权本次文档任务创建外部任务、连接账户或向真实聊天发送消息。
