## 二、审查发现与缺陷清单

### R3-1（P2）展开过渡矩形已闭环，但尺寸回写后的**最终矩形**仍不包含鼠标，左右边缘约 31% 的小浮窗面积落在窗口外 → 悬停展开仍可能在 400 ms 后收起

- **文件与行号**
  - `src-tauri/src/dock.rs:461-488`（`mouse_enter`：`set_full_size` → `place_full_for_transition`，过渡期矩形已覆盖小浮窗）
  - `src-tauri/src/dock.rs:634-646`（`window_resized`：前端 `dock_window_resized` 到达后无条件调用 `place_full_at_anchor`）
  - `src-tauri/src/dock.rs:721-757`（`place_full_at_anchor`：用 `window.outer_size()`（= 回写后的**真实胶囊**尺寸 871×211 物理）把**保存的松手锚点** `(left, top)` 夹紧到 work area 后落位；不再参考小浮窗矩形）
  - `src-tauri/src/dock.rs:326-377`（`pill_geometry`：左右边缘小浮窗高 `PILL_HEIGHT_LOGICAL=100`×factor = 306 物理，恒为胶囊高 211 物理的 1.45 倍）
  - `src/components/OverlayView.tsx:95-114`（`fitCapsuleSize` → `invoke('dock_window_resized')`，即最终落位的触发点）
  - 对照契约：`docs/v1.1.0-technical-spec.md:407`（§3.4「**展开后的矩形须覆盖鼠标当前所在的小窗命中区域，避免刚展开就收到 `mouseleave`**」）；`docs/handoff/2026-09-28-workbuddy-code-review-round2-handoff.md:31,44-51`（第 2 轮已识别该"结构性上限"并要求"在规格层记录该已知几何，或把「覆盖」目标明确为「覆盖鼠标当前位置」，且必须显式断言并更新 §3.4 文案"）
- **触发条件**：`auto_edge_hide=true`、窗口贴**左/右**边缘收起为小浮窗（由拖动落位，锚点=松手胶囊中心），鼠标从屏幕内侧移入小浮窗的**上下外侧带**（距小浮窗上/下沿约 47.5 物理 px 内，约占小浮窗高度 31%）。
- **实际行为与期望行为**
  - 期望（§3.4 + 第 2 轮目标）：悬停展开全程鼠标保持在窗口内，不触发 `mouseleave`、不收起。
  - 实际：`mouse_enter` 过渡期矩形确实包含整个小浮窗（本项已修好）；但**紧随其后**前端回写真实胶囊尺寸触发 `window_resized` → `place_full_at_anchor`，窗口被落到"保存松手锚点 + 真实胶囊尺寸"处。由于胶囊（211 物理高）比小浮窗（306 物理高）矮 1.45 倍，二者同心而前者更矮，小浮窗的上/下各约 47.5 px 落在最终矩形之外。若鼠标此刻正处于该外侧带，最终矩形不再包含鼠标 → 400 ms 后 `collapse_if_current`（`pointer_inside=false`）收起，表现为"展开后一闪即回"，与 D6 的用户可见症状相同，只是在尺寸回写之后发生。
- **根因**：本轮只把"覆盖"契约实现到**过渡期**；`place_full_at_anchor`（最终落位）仍按 §3.4 的"恢复用户锚点 + 夹紧"落位，**不保证包含鼠标当前点位**。第 2 轮已要求把"覆盖"目标显式改为"覆盖鼠标当前位置"并更新 §3.4，或记录该结构上限；本轮既未改判定逻辑，也未更新 §3.4/预览说明，故 §3.4 的覆盖要求在**已展开（尺寸稳定）态**仍然不满足。
- **影响范围**：左右边缘（各约 31% 的小浮窗面积不覆盖）、上下边缘基本覆盖（小浮窗宽 306 < 胶囊宽 871）；仅影响"悬停展开"主交互，无数据损坏（`window-position.json`/`dock-state.json` 不被写坏）；有规避：把鼠标移回窗口内即可取消待收起定时器（`enter_pill()` 置 `pointer_inside=true` 并递增 `timer_generation`）。
- **复现方法/验证证据**（按源码公式定值演算，参数：`sf=1.75`、`scalePercent=175`、`show_credits=true`、work area 2560×1440、内容胶囊实测 871×211 物理——与第 1/2 轮同源；`pill_geometry` 数值已由仓库自带单测 `pill_geometry_swaps_dimensions_for_top_and_bottom_and_scales` 交叉印证）
  - 松手锚点取"右边缘右对齐"的合法位置：`saved=(1689,400)`（`(1689+871)−2560=0 ≤ 阈值 28`）。
  - 拖动结束时 `anchor_center = saved + 胶囊尺寸/2 = (2124, 505)`（`dock.rs:419-427`），贴边后小浮窗 `pill_geometry(Right,…,(2124,505)) = (2415, 352, 141, 306)` → y∈[352,658]。
  - `mouse_enter` 过渡期矩形 `transition_rect(Right, work, (674,306), (2124,505)) = (1886, 352, 674, 306)` → y∈[352,658]，**包含**小浮窗（本项已修好）。
  - 尺寸回写后 `place_full_at_anchor`：`clamp_position((1689,400), (871,211), work) = (1689,400)` → 最终矩形 `(1689,400,871,211)` → **y∈[400,611]**。小浮窗 y∈[352,658] 中 `[352,400)`（48 px）与 `(611,658]`（47 px）落在窗口外，合计 95/306 = **31.0%** 不覆盖。
  - 反例：鼠标进入小浮窗上带 `y=360`（在过渡期矩形内）→ 尺寸回写后 `360 < 400`，鼠标落在窗口外；静止不动则 400 ms 后收起。
  - 现有测试未覆盖：新增单测 `transition_rect_covers_pill_rect_on_all_edges`（`dock.rs:1133-1166`）只断言**过渡期**矩形包含小浮窗，未断言 `window_resized`（`place_full_at_anchor`）后的最终矩形包含鼠标/小浮窗；`place_full_at_anchor` 无任何包含性断言。
  - **未验证环节（如实声明）**：本机自动化会话无可见 Tauri 桌面窗口，无法实测"窗口在静止鼠标下缩小后 Windows/WebView2 是否投递 `mouseleave`"。因此"最终矩形不包含鼠标"是**确定结论**（纯几何），而"是否必然收起"依赖该 leave 语义（第 1/2 轮同样列为未验证）。
- **修复建议**（审查轮不落码，仅供参考）
  1. 让"尺寸回写后的最终落位"以**包含鼠标当前点位**为目标：例如把 `place_full_at_anchor` 的结果与「当前小浮窗矩形 / 鼠标点位」取并集后再夹紧（贴边轴贴边、另一轴保证包含点位），或在 `window_resized` 时按"展开前记录的小浮窗矩形"二次修正；
  2. 或按第 2 轮建议显式把 §3.4 的"覆盖"目标定义为"覆盖鼠标当前位置"，并在落位时夹紧到该点；同时更新 §3.4 文案；
  3. 无论采用哪种，均应补一条**纯几何单测**：对左/右边缘、若干松手偏移，断言 `window_resized` 后的矩形包含小浮窗矩形（或鼠标点位），作为 D6 的真正闭环判据。
- **修复后验收标准**
  1. 新增 Rust 纯几何单测：左/右（及上/下）边缘、吸附阈值内若干松手偏移下，`window_resized` 后的**最终矩形**包含小浮窗矩形（若改判为"覆盖鼠标位置"，则断言包含小浮窗的任意点，并同步更新 §3.4 文案）；
  2. 实机（可见桌面，左右边缘各一次）：鼠标停在小浮窗上/下外侧带，展开后 500 ms 内不收起、无可见跳变；
  3. 记录 `window.inner_size()` 与胶囊 `getBoundingClientRect` 换算值及最终矩形实测值（±1 px）。

## 三、待确认风险与未验证项

1. **（新引入的窄竞态，待确认）过渡期落位与新落位意图不一致**：`enter_pill()` 同步置 `expanded=true`（`dock.rs:187-197`），其后 `mouse_enter` 异步执行 `place_full_for_transition`；同一时刻若一次用量读取完成并调用 `keep_docked_in_work_area`（`notify.rs:169`，默认每 60 s 一次），其 `expanded` 分支会执行 `place_full_at_anchor`（`dock.rs:608-611`）——即把窗口拉回"保存锚点 + 临时尺寸"，从而**抹掉本轮新增的过渡期覆盖保证**。修复前两者落位目标相同（都是 anchor），竞态无害；本轮拆分后目标不同，竞态可短暂破坏覆盖。窗口期约"一次 IPC 往返 + 一次 React 渲染"，命中概率低且可被随后的 `window_resized` 纠正。缺少证据：无可见桌面窗口无法实测时序；建议在 `mouse_enter` 过渡期间用一个"transitioning"标志让 `keep_docked_in_work_area` 让位，或复核实机无异常。
2. **`mouseleave` 语义未验证**（沿用前两轮）：窗口在静止鼠标下缩小后是否投递 leave，决定 R3-1 的可见表现是"收起"还是仅"命中区空洞"。需可见桌面实测；建议以"鼠标不动 500 ms 不收起"为判据。
3. **上轮复审验收标准第 2、3 条的实机证据仍缺失**：`docs/handoff/...round2...md:50-51` 要求"四边实机无收起/无跳变"与"记录 `window.inner_size()` 与胶囊尺寸换算值（±1 px）"；本轮 diff 仍只含代码与单测，无任何实机测量/截图。
4. **方法学残余**：`cargo test/check` 以 `--locked` 离线复用本机缓存运行；无可见桌面窗口，四边实机手感、任务栏四边、DPI 切换与显示器拔插（V2/V3/V6）未实测。R3-1 的结论基于源码公式定值演算 + 仓库自带几何单测数值交叉印证。
