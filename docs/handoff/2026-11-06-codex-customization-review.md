# Codex 功能源码审查

日期：2026-11-06。基线：`47c38a0`。已检查配置恢复、投递取消、周期 ledger、时间生成、模型因果接线、显示缓存与真实发布路径。以下是修复前发现，不代表已安装版本行为。

## 发现

1. **P2：整批超时的未知投递状态未完整展示。** 发送后遇到批次取消时，guard 会阻止重发，但尚未把目标 telemetry 从 requested 改为 unknown。用户可能看到持续“请求中”。需在取消清理时同时登记未知状态，并扩展现有 deadline 回归检查其解释。
2. **P2：生产投递未核对 JSON-RPC 响应 ID。** 新 observed 通道使用基线解析器，只检查 result，未将回执 ID 与本次 request ID 比较。需在该通道接收时显式核对；不匹配属于提交结果未知，不能计成功或自动重发。
3. **P3：学习状态只按用户正常间隔判断会误报。** 正常设置为 120 秒、但保护已加速到 15 秒时，不应仅凭 120 秒显示“新学习暂停”。需使用实际策略及真实观察间隔，继续保留已有效模型供显示。
4. **P3：周期 ledger 容量达到上限后缺少可见解释。** 当前安全拒绝发送，但界面没有说明。需给出固定原因码，不能靠淘汰有效／未知记录恢复发送。
5. **验证补充：连续校准目前已有数学边界与恢复测试，但尚无独立跨语言轨迹对照。** 增加无个人数据的确定性合成轨迹，比较每个 origin 的预测与在线更新；它证明实现一致性，不宣称预测准确率改善。

## 已确认

- `{resume_at}` 在浮窗计算服务器 reset＋120 秒，带完整日期、秒、UTC 偏移和系统时区；无效时间／时区回退纯暂停，不把延迟运算交给聊天。
- 默认不创建定时任务，预设仅在明确点击后保存；三种语言的任务 prompt 都包含唤醒后先停用自身。
- 活动期变化、文案变化和保护开关不清除已确认额度周期；部分写出及超时不盲目重发。
- 算法切换通过真实 patch 及发布 sink 验证，不读取、训练、修改学习文件或清除读取错误；同秒投影有独立显示序号。
- 前端 173／构建、Rust 461、无警告 all-targets 检查、Edge 634＋252 及 13 份重生成回测文件的字节一致检查通过。

此阶段只记录审查；上述发现将在独立修复提交处理。真实聊天投递、定时实际唤醒和已安装验收未执行。
