# 独立设置栏源码审查

审查日期：2026-11-06。审查基线：`ee14628`。范围为配置迁移、真实设置入口、Registry 同步、三栏组件、音频请求和事件；这是源码与测试审查，不是已安装版本实测。

## 发现与修复要求

1. **P2：旧试听请求的迟到失败可能覆盖新试听。** `SoundPicker.preview` 已为请求分配 ID，但异步调用的 catch 无条件清空当前 ID 和 previewing。用户先试听、停止、再试听时，第一个请求的迟到拒绝会让新试听显示为停止。修复需在完成／失败／停止路径比对请求 ID，并用可控 Promise 验证。
2. **P2：音频错误事件出现重复 JSON 字段。** `PlaybackErrorEvent` 自带 kind，同时 flatten 的 `PlaybackContext` 也包含 kind。值虽通常相同，重复键不是稳定 wire 契约。上下文仅保留 provider/playbackId，kind 由错误事件本身提供；完成事件按唯一 ID 关联。补充序列化和并行组件事件隔离验证。
3. **P2：早期部分迁移配置仍可能丢失明确偏好。** schema 小于 2 的迁移会重建已存在的来源项；异常 sound mode 又可被 serde 的兜底当成显式有效 windows，从而阻止继承旧自定义偏好。应只补缺失来源，读取时严格判断 mode 有效性；补充部分迁移、坏模式和显式 null 的回归。
4. **P3：音频队列测试辅助方法产生非测试构建警告。** `clear_previews` 现在仅由单测使用，限制在 cfg(test)。

## 已确认的行为
