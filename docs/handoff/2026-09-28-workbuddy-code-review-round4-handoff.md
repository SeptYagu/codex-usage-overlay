## 二、审查发现与缺陷清单

### R4-1（P2）展开态落位以**实时鼠标**为输入、且仅当鼠标仍在命中区内才夹紧 → 每次后台重排都按当前鼠标位置搬动已展开窗口（最大 96 物理 px），鼠标跨出命中区边界时还会把窗口放到鼠标之外，400 ms 后意外收起

- **文件与行号**
  - `src-tauri/src/dock.rs:934-959`（`place_docked_expanded`：取尺寸、锚点、参考矩形并落位）
  - `src-tauri/src/dock.rs:947-954`（`reference = manager.hover().pill` + `cursor_within(...)`：即"鼠标是否仍在小浮窗命中区内"的开关）
  - `src-tauri/src/dock.rs:1003-1009`（`docked_expanded_final_rect` 自由轴调用 `cover_cursor`）
  - `src-tauri/src/dock.rs:1025-1035`（`cover_cursor`：夹紧到 `[鼠标−尺寸+1, 鼠标−1]`）
  - `src-tauri/src/dock.rs:697-706`（`keep_docked_in_work_area` 展开分支**本轮改为**调用 `place_docked_expanded`）
  - `src-tauri/src/dock.rs:727-749`（`window_resized` 同样调用它）
  - 触发点：`notify.rs:169`（每次用量拉取，默认 60 s）、`commands.rs:246`（设置/几何变更）、`lib.rs:64`（DPI/缩放变更）、`src/components/OverlayView.tsx:95-114`（内容尺寸变化 → `dock_window_resized`）
  - 被该实现直接违反的规格条文：`docs/v1.1.0-technical-spec.md:414`（"两者对同一 (边, 尺寸, 锚点, 鼠标点) 恒得同一矩形、不会互相拉扯"）
- **触发条件**：`auto_edge_hide=true`；窗口贴**左/右**边缘收起为小浮窗；鼠标从外侧带进入小浮窗触发展开（该次落位被鼠标夹紧）；随后鼠标移到展开胶囊上**但离开小浮窗命中区矩形**——左/右边缘命中区仅 141 物理 px 宽，胶囊宽 871，胶囊绝大部分面积都在命中区之外，故会话中必然发生。之后任意一次程序性重排（≤60 s 的用量刷新，或任何内容尺寸变化）即命中。
- **实际行为与期望行为**
  - 期望：同一展开会话内（边、尺寸、锚点不变）落位应稳定/幂等；后台刷新不应搬动已展开窗口，更不应把鼠标甩出窗口。
  - 实际（两步皆由纯几何确定，见"复现方法/验证证据"）：
    1. 鼠标仍在命中区内时，最终矩形自由轴被夹紧到 `[鼠标−尺寸+1, 鼠标−1]`，即**窗口自由轴 = 当前鼠标坐标的函数**。175%、右边缘、`capsule()`=871×211、pill=141×306、work 2560×1440、`anchor_center=(2124,505)` 下：鼠标 y=352 → 窗口 y=351；鼠标 y=657 → 窗口 y=447；**同一会话内自由轴行程 96 物理 px ≈ 55 逻辑 px ≈ 胶囊高度的 45%**。因此每次后台重排都会把窗口瞬移到"夹紧鼠标"的那一位。
    2. 鼠标一旦离开命中区（x < pill.x=2415），`cursor_within` 返回 `None` → 退化为 `anchor_center` 居中（y=400）。若此时鼠标仍指在胶囊内但贴近其下沿，重排后窗口 [400,611] 不再包含 y=657（差 46 px）→ `mouseleave` 的几何前提成立 → `leave_window`（`dock.rs:285-298`）起 400 ms 折叠定时器 → `collapse_if_current`（`dock.rs:315-332`）见 `pointer_inside=false` → **展开态被收起**。
  - 与规格文案矛盾：§3.4 的"恒得同一矩形、不会互相拉扯"只在鼠标坐标冻结时成立；会话内鼠标必然移动，尺寸回写路径与后台刷新路径因而给出**不同**矩形并互相拉扯——正是该文案声称已消除的现象。
- **根因**：把本应只在"权威尺寸回写**那一次**"生效的"覆盖鼠标"契约，延伸到了整个展开会话的**每一次**重排，却把输入取为**实时鼠标坐标**，并以"鼠标是否仍在小浮窗命中区内"作开关。命中区（141 px）远小于展开窗口（871 px），开关必然被反复跨越，函数对同一会话不再幂等；而开关关闭方向（退回锚点居中）没有任何"不得把上一刻仍在窗口内的鼠标点甩出去"的约束，于是产生一次可达 47 px 的位移，足以让鼠标落到窗口外。
- **影响范围**：左/右边缘（上/下边缘自由轴行程为 0，不受影响）；只影响悬停展开态的窗口位置稳定性与可用性；无数据损坏（`window-position.json`/`dock-state.json` 不被写坏）；有规避：把鼠标移回命中区即停止搬动，或把鼠标移到窗口中上部使 400 ms 折叠不触发。
- **复现方法/验证证据**（仓库外临时目录，未入库，`git status` 干净；按源码公式逐点枚举，参数与第 3 轮 R3-1 同源：sf=1.75、scalePercent=175、work 2560×1440、capsule 871×211、`pill_geometry(Right,…, (2124,505)) = (2415,352,141,306)`）
  - 证据 A（窗口自由轴随鼠标移动）：`docked_expanded_final_rect(Right, work, 871×211, (·,505), Some((2435,352)))` → y=351；`Some((2435,412/472/552))` → y=400；`Some((2435,612))` → y=402；`Some((2435,657))` → y=447。行程 96 px。
  - 证据 B（命中区开关的跳变，最小反例链）：
    1. 鼠标在命中区内 (2435,657) → 回写落位 y=447 → 窗口 y∈[447,658]，鼠标被覆盖 ✓；
    2. 鼠标左移出命中区到 (2375,657)——**仍在当前窗口 [1689,2560]×[447,658] 内**；
    3. 下一次重排（用量刷新或内容尺寸回写）：`cursor_within(pill)` → `None` → y=400 → 窗口 y∈[400,611]；
    4. 鼠标 y=657 > 611 → **覆盖失败 46 px** → 判定 `mouseleave` 的几何前提成立 → 400 ms 后收起。
    对称反例：命中区内 (2435,352) → y=351（窗口 [351,562]）→ 鼠标移到 (2375,352) → 重排后 y=400 → 鼠标在窗口上方 48 px。
  - 证据 C（四边行程）：Left 97 px、Right 97 px、Top 0 px、Bottom 0 px。
  - 现有测试为何未覆盖：本轮新增的 4 条测试（`dock.rs:1438-1472`、`1476-1496`、`1498-1508`、`1510-1542`、`1544-1578`）全部只**单次**调用 `docked_expanded_final_rect` 并断言"这一次的矩形包含鼠标"，没有任何测试断言**同一会话（同边/同尺寸/同锚点）在不同鼠标坐标下多次落位结果一致**，也没有断言"重排不得把上一刻仍在窗口内的鼠标点变成窗口外"——这正是 R4-1 的漏洞所在（测试有效但样本维度不足，不构成假阳性）。
- **修复建议**（审查轮不落码，仅供参考）
  1. 让展开会话落位**幂等**：在权威尺寸回写落位时把结果矩形（或仅自由轴原点）记入 `Hover`，其后同一会话的所有重排直接复用该矩形，仅在尺寸/边/锚点变化时重算。这样 `keep_docked_in_work_area` 不再以实时鼠标为输入，证据 A 的搬家与证据 B 的开关跳变同时消失。
  2. 若保留现有结构，则必须给"退回锚点居中"补约束：新矩形应仍包含"重排前一刻的鼠标点"（当鼠标已经进入展开窗口时，可把参考从 `pill` 改为当前窗口矩形继续以鼠标为目标）；但该方案仍会让窗口随鼠标搬家，不建议单独使用。
  3. 同步文档：把 §3.4 第 2 阶段明确为"**仅在权威尺寸回写那一次**以鼠标为目标，其后冻结"，并删去 `docs/v1.1.0-technical-spec.md:414` 中"恒得同一矩形、不会互相拉扯"的过强表述（其成立前提是鼠标坐标冻结）。
- **修复后验收标准**
  1. 新增 Rust 纯几何单测：(i) 同一 (边, 尺寸, 锚点) 下，对命中区内多个不同鼠标点连续两次落位，断言**矩形完全相同**；(ii) 构造"鼠标先在命中区内（被夹紧）→ 随后移出命中区但仍在当前窗口内"的序列，断言重排后的矩形仍包含该鼠标点。
  2. 断言落位半径有界：任何一次重排都不得把上一矩形的鼠标点甩出窗口。
  3. 实机（可见桌面，左/右边缘各一次）：悬停展开后把鼠标停在胶囊内任意位置 ≥2 分钟（跨过 ≥2 次用量刷新），窗口不移动、不收起。

## 三、待确认风险与未验证项
