# 需求记录：系统托盘菜单宽度策略优化（回归紧凑设计）

日期：2026-09-29  
状态：待规划实施（Backlog / Next Iteration）  
关联版本：v1.1.3 交付后用户反馈  

---

## 一、问题背景

在 v1.1.3 版本中，托盘菜单在“检查更新”文案后追加了当前版本号展示（如 `检查更新 (当前版本: v1.1.3)`）。  
为防止文本换行，v1.1.3 引入了前端内容测量与后端动态自适应宽度机制：
- 机制：通过 `scrollWidth` 抓取最长菜单项宽度并叠加 `+20px` 内边距，再经由 `layout_tray_menu` 将原生窗口尺寸撑宽（范围约束在 300~500px）。
- 现象：导致右键点击系统托盘图标时，弹出的菜单整体宽度明显变宽，原有紧凑精致的托盘菜单视觉被打破。

---

## 二、实际表现与用户反馈

- **实机表现**：实际在常见分辨率、DPI 缩放与系统字体渲染下，追加版本号后的完整文案（如 `检查更新 (当前版本: v1.1.3)`）在原版紧凑宽度（300px）下**完全能够正常单行容纳，并不会发生折行或溢出遮挡**。
- **用户反馈**：当前的自适应撑宽算法存在“过度预留 / 过度撑宽”问题，使得托盘菜单在视觉上显得笨重、不协调，用户明确希望恢复原有紧凑的托盘菜单尺寸。

---

## 三、后续优化需求目标

1. **取消过度撑宽机制**：
   - 将托盘菜单宽度恢复为紧凑默认值（固定为 300px，或收敛为仅当文本发生不可避免的物理溢出时才最小幅度微调）。
   - 去除前端测量中不必要的多余 padding 膨胀逻辑。
2. **保持单行优雅排版**：
   - 继续保留 CSS 的 `.tray-menu-item { white-space: nowrap; }`，确保文字绝不丑陋折行。
3. **视觉风格回归**：
   - 确保托盘菜单保持轻量、精致、符合原生桌面托盘习惯的紧凑视觉体验。
