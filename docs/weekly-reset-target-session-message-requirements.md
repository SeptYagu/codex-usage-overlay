# 周额度重置后向指定会话发送消息：需求文档

**状态：** 需求草案，供公开版实现与验收使用

**日期：** 2026-11-24

**范围：** Codex Usage Overlay 公开版的 Codex 与 Antigravity 来源

## 1. 目标与用户场景

用户分别为 Codex 和 Antigravity 指定一个工作区、该工作区内的一个现有会话，以及一段消息（例如 `hi`）。Overlay 确认对应来源的**每周额度进入新周期**后，自动把这段消息作为用户消息发送到所选会话。每个来源、账号、额度池及周额度周期最多自动提交一次。发送时默认选用该来源当前可用的低档模型及其**最低受支持的思考深度**；用户可在设置中改选模型和思考深度。

此功能是独立的“重置后发送消息”操作，不由系统通知开关、提示音、低额度暂停或恢复模板开关控制。初次安装和升级后默认关闭；启用前必须完成目标和消息配置。示例 `hi` 仅用于说明，不能在用户未填写消息时作为隐式发送内容。

## 2. 现状与实现边界

- 公开版已经分别监控 Codex 与 Antigravity 配额，并有每周重置检测和通知状态。现有 [`notify.rs`](../src-tauri/src/notify.rs) 的周额度分支主要根据前后 `resetsAt` 和本机时间判断通知；新功能须增加新鲜样本、账号、额度池和投递去重约束，不能仅凭倒计时到零、旧缓存或显示层投影发送。
- Codex 已有面向**活动会话**的 `list_threads` / `send_message_to_thread` 暂停桥，见 [`pause_control/transport.rs`](../src-tauri/src/pause_control/transport.rs)。新功能需要枚举并验证用户选择的**特定会话**，包括其空闲状态；不能复用“向所有活动会话发送暂停”的筛选与广播语义。当前暂停桥发送参数没有模型/思考档位，新功能需要单独传入并核实这两个参数。
- Antigravity 当前只接入配额读取和低额度 `PreInvocation` 钩子，没有现成的会话消息投递器。官方 CLI 文档说明 `agy -p` 可发送单次提示、`--conversation` 可指定已有 CLI 会话，`--model` 和 `--effort` 可限定本次调用；这构成候选实现路径，不等于已验证目标工作区和原会话都能准确接收。参见 [Headless mode](https://antigravity.google/docs/cli/headless/)、[Resume command](https://antigravity.google/docs/cli/commands/resume/) 与 [Effort command](https://antigravity.google/docs/cli/commands/effort/)。
- Antigravity 文档中的 Desktop 会话“导入 CLI”会克隆会话历史。克隆出的 CLI 会话不满足“向指定原会话发送”。若某类会话没有可验证的原会话投递接口，设置中应显示该目标暂不支持，不能自动导入、复制或改投其他会话。

## 3. 设置与用户流程

在 Codex 和 Antigravity 各自的来源设置页增加独立的“周额度重置后发送消息”区域。两个来源的配置、启用状态、执行记录互不影响。

| 设置项 | 要求与默认值 |
| --- | --- |
| 启用开关 | 默认关闭。仅在目标工作区、会话和非空消息均有效时允许开启；关闭后取消尚未提交的自动投递。 |
| 工作区 | 用户选择本机绝对路径。显示规范化后的路径；不能仅靠同名目录匹配。 |
| 目标会话 | 从所选来源、账号和工作区的现有会话列表中选择；显示标题辅助识别，保存稳定会话 ID、来源、账号、宿主/实例及工作区身份。标题不能作为投递地址。 |
| 消息内容 | 用户可编辑纯文本，多行可用。默认留空；去除仅由空白组成的内容，其他文字按原样发送。设置页预览实际发送文本。建议沿用现有消息长度上限 2,000 个 UTF-16 单元。 |
| 模型 | 默认“自动选择当前可用的低档模型”；也可选择来源实际支持的具体模型。设置页展示将使用的模型及额度池。 |
| 思考深度 | 默认“所选模型支持的最低档”；也可选择所选模型实际支持的档位。模型变化时重新验证，不静默切换成更高档。 |

选择工作区后刷新该来源的会话列表，并只显示可核对身份的会话。选择会话时显示来源、账号、工作区、会话标题和 ID 的末尾部分，供用户确认。用户更换工作区、账号、Antigravity 配额池或宿主实例时，旧会话绑定须失效；不能以相同标题自动改绑。会话被删除、归档后不可写、或失去访问权限时，暂停自动发送并给出明确状态。再次选择和启用由用户完成。

“发送测试消息”可以作为设置页的显式操作，用当前配置向当前目标发送一次，并清楚标示会消耗额度、会在会话中留下消息。测试发送不占用周重置的自动投递名额；正式自动投递仍需单独开启。测试功能若无法遵循同样的身份、模型和思考档位校验，则不提供按钮。

## 4. 重置事件判定

1. 每个来源按**实际额度身份**维护独立基线：来源、账号、Antigravity 的有效配额池，以及周额度窗口。Antigravity `auto` 池切换到另一实际池时，重新建立该池的基线，不把换池误判为重置。
2. 首次读取、首次启用、升级迁移、账号或配额池切换，只建立基线，不追发过去的重置。之后须有同一身份的有效旧窗口记录，并由**新鲜、成功且时间顺序可信**的配额样本确认进入下一周窗口；旧窗口截止时间已过，且新窗口边界比旧边界晚。单独的本机时钟到点、缓存重复读取、显示层归零、无效时间戳或读取失败均不能触发。
3. 检测到新窗口后，把重置事件和其身份、旧/新边界持久化，再进入发送流程。即使系统通知被关闭，也要处理已启用的发送规则；即使发送失败，也不影响既有通知功能。
4. 睡眠或应用暂时退出后，若保留了可信的旧窗口基线，并在重启后以新鲜样本确认下一个周期，可对**最新的一次**重置投递一次；无法确定跨越了几个周期时不补发多条。用户在事件发生后才启用功能、修改目标或修改消息，不追发该事件。
5. 同一时间出现 5 小时与周额度重置，只由周额度事件触发此功能一次。Antigravity 若同时展示 Gemini 周额度和 Argon WTU 周额度，只对设置时选定的**有效配额池**触发，不因同一底层读数同时向一个会话发送多条。

## 5. 投递与模型选择

- 投递前再次核对：功能仍开启；事件仍属于当前账号/配额池；目标会话仍存在且属于保存的工作区、宿主和账号；消息非空；模型与思考档位仍受支持。任何一项无法确认时停止投递并显示原因，不猜测替代目标。
- Codex 仅向保存的 `threadId` 和对应 `hostId` 发送**一条用户消息**。允许已存在的空闲会话；活动会话必须由官方发送接口明确接受，不能为了投递而批量扫描或向其他活动会话发送。传入明确的模型与思考档位，并核对接口没有忽略或悄悄回退。
- Antigravity 仅在官方 CLI/接口能够证明目标为**同一个现有会话**时，使用所选工作区作为执行目录，指定会话 ID、单次消息、模型及 effort。不能使用“继续最近会话”代替指定 ID，也不能因指定 ID 失效而新建会话。CLI 返回的会话 ID、执行结果和错误状态需被校验；原 Desktop/IDE 会话若只能导入为副本，则保持不可选。
- “低档模型”是按来源当前能力目录选出的低成本/快速档，**不是硬编码某个随版本可能消失的模型名**。最低思考档位以该模型实际支持的档位为准。界面须在启用时和执行记录中展示解析出的具体模型及档位。若默认策略找不到兼容组合，停止发送并提示用户选择；用户显式指定的模型或档位失效时也不自动降级或升级。
- 发送的消息须为用户输入的文字，不把它包装成另一个任务或添加隐藏指令。若目标接口会把消息开头的 `/` 等内容解释为 CLI 命令，投递器必须使用可保证字面发送的方式；否则在设置时明确拒绝该内容。不能为完成投递关闭目标应用的权限保护，也不能绕过目标应用的授权或安全提示。

## 6. 去重、失败与可观察性

持久化执行键至少包含来源、账号、有效配额池和周窗口边界；目标会话 ID 与消息版本作为该事件的配置快照保存，**不参与生成第二次自动投递资格**。因此发送后更换目标也不会在同一周期再次自动发送。发送前先持久化待提交记录；收到明确的“未提交”失败才可在当前周窗口内重试。提交已被接受、或超时/断连导致结果不确定时，均不得自动重发，以免在会话中出现两条 `hi`。重启后继续遵守这项记录。下一周窗口重新获得一次自动投递资格。

设置页显示最近一次重置检测、目标、实际模型/思考档位、投递时间及状态：`待发送`、`已提交`、`执行成功`、`提交失败可重试`、`结果不确定`、`目标失效`。Codex 接口确认接收消息不等于模型完成回复；Antigravity 的 CLI 进程成功也须结合结构化结果判断，不能只看退出码。失败或不确定状态提供用户可见的原因和**手动重试**入口；手动重试明确告知可能重复发送。

记录中不写入消息正文、认证凭据或完整 CLI 原始输出。设置文件保存用户填写的消息，按现有本机设置权限管理；诊断日志仅记录必要的事件键、脱敏目标标识和固定错误码。自动投递在后台执行，不阻塞额度刷新、通知或浮窗操作。

## 7. 验收标准

1. Codex 和 Antigravity 均能分别配置工作区、原会话、消息、模型和思考档位；默认关闭，空消息不能开启，`hi` 在已启用且确认周重置时恰好提交一次。另一个来源的设置和额度事件不触发该来源的消息。
2. 对同一账号和配额池回放旧窗口、新鲜的新窗口、重复样本、陈旧样本、时钟到点、读取失败、重启、睡眠、账号切换及 Antigravity 换池。仅确认的新周窗口触发；每个事件最多自动提交一次，切换身份和首次启用不追发。
3. 用两个同名工作区、两个同名会话、不同账号/宿主以及空闲和活动会话验证目标精确匹配。无法确认原会话时不新建、不导入副本、不改投最近会话；目标失效有清楚的设置状态。
4. 验证默认策略实际使用低档模型的最低支持档位；用户显式选择生效，模型失效、档位不兼容或底层接口忽略参数时停止发送并显示错误。Antigravity 需用真实 `agy` 的结构化回执证明 `--conversation`、工作区、`--model`、`--effort` 组合投到同一原 CLI 会话；Codex 需用真实桌面桥回执证明消息落在目标会话，且模型/思考档位生效。
5. 注入明确的提交前失败、提交后断连、超时和进程崩溃，验证可重试与不确定状态不会造成自动重复发送。关闭开关或更换目标后，尚未提交的旧任务被取消；系统通知开关与发送功能互不控制。

**交付门槛：** 两个来源分别完成真实目标会话的端到端验收后，才在公开版界面标为可用。若 Antigravity 仅证实 CLI 会话可原位续接，则先将可选目标限定为 CLI 会话，并在界面明确说明 Desktop/IDE 会话暂不支持；不得把克隆会话的成功当作原会话投递成功。
